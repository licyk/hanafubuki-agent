所有键使用 camelCase。没有写出的键使用默认值；TOML 没有空值，要让可选键“未设置”，就不要写它。

## config.toml [#config-toml]

这些键可以写在用户的 `config.toml`、配置档 `[profiles.名字]` 和受信任项目的 `.hanafubuki-agent/config.toml` 中，也可以用 `-c` 和 `config set` 设置。见[配置分层](/docs/config-layers)。

### 通用 [#general]

| 键                | 类型和取值                                                   | 默认值     | 含义                                                          |
| ----------------- | ------------------------------------------------------------ | ---------- | ------------------------------------------------------------- |
| `permissionMode`  | `"manual"`、`"auto_review"`、`"full_access"`                 | `"manual"` | [权限模式](/docs/permissions)                                 |
| `disabledPlugins` | 插件名的数组，最多 64 个                                     | `[]`       | 关闭的插件，见下表                                            |
| `logLevel`        | `"off"`、`"error"`、`"warn"`、`"info"`、`"debug"`、`"trace"` | `"info"`   | 日志文件的级别，见[网络与日志](/docs/network-logging#logging) |

`disabledPlugins` 中有意义的插件名：

| 插件                | 关闭后                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------- |
| `execution`         | 不能运行命令（`exec_command`、`write_stdin`、`resize_execution`）                                       |
| `workspace-fs`      | 不能读写文件（`read_file`、`list_directory`、`search_text`、`apply_patch`、`move_path`、`delete_path`） |
| `web`               | 不能搜索和抓取网页（`web_search`、`fetch_web_page`）                                                    |
| `view-image`        | 不能查看图片（`view_image`）                                                                            |
| `mcp`               | 模型看不到 MCP 工具和资源；服务器仍然会连接                                                             |
| `skills`            | 没有 Skill 目录、Skill 工具和 `$名字` 提及                                                              |
| `memory`            | 模型看不到记忆，也没有记忆工具                                                                          |
| `titles`            | 不再用模型为会话生成标题，保留第一条消息开头作为标题；没有标题建议                                      |
| `recap`             | 没有会话概要                                                                                            |
| `goal`              | 没有会话目标：没有目标工具、上下文和继续推进，也没有目标调用；已经设置的目标仍然保存着                  |
| `subagents`         | 没有子代理：模型没有子代理工具和指引；门面的 `subagents` 调用不可用                                     |
| `review`            | 没有评审：评审调用不可用，评审会话既不带评审准则，也不保持只读                                          |
| `worktree`          | 没有工作树（`/worktree`，门面的 `worktree_*` 调用）                                                     |
| `plugins`           | 模型不再被告知已安装的插件，它们的代码停止；它们的 Skill、MCP 服务器和钩子仍然运行，角色也保留          |
| `workspace-context` | 模型看不到 `AGENTS.md`、工作区目录和环境信息                                                            |
| `permission-mode`   | 模型不再被告知当前的权限模式                                                                            |

其他名字会被接受但没有效果。

### 沙箱 [#sandbox]

模型运行的命令能触及什么，见[沙箱](/docs/permissions#sandbox)。

| 键                                    | 类型和取值                                          | 默认值                                                                      | 含义                                                                                                                                                                                                                               |
| ------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sandboxMode`                         | `"read-only"`、`"workspace-write"`、`"full-access"` | 未设置：Linux 和 macOS 上为 `"workspace-write"`，其他平台为 `"full-access"` | 沙箱模式。未设置的模式不会被写入文件，所以会随平台获得沙箱而改变                                                                                                                                                                   |
| `sandboxWorkspaceWrite.writableRoots` | 绝对路径的数组                                      | `[]`                                                                        | workspace-write 模式下命令还可以写入的目录                                                                                                                                                                                         |
| `sandboxWorkspaceWrite.networkAccess` | `true`、`false`                                     | `false`                                                                     | workspace-write 模式下命令能否使用网络                                                                                                                                                                                             |
| `windows.sandbox`                     | `"unelevated"`、`"elevated"`                        | 未设置                                                                      | Windows 的沙箱（[平台](/docs/permissions#sandbox-platforms)）：`"unelevated"` 是受限令牌，限制写入但不限制网络；`"elevated"` 暂不可用。未设置或为 `"elevated"` 时，在 Windows 上完全访问以外的模式会让每个命令失败；其他平台忽略它 |

无法读取的 `sandboxMode` 会被修复为最严格的 `"read-only"`，而不是默认值；含有相对路径的 `writableRoots` 会被整个丢弃；无法读取的 `windows.sandbox` 会被丢弃，这会关闭 Windows 沙箱，于是沙箱中的命令会失败，而不是以更少的限制运行。

### 压缩 [#compaction]

会话上下文增长时如何缩减；何时运行标准压缩、运行哪种压缩由模型策略决定（[上下文窗口与压缩](/docs/providers-models#compaction)）。

| 键                                                  | 类型和取值                                     | 默认值       | 含义                                                                                             |
| --------------------------------------------------- | ---------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------ |
| `compaction.strategy`                               | `"standard"`、`"background"`、`"hierarchical"` | `"standard"` | 压缩策略（见下）                                                                                 |
| `compaction.background.thresholdPercent`            | 整数，1–100                                    | `65`         | 在后台开始压缩的窗口比例；应低于 `autoCompactThresholdPercent`                                   |
| `compaction.background.childSessions`               | 布尔值                                         | `true`       | 子会话（子代理的、评审的）是否也在后台压缩；`false` 时它们用 `"standard"`                        |
| `compaction.hierarchical.maxContextLimitPercent`    | 整数，1–100                                    | `75`         | 超过窗口的这一比例时，立即请模型折叠历史                                                         |
| `compaction.hierarchical.emergencyThresholdPercent` | 整数，1–100                                    | `95`         | 超过窗口的这一比例时，截短过大的工具输出                                                         |
| `compaction.hierarchical.nudgeGrowthTokens`         | 整数                                           | `50000`      | 可折叠片段增长到这么多 token 后才请模型折叠                                                      |
| `compaction.hierarchical.preserveRecentMessages`    | 整数                                           | `3`          | 不参与折叠的最近消息数                                                                           |
| `compaction.hierarchical.preserveRecentTokens`      | 整数                                           | `5000`       | 不参与折叠的最近 token 数                                                                        |
| `compaction.hierarchical.minCompressRangeChars`     | 整数                                           | `5000`       | 值得折叠的最短历史片段，按字符计                                                                 |
| `compaction.hierarchical.minSummaryLength`          | 整数，不超过 `maxSummaryLength`                | `50`         | 模型所写摘要的最短长度，按字符计；更短的会被拒绝                                                 |
| `compaction.hierarchical.maxSummaryLength`          | 整数                                           | `20000`      | 摘要的最长长度；更长的会被拒绝                                                                   |
| `compaction.hierarchical.tiers`                     | 布尔值                                         | `true`       | 是否把较早的摘要分层再次提炼                                                                     |
| `compaction.hierarchical.protectedTools`            | 工具名数组                                     | `[]`         | 结果从不被折叠的工具                                                                             |
| `compaction.hierarchical.messageTimestamps`         | 布尔值                                         | `true`       | 每条消息的标签显示请求首次显示它时的本地时间，折叠的回复显示它覆盖的时间段；`false` 时不显示时间 |
| `compaction.hierarchical.absorb`                    | 布尔值                                         | `false`      | 4 000 个 token 及以上的工具结果要求模型用 `absorb` 提炼它；之后该结果离开请求                    |
| `compaction.hierarchical.contentStore`              | 布尔值                                         | `false`      | 4 000 个 token 及以上的工具结果在到达时被替换为占位符；`acp_retrieve` 返回原文                   |
| `compaction.hierarchical.crush`                     | 布尔值                                         | `false`      | 在要求 `absorb` 之前，确定性地折叠大工具结果中的 JSON、代码和日志；只在 `absorb` 开启时          |
| `compaction.hierarchical.rules`                     | 布尔值                                         | `false`      | 模型用 `acp_rule` 记录持久的提醒，显示在每个请求的指令中                                         |

各策略：

- **`"standard"`** 同步压缩：上下文用到窗口的 `autoCompactThresholdPercent` 时（小窗口为给回复留出空间会更早）在轮次前或轮次中压缩，模型请求新上下文时、Provider 报告上下文窗口错误之后、`/compact` 时也压缩。
- **`"background"`** 还会在上下文用到窗口的 `compaction.background.thresholdPercent`（低于 `autoCompactThresholdPercent`）时于后台开始压缩：会话继续工作的同时，它压缩到当时为止已完成的轮次，结果在下一个请求之前安装，排在之后所做的工作之前。它运行期间，如果因为阈值、上下文窗口错误或 `/compact` 需要压缩，会等待它而不发送自己的请求；结果失败、已不适用或安装后上下文仍超过阈值时，按 `"standard"` 的方式同步压缩。不低于 `autoCompactThresholdPercent` 的值永远不会开始，日志会给出警告。`autoCompactionEnabled = false` 也会关闭它。它的用量计入会话，从不计入轮次的预算。
- **`"hierarchical"`** 让模型把自己的历史折叠成它写的摘要（源自 [billion-context](https://github.com/ranxianglei/billion-context)）。保存的历史从不改变：每个请求把折叠的片段显示为它们的摘要。模型得到一段常驻提示、五个工具（`compress`、`decompress`、`search_context`、`acp_status`、`acp_cache`），以及上下文变满时折叠的提醒（见 `maxContextLimitPercent`、`emergencyThresholdPercent` 和 `nudgeGrowthTokens` 三行）；超过 `emergencyThresholdPercent` 时还会截短过大的工具输出。没有阈值压缩，也不使用 `autoCompactThresholdPercent`。标准压缩在上下文窗口错误之后、`/compact` 和请求新上下文时运行，以及上下文连续三个请求超过 `emergencyThresholdPercent` 且已没有可折叠或可截短的内容时运行；`autoCompactionEnabled = false` 关闭其中两种自动的：错误之后的（与其他策略相同）和超过 `emergencyThresholdPercent` 的。上下文窗口未知时，既不提醒也不截短。它的表中每个键都生效。开启 `messageTimestamps` 时，每条消息的标签带有请求首次显示它时的本地时间（`time="2026-11-09 09:00:00"`，显示后不再改变，所以请求的缓存前缀不受影响），折叠的回复写明它覆盖的时间段；开启之前已显示过的消息没有时间。模型的折叠在终端界面中显示为折叠的 `compress` 调用，`/compression` 显示各个块及其节省的量（[分层压缩](/docs/terminal-interface#compression)）。可选功能在此之上加入内容，每个功能的工具只在它开启时提供：`absorb`（工具 `absorb`；`crush` 先折叠它能折叠的）、`contentStore`（工具 `acp_retrieve`，它把原文内联返回，或者从 4 000 个 token 起写入会话的导出文件并给出路径；原文保存在会话的一个文件中，随会话删除）和 `rules`（工具 `acp_rule`）。四项都关闭时，请求与没有它们时相同。从它切换走的会话继续把已折叠的内容显示为摘要，直到下一次标准压缩。

每种策略都以标准压缩为底线：`/compact`、模型请求新上下文、上下文窗口错误之后的重试总是运行它。策略按会话生效：新会话采用它，已有会话在下一轮次或 `/compact` 时采用，子会话（子代理的、评审的）同样采用，但 `"background"` 且 `childSessions = false` 时子会话用 `"standard"`；旁支对话（`/side`）总是用 `"standard"`。终端界面的 `/config` 可以选择它。无法使用的值取默认值；`minSummaryLength` 大于 `maxSummaryLength` 时两者都回到默认值。

### 模型元数据 [#model-metadata]

| 键                        | 类型和取值        | 默认值   | 含义                                                                                   |
| ------------------------- | ----------------- | -------- | -------------------------------------------------------------------------------------- |
| `modelMetadata.discovery` | `"auto"`、`"off"` | `"auto"` | Agent 是否自己在后台列出各 Provider 的模型，以得知每个模型报告的信息（它的上下文窗口） |

为 `"auto"` 时，Agent 启动时列出默认 Provider 的模型；此后每当在某个 Provider 上创建会话、选用它的模型或在它上面运行轮次时，列出该 Provider 的模型：每个 Provider 每天最多一次，列出失败后每 15 分钟最多一次。会话在下一个轮次采用得知的信息（[上下文窗口与压缩](/docs/providers-models#compaction)）。没有什么会等待列表；失败的列出只是稍后再试。`"off"` 时 Agent 不自己列出；`/model` 和 `/providers` 的模型列表、Provider 的测试和 `doctor --online` 仍会列出，它们报告的信息也仍会保存。嵌入 Agent 的应用用同样的方式关闭它，写在它的 Agent 配置的 `config.toml` 里。

### 终端界面 [#tui]

| 键                         | 类型和取值                                     | 默认值                                                     | 含义                                                                                                                                                          |
| -------------------------- | ---------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tui.fullscreenTranscript` | 布尔值                                         | `true`                                                     | [终端界面](/docs/terminal-interface#modes)在备用屏幕上自己绘制对话（Fullscreen）；`false` 时对话写入终端的滚动历史（Scrollback）。启动时读取，`/tui` 会设置它 |
| `tui.alternateScreen`      | `"auto"`、`"always"`、`"never"`                | `"auto"`                                                   | 界面是否可以使用备用屏幕；`"auto"` 在 SSH 会话中不使用。不能使用备用屏幕时，界面以 Scrollback 方式运行                                                        |
| `tui.rawOutput`            | 布尔值                                         | `false`                                                    | 以对话内容的原始纯文本显示，便于用终端自己的选择复制；`/raw` 会设置它                                                                                         |
| `tui.theme`                | 字符串                                         | 未设置                                                     | [语法高亮](/docs/terminal-interface#highlighting)主题：内置主题的名字，或数据目录 `themes/` 下自定义的 `名字.tmTheme`；未设置时是 `ansi`。`/theme` 会设置它   |
| `tui.statusLine`           | 项目 ID 数组                                   | `["model-with-reasoning", "current-dir", "session-title"]` | [状态栏](/docs/terminal-interface#status-line)的项目及顺序；`[]` 表示不显示（底栏显示 `? for shortcuts`）。`/statusline` 会设置它                             |
| `tui.statusLineColors`     | 布尔值                                         | `true`                                                     | 状态栏的项目是否使用主题的颜色                                                                                                                                |
| `tui.terminalTitle`        | 项目 ID 数组                                   | `["activity", "session-title", "project-name"]`            | [终端标题](/docs/terminal-interface#status-line)的项目及顺序；`[]` 表示不修改终端标题。`/title` 会设置它                                                      |
| `tui.keymap.上下文.动作`   | 按键字符串或其数组                             | 各动作的默认按键                                           | 界面某个动作的按键（[按键映射](/docs/terminal-interface#keymap)）：`"ctrl-t"`、`"ctrl-x ctrl-s"`、`"leader p"`；`[]` 取消绑定。`/keymap` 会设置它             |
| `tui.presets.N`            | 表：`input`（字符串）、`label`（字符串，可选） | 无                                                         | `N` 号位置（`"0"` 到 `"9"`）的[预设](/docs/terminal-interface#presets)：像输入一样运行的内容，不能为空，最多 8000 字节，不能以 `!` 开头。`/presets` 会设置它  |

`[tui]` 下的其他键保留在文件中，但会被忽略；`statusLine` 和 `terminalTitle` 中的项目，以及按键映射的上下文、动作和按键，界面不认识或无法使用的也会被忽略，每个都产生一条[警告](/docs/terminal-interface#warnings)。配置档、项目配置或 `-c` 中的按键映射项或预设只替换用户文件中同一个动作或位置的设置，其他的保持不变。`config set` 只能以表的形式写入 `tui.keymap` 和 `tui.presets`，并与文件合并（`config set tui.keymap '{ global = { open_transcript = "ctrl-g" } }'`），不能写入它们下面的某个键。

`logLevel`、`network.proxy` 和 `[tui]` 只对独立运行的 Agent 有效；嵌入 Agent 的应用提供自己的日志、代理和界面。

### 钩子 [#hooks]

| 键                   | 类型和取值                                                                                            | 含义                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `hooks.事件`         | matcher 组的数组，`[[hooks.PreToolUse]]`                                                              | `事件` 的钩子：`PreToolUse`、`PostToolUse`、`SessionStart`、`UserPromptSubmit` 或 `Stop` |
| `hooks.事件.matcher` | 字符串；默认为空或 `*`                                                                                | 组内钩子针对的工具名（或会话开始的来源）                                                 |
| `hooks.事件.hooks`   | 钩子数组：`type = "command"`、`command`，以及 `commandWindows`、`timeout`（秒，600）、`statusMessage` | 要运行的命令                                                                             |

用户的文件和被读取的项目文件都可以有它们，各自旁边的 `hooks.json` 也可以。它们不是设置：`config get` 和 `config set` 不处理它们，钩子的信任与启用状态也不是 `config.toml` 的键（见[钩子](/docs/configuration#hooks)）。

### 插件 [#plugins]

按插件 id（`<插件>@<市场>`）设置哪些[已安装的插件](/docs/architecture#installed-plugins)启用。这些表来自 Codex，键名用 camelCase。

| 键                                                  | 类型和取值        | 默认值 | 含义                                                                                             |
| --------------------------------------------------- | ----------------- | ------ | ------------------------------------------------------------------------------------------------ |
| `plugins._default.enabled`                          | `true` 或 `false` | 无     | 自身条目没有说明的包是否启用                                                                     |
| `plugins."插件@市场".enabled`                       | `true` 或 `false` | 无     | 这个包是否启用                                                                                   |
| `plugins."插件@市场".mcpServers.名字.enabled`       | `true` 或 `false` | `true` | 这个包的 MCP 服务器 `名字` 是否运行                                                              |
| `plugins."插件@市场".mcpServers.名字.enabledTools`  | 工具名数组        | 全部   | 只提供该服务器的这些工具                                                                         |
| `plugins."插件@市场".mcpServers.名字.disabledTools` | 工具名数组        | 无     | 在 `enabledTools` 之后，不提供该服务器的这些工具                                                 |
| `plugins."插件@市场".settings`                      | 表                | 无     | 包的代码的设置，按其清单的 `configSchema` 描述：它的访客的配置（`plugins settings`、`/plugins`） |

已安装的包默认启用，除非：它的市场被关闭（见下文），或它的条目写了 `enabled = false`，或它的条目没有说明而 `_default.enabled` 为 `false`。键不是插件 id 的条目保留在文件中，但和未知键一样被忽略。包的 MCP 服务器如何运行由包决定，`mcpServers` 只做限制（[插件的服务器](/docs/mcp#plugin-servers)）。Agent 写入的更改立即生效：它在每次写入设置之后重新加载包；手动编辑在下次启动时生效。`plugins add`（以及 `/plugins` 中的安装）写入 `enabled = true`，`plugins enable` 和 `disable` 只写 `enabled`，`plugins remove` 删除该条目（[plugins](/docs/cli-reference#plugins)）。`settings` 由 `set_package_settings`（以及 `/plugins` 中代码插件页面的 **Settings** 行，或它的选项表单 `o`）整体替换，它按清单的 `configSchema` 及其降低成的选项校验，并以新设置重启访客；不是表的值会被修复。访客把它作为自己的配置和 `settings` 视图读取（[代码插件](/docs/plugin-rules#guest-host-calls)），读取包时按这些选项检查：不符合其选项的键取选项的默认值，模式没有给出默认值时则被省略，同时产生包的问题和一条日志警告；越界的整数或数字被截取到边界。文件不会因此被改写（[configSchema](/docs/writing-plugins#config-schema)）。

### 市场 [#marketplaces]

按名字列出你添加的市场：Agent 从这里找到它们的包。

| 键                               | 类型和取值                | 含义                                                 |
| -------------------------------- | ------------------------- | ---------------------------------------------------- |
| `marketplaces.名字.sourceType`   | `"git"` 或 `"local"`      | 来源类型；必填                                       |
| `marketplaces.名字.source`       | 字符串                    | git URL，或本地市场的目录；必填                      |
| `marketplaces.名字.ref`          | 字符串                    | git 市场检出的分支、标签或提交                       |
| `marketplaces.名字.sparsePaths`  | 路径数组                  | git 市场只检出这些路径                               |
| `marketplaces.名字.lastUpdated`  | RFC 3339 时间             | 最近一次添加或升级的时间                             |
| `marketplaces.名字.lastRevision` | git 修订                  | 检出的修订                                           |
| `marketplaces.名字.enabled`      | `true` 或 `false`；`true` | 为 `false` 时关闭它的所有包，不管 `[plugins]` 怎么写 |

`plugins marketplace add`、`upgrade` 和 `remove` 写入这些条目（[plugins](/docs/cli-reference#plugins)）。git 市场检出在数据目录的 `plugins/marketplaces/名字/` 中；本地市场在原处读取。没有可用的 `sourceType` 和 `source` 的条目保留在文件中，但被忽略。两个表可以写在任何一层，`config get` 和 `config set` 能处理它们的键（`config set plugins."demo@my-mkt".enabled false`）；`-c` 覆盖不能给键加引号，所以只能指定名字中没有点的包（`-c plugins.demo@my-mkt.enabled=false`）。

### 插件选项 [#plugin-options]

编译进 Agent 的插件（以及宿主的插件）的选项，按插件名、再按选项：`[pluginOptions.名字]`。插件的描述符说明它接受哪些选项，以及它们的种类、界限和默认值；`/plugins` 和 `/config plugins` 用表单显示它们。

| 键                                             | 类型和取值      | 默认值 | 含义                                                       |
| ---------------------------------------------- | --------------- | ------ | ---------------------------------------------------------- |
| `pluginOptions.subagents.maximumRunningAgents` | 整数，1 到 16   | `3`    | 一个对话的子代理同时最多有几个在运行轮次                   |
| `pluginOptions.subagents.defaultWaitSeconds`   | 整数，10 到 300 | `30`   | 模型没有给出超时时 `wait_agent` 等多久，取到最短与最长之间 |
| `pluginOptions.subagents.minimumWaitSeconds`   | 整数，10 到 300 | `10`   | `wait_agent` 接受的最短超时；高于最长超时时取为最长超时    |
| `pluginOptions.subagents.maximumWaitSeconds`   | 整数，10 到 300 | `300`  | `wait_agent` 接受的最长超时                                |

```toml
[pluginOptions.subagents]
maximumRunningAgents = 4
defaultWaitSeconds = 60
```

这个表按插件和键跨层合并，就像 `[plugins]` 按条目合并：某层设置的键替换下层的，其余键保留。每个键单独读取：类型不对的值，或不合适的文本，取选项的默认值；越界的整数被截取到边界；两者都会产生一条警告，指明层、插件和键（`/warnings`，以及 `/plugins` 中该插件的选项）。插件不接受的键保留在文件中但被忽略，并有一条警告；插件没有选项的表没有意义，就像 `disabledPlugins` 中的未知名字。写入是严格的：`config set pluginOptions.名字.键 值`、选项表单和 `set_plugin_options` 按插件的选项检查每个值，在写入任何内容之前带着原因拒绝不合适的值；`config get pluginOptions.名字.键` 打印各层解析出的值，没有设置时打印默认值。配置档或项目的 `pluginOptions` 需要手动编写。Agent 写入的更改立即生效：`subagents` 就地接受新的运行中代理上限，对新的等待界限则重新启动，它运行的子代理继续运行。`web` 插件的设置仍是上面的 `webSearchProvider`、`searxngBaseUrl` 和 `webFetchUseJinaReader`，网络表单也使用它们。

### 角色 [#agents]

某一层定义的[角色](/docs/roles)，按名字：`[agents.名字]`，键与角色文件相同（[键](/docs/roles#keys)）。

| 键                       | 类型和取值                     | 含义                                                                                             |
| ------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------------ |
| `agents.名字`            | 角色的键组成的表               | 角色 `名字`                                                                                      |
| `agents.名字.configFile` | 路径，相对于本文件所在的文件夹 | 一个角色文件，条目的键覆盖在它的键之上读取（Codex 的 `config_file`）；`agents/` 不会再读这个文件 |
| `profiles.配置档.agents` | 角色组成的表，同 `agents`      | 配置档 `配置档` 的角色                                                                           |

用户的文件、其中的配置档以及受信任项目的文件都可以写。它们不跨层合并：较高层的角色整体替换下一层的同名角色（[角色的来源](/docs/roles#sources)）。它们不是设置：`config get` 和 `config set` 不处理它们，`-c agents.…` 覆盖是未知的键，其中无法使用的内容是角色的问题（`roles list`、`doctor`、`/warnings`），从不会修复文件。

## providers.toml [#providers-toml]

`providers.toml` 没有分层，只有自己可读。通常用 `providers` 命令修改；终端界面的 `/providers` 可以编辑 Provider，按 `p` 或 `/providers policy` 可以编辑共享的模型策略；也可以直接编辑文件。修改时请先退出正在运行的 Agent。

```toml
revision = 2
defaultProviderId = "provider-1"

[modelPolicy]
model = "gpt-5.1"
reasoningEffort = "medium"
autoCompactionEnabled = true
autoCompactThresholdPercent = 80
remoteCompaction = "disabled"

[modelPolicy.inputCapabilities]
imageInput = "auto"

[[providers]]
id = "provider-1"
displayName = "OpenAI"
enabled = true
protocol = "responses"
baseUrl = "https://api.openai.com/v1"
apiToken = "sk-..."
requestHeaders = []
```

### 顶层 [#providers-top]

| 键                  | 类型         | 含义                                           |
| ------------------- | ------------ | ---------------------------------------------- |
| `revision`          | 整数         | 每次修改加一，由 Agent 维护                    |
| `defaultProviderId` | 字符串，可选 | 默认 Provider 的 ID，必须是一个启用的 Provider |

### [modelPolicy] [#model-policy]

模型策略对所有 Provider 生效。

| 键                             | 类型和取值                                                                     | 默认值       | 含义                                                                                                                                                                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`                        | 字符串，最多 256 字节                                                          | `""`         | 新会话使用的模型                                                                                                                                                                                                                                          |
| `reasoningEffort`              | `"minimal"`、`"low"`、`"medium"`、`"high"`、`"xhigh"` 或其他 1–64 个字符的标识 | 未设置       | 推理强度，只对 Responses 协议有效                                                                                                                                                                                                                         |
| `inputCapabilities.imageInput` | `"auto"`、`"disabled"`                                                         | `"auto"`     | 是否向模型发送图片                                                                                                                                                                                                                                        |
| `contextWindowTokens`          | 正整数                                                                         | 未设置       | 模型的上下文窗口；未设置时取从 Provider 对过长请求的拒绝中学到的更小窗口、Provider 的模型列表报告的值（除非 `modelMetadata.discovery = "off"`，否则[自动列出](#model-metadata)），或内置表中的值（[上下文窗口与压缩](/docs/providers-models#compaction)） |
| `autoCompactionEnabled`        | 布尔值                                                                         | `true`       | 是否自动压缩上下文                                                                                                                                                                                                                                        |
| `autoCompactThresholdPercent`  | 整数，1–100                                                                    | `80`         | 上下文用到窗口的这个百分比时自动压缩；剩下的部分容不下一次回复时更早（[上下文窗口与压缩](/docs/providers-models#compaction)）                                                                                                                             |
| `remoteCompaction`             | `"disabled"`、`"responses_compact"`、`"responses_compact_v2"`                  | `"disabled"` | 用 Responses 的远程压缩代替本地摘要                                                                                                                                                                                                                       |
| `turnBudget`                   | 表                                                                             | 未设置       | 回合的限制，见下文                                                                                                                                                                                                                                        |

`[modelPolicy.turnBudget]` 是可选的；写出时必须包含全部 11 个键，每个都是正整数：

| 键                                   | 默认值  | 上限      | 含义                         |
| ------------------------------------ | ------- | --------- | ---------------------------- |
| `maximumCumulativeModelInputTokens`  | 8000000 | 100000000 | 一个回合累计的输入 token     |
| `maximumCumulativeModelOutputTokens` | 1000000 | 10000000  | 一个回合累计的输出 token     |
| `maximumToolInvocations`             | 256     | 10000     | 一个回合的工具调用次数       |
| `maximumToolOutputBytes`             | 16 MiB  | 256 MiB   | 一个回合的工具输出总字节数   |
| `maximumHookFragmentBytes`           | 1 MiB   | 16 MiB    | 插件钩子注入的内容字节数     |
| `maximumPendingInputItems`           | 64      | 1024      | 等待处理的补充消息数         |
| `maximumInFlightTools`               | 8       | 64        | 同时运行的工具调用数         |
| `maximumConsecutiveStalledSteps`     | 4       | 32        | 连续没有进展的步骤数         |
| `modelStreamIdleTimeoutSeconds`      | 120     | 86400     | 模型响应流多久没有数据算超时 |
| `toolIdleTimeoutSeconds`             | 600     | 86400     | 工具多久没有进展算超时       |
| `approvalTimeoutSeconds`             | 900     | 86400     | 审批最长等待时间             |

### [[providers]] [#providers]

最多 32 个。

| 键               | 类型和取值                                                  | 含义                                                                                                                               |
| ---------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | 1–64 个字母、数字、`_` 或 `-`                               | Provider 的 ID；`providers add` 分配最小的空闲 `provider-N`                                                                        |
| `displayName`    | 1–128 字节                                                  | 显示名称                                                                                                                           |
| `enabled`        | 布尔值                                                      | 是否启用                                                                                                                           |
| `protocol`       | `"responses"`、`"chat_completions"`、`"anthropic_messages"` | 协议，见 [Provider 与模型](/docs/providers-models#protocols)                                                                       |
| `baseUrl`        | `http` 或 `https` URL，不含凭据和片段                       | 接口地址，协议的路径追加在它后面                                                                                                   |
| `apiToken`       | 字符串，可选                                                | API 令牌，原样保存                                                                                                                 |
| `requestHeaders` | `{ name, value }` 的数组，最多 32 个                        | 附加到每个请求的请求头；不能设置 `Authorization`、`x-api-key`、`anthropic-version`、`Host`、`Content-Type` 等由 Agent 管理的请求头 |

默认 Provider 被删除或禁用时，默认改为列表中第一个启用的 Provider。

## mcp.toml [#mcp-toml]

`mcp.toml` 没有分层，只有自己可读。`mcp add` 写入新服务器的默认值；终端界面的 `/mcp` 可以编辑服务器、凭据、协议模式和按工具的策略，也可以直接编辑文件。

```toml
revision = 3

[[servers]]
id = "github"
enabled = true
required = false
protocolMode = "legacy"
connectTimeoutSeconds = 15
initializeTimeoutSeconds = 30
listTimeoutSeconds = 30
callTimeoutSeconds = 120
shutdownTimeoutSeconds = 10
maximumConcurrentCalls = 4
enabledTools = []
disabledTools = []
approvalPolicy = "ask"
exposurePolicy = "deferred"

[servers.transport]
type = "stdio"
program = "github-mcp-server"
argv = ["stdio"]

[servers.transport.publicEnvironment]
GITHUB_TOOLSETS = "repos,issues"

[servers.transport.credentialEnvironment]
GITHUB_PERSONAL_ACCESS_TOKEN = "github-token"

[servers.toolApprovalPolicies]
get_issue = "allow"

[credentials.github-token]
value = "ghp_..."
generation = 1
```

### [[servers]] [#servers]

最多 64 个。

| 键                           | 类型和取值                                                  | 默认值       | 含义                                               |
| ---------------------------- | ----------------------------------------------------------- | ------------ | -------------------------------------------------- |
| `id`                         | 1–128 个字母、数字、`-`、`_`、`.`                           |              | 服务器 ID；ID 不符合要求的服务器会被丢弃           |
| `enabled`                    | 布尔值                                                      | `true`       | 是否启用；启用的服务器在 Agent 启动时连接          |
| `required`                   | 布尔值                                                      | `false`      | 必需的服务器：它的工具无法使用时，这一步失败       |
| `protocolMode`               | `"legacy"`、`"v20260728"`                                   | `"legacy"`   | MCP 协议版本                                       |
| `transport`                  | 表，见下文                                                  |              | 传输方式                                           |
| `connectTimeoutSeconds`      | 1–86400                                                     | `15`         | 连接超时                                           |
| `initializeTimeoutSeconds`   | 1–86400                                                     | `30`         | 初始化超时                                         |
| `listTimeoutSeconds`         | 1–86400                                                     | `30`         | 列出工具的超时                                     |
| `callTimeoutSeconds`         | 1–86400                                                     | `120`        | 工具调用超时                                       |
| `shutdownTimeoutSeconds`     | 1–86400                                                     | `10`         | 关闭超时                                           |
| `maximumConcurrentCalls`     | 1–64                                                        | `4`          | 同时进行的调用数                                   |
| `toolMaximumConcurrentCalls` | 工具名到 1–64 的表                                          | `{}`         | 单个工具的并发上限                                 |
| `enabledTools`               | 工具名的数组                                                | `[]`         | 只开放这些工具；空数组表示全部                     |
| `disabledTools`              | 工具名的数组                                                | `[]`         | 不开放这些工具                                     |
| `approvalPolicy`             | `"allow"`、`"ask"`、`"deny"`                                | `"ask"`      | 工具调用是否需要审批，见 [MCP](/docs/mcp#policies) |
| `toolApprovalPolicies`       | 工具名到审批策略的表                                        | `{}`         | 单个工具的审批策略                                 |
| `exposurePolicy`             | `"direct"`、`"direct_model_only"`、`"deferred"`、`"hidden"` | `"deferred"` | 工具如何提供给模型                                 |
| `toolExposurePolicies`       | 工具名到暴露策略的表                                        | `{}`         | 单个工具的暴露策略                                 |

数值超出范围时会被调整到范围内。

`transport` 的 `type = "stdio"`：

| 键                      | 含义                                                |
| ----------------------- | --------------------------------------------------- |
| `program`               | 程序：绝对路径，或在 `PATH` 中查找的程序名          |
| `argv`                  | 参数数组                                            |
| `cwd`                   | 工作目录，可选                                      |
| `publicEnvironment`     | 环境变量名到值的表                                  |
| `credentialEnvironment` | 环境变量名到凭据键的表，值从 `[credentials]` 中读取 |

`transport` 的 `type = "streamable_http"`：

| 键                  | 含义                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------- |
| `url`               | `http` 或 `https` URL                                                                   |
| `publicHeaders`     | 请求头名到值的表                                                                        |
| `credentialHeaders` | 请求头名到凭据键的表，值从 `[credentials]` 中读取                                       |
| `oauth`             | `"disabled"`（默认）、`"optional"`、`"required"`；不能和 `Authorization` 请求头同时使用 |

### [credentials] [#credentials]

| 键                          | 含义                                        |
| --------------------------- | ------------------------------------------- |
| `credentials.键.value`      | 凭据的值，原样保存                          |
| `credentials.键.generation` | 正整数，修改值时加一，让 Agent 知道凭据变了 |

凭据键由 1–128 个字母、数字、`.`、`_`、`-` 组成。服务器引用了不存在的凭据时无法连接。
