Every key is camelCase. A key that is not written takes its default (in an MCP server of `mcp.toml`, a new server's value: [below](#servers)); TOML has no null, so to leave an optional key unset, leave it out.

## config.toml [#config-toml]

These keys go in the user's `config.toml`, in a profile `[profiles.NAME]` and in a trusted project's `.hanafubuki-agent/config.toml`, and can be set with `-c` and `config set`. See [Configuration layers](/docs/config-layers).

### Sandbox [#sandbox]

What the commands the model runs can reach; see [The sandbox](/docs/permissions#sandbox).

| Key                                   | Type and values                                     | Default                                                                  | Means                                                                                                                                                                                                                                                                                                         |
| ------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sandboxMode`                         | `"read-only"`, `"workspace-write"`, `"full-access"` | unset: `"workspace-write"` on Linux and macOS, `"full-access"` elsewhere | The sandbox mode. An unset mode is never written, so it follows the platforms that gain a sandbox                                                                                                                                                                                                             |
| `sandboxWorkspaceWrite.writableRoots` | An array of absolute paths                          | `[]`                                                                     | More directories workspace-write lets commands write in                                                                                                                                                                                                                                                       |
| `sandboxWorkspaceWrite.networkAccess` | `true`, `false`                                     | `false`                                                                  | Whether workspace-write lets commands use the network                                                                                                                                                                                                                                                         |
| `windows.sandbox`                     | `"unelevated"`, `"elevated"`                        | unset                                                                    | The Windows sandbox ([Platforms](/docs/permissions#sandbox-platforms)): `"unelevated"` is the restricted token, which confines writes but not the network; `"elevated"` is not available yet. Unset, or `"elevated"`, a mode other than full access fails every command on Windows; other platforms ignore it |

A `sandboxMode` that cannot be read is repaired to `"read-only"`, the most restrictive, rather than to the default; a `writableRoots` holding a relative path is dropped whole; a `windows.sandbox` that cannot be read is dropped, which turns the Windows sandbox off, so sandboxed commands fail rather than run with less.

### Compaction [#compaction]

How a session's context is reduced when it grows; the model policy decides when the standard compaction runs and what it runs ([The context window and compaction](/docs/providers-models#compaction)).

| Key                                                 | Type and values                                | Default      | Means                                                                                                                           |
| --------------------------------------------------- | ---------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `compaction.strategy`                               | `"standard"`, `"background"`, `"hierarchical"` | `"standard"` | The compaction strategy (below)                                                                                                 |
| `compaction.background.thresholdPercent`            | integer, 1–100                                 | `65`         | The share of the window that starts a compaction in the background; below `autoCompactThresholdPercent`                         |
| `compaction.background.childSessions`               | boolean                                        | `true`       | Whether child sessions (sub-agents', reviews') compact in the background too; `false` gives them `"standard"`                   |
| `compaction.hierarchical.maxContextLimitPercent`    | integer, 1–100                                 | `75`         | Past this share of the window, the model is asked to fold its history at once                                                   |
| `compaction.hierarchical.emergencyThresholdPercent` | integer, 1–100                                 | `95`         | Past this share of the window, oversized tool outputs are cut                                                                   |
| `compaction.hierarchical.nudgeGrowthTokens`         | integer                                        | `50000`      | The model is asked to fold only once a foldable stretch has grown by this many tokens                                           |
| `compaction.hierarchical.preserveRecentMessages`    | integer                                        | `3`          | The latest messages are kept out of folds                                                                                       |
| `compaction.hierarchical.preserveRecentTokens`      | integer                                        | `5000`       | The latest tokens are kept out of folds                                                                                         |
| `compaction.hierarchical.minCompressRangeChars`     | integer                                        | `5000`       | The smallest stretch of history worth folding, in characters                                                                    |
| `compaction.hierarchical.minSummaryLength`          | integer, at most `maxSummaryLength`            | `50`         | The shortest summary the model may write, in characters; a shorter one is refused                                               |
| `compaction.hierarchical.maxSummaryLength`          | integer                                        | `20000`      | The longest one; a longer one is refused                                                                                        |
| `compaction.hierarchical.tiers`                     | boolean                                        | `true`       | Whether older summaries are distilled again, in tiers                                                                           |
| `compaction.hierarchical.protectedTools`            | array of tool names                            | `[]`         | Tools whose results are never folded                                                                                            |
| `compaction.hierarchical.messageTimestamps`         | boolean                                        | `true`       | Each message's tag shows the local time a request first showed it, and a fold's reply the span it covers; `false` shows no time |
| `compaction.hierarchical.absorb`                    | boolean                                        | `false`      | A tool result of 4 000 tokens or more asks the model to distil it with `absorb`; the result then leaves the requests            |
| `compaction.hierarchical.contentStore`              | boolean                                        | `false`      | A tool result of 4 000 tokens or more is replaced, as it arrives, by a placeholder; `acp_retrieve` returns the original         |
| `compaction.hierarchical.crush`                     | boolean                                        | `false`      | JSON, code and logs in large tool results are folded deterministically before `absorb` is asked for; only with `absorb`         |
| `compaction.hierarchical.rules`                     | boolean                                        | `false`      | The model records lasting reminders with `acp_rule`, shown in the instructions of every request                                 |

The strategies:

- **`"standard"`** compacts in line: before a turn or during one once the context uses `autoCompactThresholdPercent` of the window (sooner on a small one, keeping room for a reply), when the model asks for a new context, after a Provider's context-window error, and on `/compact`.
- **`"background"`** also starts a compaction in the background once the context uses `compaction.background.thresholdPercent` of the window, below `autoCompactThresholdPercent`: it compacts the turns completed so far while the session goes on, and its result is installed before the next request, ahead of the work done since. When a compaction is needed at the threshold, after a context-window error or on `/compact` while one runs, it waits for it rather than sending its own; if the result failed, no longer fits or leaves the context over the threshold, it compacts in line as `"standard"` does. A value at or above `autoCompactThresholdPercent` never starts one, and the log warns of it. `autoCompactionEnabled = false` turns it off too. Its usage counts toward the session's, never toward a turn's budget.
- **`"hierarchical"`** has the model fold its own history into summaries it writes (after [billion-context](https://github.com/ranxianglei/billion-context)). The stored history is never changed: each request shows the folded stretches as their summaries. The model gets a standing prompt, five tools (`compress`, `decompress`, `search_context`, `acp_status`, `acp_cache`) and, as the context fills, a reminder to fold (the `maxContextLimitPercent`, `emergencyThresholdPercent` and `nudgeGrowthTokens` rows); past `emergencyThresholdPercent` oversized tool outputs are cut too. There is no threshold compaction and `autoCompactThresholdPercent` is not used. The standard compaction runs after a context-window error, on `/compact` and a new context, and once the context has stayed over `emergencyThresholdPercent` for three requests with nothing left to fold or cut; `autoCompactionEnabled = false` turns off the two automatic ones, after an error (as under every strategy) and over `emergencyThresholdPercent`. Without a known context window nothing reminds or cuts. Every key of its table acts. With `messageTimestamps`, each message's tag carries the local time a request first showed it (`time="2026-11-09 09:00:00"`, fixed once shown, so the requests' cached prefix holds), and the reply to a fold names the span of time it covered; a message shown before it was turned on keeps no time. The model's folds show in the terminal interface as folded `compress` calls, and `/compression` shows the blocks and their savings ([Hierarchical compression](/docs/terminal-interface#compression)). The optional features add to it, each with its tool offered only while it is on: `absorb` (the tool `absorb`; `crush` folds what it can first), `contentStore` (the tool `acp_retrieve`, which returns an original inline or, from 4 000 tokens on, writes it to an export file of the session and names the path; the originals are kept in a file of the session, deleted with it) and `rules` (the tool `acp_rule`). With all four off, a request is what it was without them. A session switched away from it keeps showing what was folded, as summaries, until its next standard compaction.

Every strategy keeps the standard compaction as its floor: `/compact`, the model's request for a new context and the retry after a context-window error always run it. The strategy is taken per session: a new session takes it, an existing one at its next turn or `/compact`, and a child session (a sub-agent's, a review's) as well, except that `"background"` with `childSessions = false` gives it `"standard"`; a side conversation (`/side`) always runs `"standard"`. `/config` in the terminal interface chooses it. A value that cannot be used takes its default, and `minSummaryLength` above `maxSummaryLength` takes both from the layer below (in the user's file, their defaults).

### Model metadata [#model-metadata]

| Key                       | Type and values   | Default  | Means                                                                                                                                                                                                                                                             |
| ------------------------- | ----------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `modelMetadata.discovery` | `"auto"`, `"off"` | `"auto"` | Whether the Agent lists its Providers' models by itself, in the background, to learn what each reports (its context window)                                                                                                                                       |
| `modelMetadata.modelsDev` | `true`, `false`   | `false`  | Whether the Agent downloads the public catalogue of [models.dev](https://models.dev) to fill what nothing else says of a model ([models.dev](/docs/providers-models#models-dev)). On, this machine sends a request to models.dev, a third party, about once a day |

With `"auto"` the Agent lists the default Provider's models when it starts, and a Provider's whenever a session is created on it, given one of its models or runs a turn on it: at most once a day per Provider, and once every 15 minutes after a listing that failed. A session takes the window a listing reports as soon as it is recorded, and the rest of what was learned at its next turn ([The context window and compaction](/docs/providers-models#compaction)). Nothing waits for a listing, and one that fails is only tried again later. `"off"` lists nothing by itself; the model list of `/model` and `/providers`, a Provider's test and `doctor --online` still list, and what they report is still kept. An application that embeds the Agent turns it off the same way, in its Agent configuration's `config.toml`.

`modelsDev` is off unless you turn it on. On, the Agent downloads `https://models.dev/api.json` in the background (at start and when a session is bound to a Provider, as discovery does, whatever `discovery` says), with a User-Agent naming the Agent and its version and nothing of you, at most once a day after a download and every 15 minutes after a failed one. The copy is kept in the data directory's `model-metadata.json` and used for a week; models.dev unreachable or answering something unusable is silent, and the copy kept goes on being used. Turned off, the copy is dropped. `/config modelMetadata` in the terminal interface edits both keys.

### Plugins [#plugins]

Which [installed plugins](/docs/architecture#installed-plugins) are on, by plugin id (`<plugin>@<marketplace>`). The tables are Codex's, with camelCase keys.

| Key                                                          | Type and values        | Default       | Means                                                                                                                                                                               |
| ------------------------------------------------------------ | ---------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugins._default.enabled`                                   | `true` or `false`      | none          | Whether a package whose own entry does not say is on                                                                                                                                |
| `plugins."PLUGIN@MARKETPLACE".enabled`                       | `true` or `false`      | none          | Whether the package is on                                                                                                                                                           |
| `plugins."PLUGIN@MARKETPLACE".mcpServers.NAME.enabled`       | `true` or `false`      | the package's | Whether the package's MCP server `NAME` runs                                                                                                                                        |
| `plugins."PLUGIN@MARKETPLACE".mcpServers.NAME.enabledTools`  | An array of tool names | the package's | The only tools of that server offered, in place of the package's list                                                                                                               |
| `plugins."PLUGIN@MARKETPLACE".mcpServers.NAME.disabledTools` | An array of tool names | the package's | Tools of that server not offered, in place of the package's list                                                                                                                    |
| `plugins."PLUGIN@MARKETPLACE".settings`                      | A table                | none          | The settings of the package's code, as its manifest's `configSchema` describes them: its guest's configuration (`plugins settings`, `/plugins`, its section in the settings center) |

An installed package is on unless its marketplace is turned off (below), or its entry says `enabled = false`, or its entry does not say and `_default.enabled` is `false`. An entry whose key is not a plugin id is kept in the file and ignored, as an unknown key is. How a package's MCP servers run is the package's; `mcpServers` only restricts them ([Plugins' servers](/docs/mcp#plugin-servers)): a key it sets replaces the package's value (a list replaces the package's list), and a server whose two lists name one tool is left out, an issue of the package. A change the Agent writes applies at once: it reloads its packages after each settings write; a hand edit applies at the next start. `plugins add` (and an install in `/plugins`) writes `enabled = true`, `plugins enable` and `disable` write `enabled` alone, and `plugins remove` removes the entry ([plugins](/docs/cli-reference#plugins)). `settings` is replaced whole by `set_package_settings` (`plugins settings --set`, and the **Settings** row of a code plugin's page in `/plugins`), which checks it against the manifest's `configSchema` and the options it lowers to, and restarts the guest with it; a value that is not a table is a repair. The options are also settings of their own, `plugins."ID".settings.OPTION`: the options form of `/plugins` (`o`) and the plugin's section in the settings center's Plugins tab write the keys they change over the settings the user's file holds, remove the one they reset, check the result the same way and restart the guest; one write holds one plugin's settings and nothing else, and every value they show is the user's file's or the default. `config set plugins."ID".settings.OPTION` writes one the same way (the Agent starts for it), and refuses a value its option does not take, or any other key under `settings`. The guest reads it as its configuration and as its `settings` view ([Code plugins](/docs/plugin-rules#guest-host-calls)), checked against those options when the package is read: a key that does not fit its option gets the option's default, or is left out when the schema gives none, with an issue of the package and a log warning; an integer or a number out of range is clamped. The file is never rewritten for it ([configSchema](/docs/writing-plugins#config-schema)).

The settings center has two collections over `[plugins]`: **Installed plugins** (Plugins tab, `/config packages`) installs from `PLUGIN@MARKETPLACE` or a directory, turns a package on or off (`enabled`), updates it, loads it again, trusts its hooks and uninstalls it, keeping or deleting its data; **Plugins' MCP servers** (Tools tab, `/config pluginMcp`) has a record per server an enabled package runs (`PLUGIN/SERVER`), with its connection phase and tools, and writes its `enabled`, `enabledTools` and `disabledTools` under `mcpServers.NAME`, a field unset (`r`) removing its key so that the package's value applies again.

### Marketplaces [#marketplaces]

The marketplaces you added, by name: where the Agent finds their packages.

| Key                              | Type and values           | Means                                                              |
| -------------------------------- | ------------------------- | ------------------------------------------------------------------ |
| `marketplaces.NAME.sourceType`   | `"git"` or `"local"`      | Where it comes from; required                                      |
| `marketplaces.NAME.source`       | A string                  | The git URL, or the local marketplace's directory; required        |
| `marketplaces.NAME.ref`          | A string                  | The branch, tag or commit a git marketplace checks out             |
| `marketplaces.NAME.sparsePaths`  | An array of paths         | The only paths a git marketplace checks out                        |
| `marketplaces.NAME.lastUpdated`  | An RFC 3339 time          | When it was last added or upgraded                                 |
| `marketplaces.NAME.lastRevision` | A git revision            | The revision checked out                                           |
| `marketplaces.NAME.enabled`      | `true` or `false`; `true` | `false` turns off every package from it, whatever `[plugins]` says |

`plugins marketplace add`, `upgrade` and `remove` write these entries ([plugins](/docs/cli-reference#plugins)). The settings center's Marketplaces collection (Plugins tab) adds, upgrades and removes them.

### Plugin options [#plugin-options]

The options of the plugins compiled into the Agent (and of a host's plugins), by plugin name, then by option: `[pluginOptions.NAME]`. A plugin's descriptor says which options it takes, with their kind, bounds and defaults; `/plugins` shows them in a form (`o`), and the settings center as the plugin's own section of its Plugins tab (`/config pluginOptions.NAME`).

| Key                                            | Type and values       | Default | Means                                                                                           |
| ---------------------------------------------- | --------------------- | ------- | ----------------------------------------------------------------------------------------------- |
| `pluginOptions.subagents.maximumRunningAgents` | An integer, 1 to 16   | `3`     | How many sub-agents of one conversation run a turn at once                                      |
| `pluginOptions.subagents.defaultWaitSeconds`   | An integer, 10 to 300 | `30`    | How long `wait_agent` waits when the model gives no timeout, taken into the minimum and maximum |
| `pluginOptions.subagents.minimumWaitSeconds`   | An integer, 10 to 300 | `10`    | The shortest timeout `wait_agent` takes; one above the maximum is taken down to it              |
| `pluginOptions.subagents.maximumWaitSeconds`   | An integer, 10 to 300 | `300`   | The longest timeout `wait_agent` takes                                                          |

```toml
[pluginOptions.subagents]
maximumRunningAgents = 4
defaultWaitSeconds = 60
```

The table merges across the layers per plugin and key, as `[plugins]` merges per entry: a key a layer sets replaces the one below, and the other keys stay. Each key is read on its own: a value of the wrong type, or a text that does not fit, takes the option's default; an integer out of range is clamped to it; either is a warning that names the layer, the plugin and the key (`/warnings`, and the plugin's options in `/plugins`). A key the plugin does not take is kept in the file and ignored, with a warning; a table whose plugin has no options means nothing, as an unknown name in `disabledPlugins` does. A write is strict: `config set pluginOptions.NAME.KEY VALUE`, the settings center, the options form and the facade's `write_setting_values` and `set_plugin_options` check every value against the plugin's options and refuse one that does not fit, with the reason, before anything is written; `config get pluginOptions.NAME.KEY` prints the value the layers resolve, the default when nothing sets it. A profile's or a project's `pluginOptions` is written by hand. A change the Agent writes applies at once: `subagents` takes a new running-agent limit in place and starts again for new wait bounds, and the sub-agents it runs keep running. The `web` plugin's settings stay `webSearchProvider`, `searxngBaseUrl`, `webFetchUseJinaReader` and `webFetchResolveThroughProxy` (above), the settings center's Web tools section (Tools tab).

### Roles [#agents]

The [roles](/docs/roles) a layer defines, by name: `[agents.NAME]`, with the keys of a role file ([Keys](/docs/roles#keys)).

| Key                       | Type and values                        | Means                                                                                                                    |
| ------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `agents.NAME`             | A table of a role's keys               | The role `NAME`                                                                                                          |
| `agents.NAME.configFile`  | A path, relative to this file's folder | A role file whose keys the entry's are read over (Codex's `config_file`); the file is then not read again from `agents/` |
| `profiles.PROFILE.agents` | A table of roles, as `agents`          | The roles of the profile `PROFILE`                                                                                       |

The user's file, its profiles and a trusted project's file may each have them. They do not merge across layers: a role of a higher layer replaces the one below whole ([Where roles come from](/docs/roles#sources)). They are not settings: `config get` and `config set` do not reach them, a `-c agents.…` override is an unknown key, and what cannot be used in them is an issue of the roles (`roles list`, `doctor`, `/warnings`), never a repair of the file. The settings center's Roles collection (Model tab) adds, edits key by key and deletes the entries of the user's file (`description`, `instructions`, `instructionsMode`, `model`, `reasoningEffort`, `spawnable`); the keys that narrow a role, and the roles of role files, profiles, projects and plugins, are written in their files.

## providers.toml [#providers-toml]

`providers.toml` has no layers and is readable by its owner only. The `providers` commands usually change it; `/providers` in the terminal interface (the settings center's Providers) edits a Provider and, with `/providers policy`, the shared model policy, and the center's Model overrides (`/config providerModels`) a model's own settings; it can also be edited by hand. Quit any running Agent before you edit it.

```toml
revision = 2
defaultProviderId = "provider-1"

[modelPolicy]
model = "gpt-5.1"
reasoningEffort = "medium"
autoCompactionEnabled = true
autoCompactThresholdPercent = 80
remoteCompaction = "disabled"

[modelPolicy.inputCapabilities]
imageInput = "auto"

[[providers]]
id = "provider-1"
displayName = "OpenAI"
enabled = true
protocol = "responses"
baseUrl = "https://api.openai.com/v1"
apiToken = "sk-..."
requestHeaders = []
```

### Top level [#providers-top]

| Key                 | Type             | Means                                                     |
| ------------------- | ---------------- | --------------------------------------------------------- |
| `revision`          | integer          | Raised by one on each change; the Agent keeps it          |
| `defaultProviderId` | string, optional | The default Provider's id; it must be an enabled Provider |

### [modelPolicy] [#model-policy]

One policy for every Provider.

| Key                            | Type and values                                                                                                             | Default      | Means                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`                        | string, at most 256 bytes                                                                                                   | `""`         | The model new sessions run                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `reasoningEffort`              | `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"`, or another identifier of 1–64 ASCII letters, digits, `-`, `_` or `.` | unset        | The reasoning effort, sent on every protocol (`max`, say, is one of the other identifiers; `none` is refused: leave it unset for the Provider's default). A request sends the level the model's catalog lists nearest to it, or none for a model known to take none. The settings center offers the model's known levels, Default and Custom (typed), as `/effort` does ([Reasoning effort and thinking](/docs/providers-models#reasoning))                       |
| `inputCapabilities.imageInput` | `"auto"`, `"disabled"`                                                                                                      | `"auto"`     | Whether images are sent to the model: `"auto"` sends them unless the model is known not to read them or its own `imageInput` says otherwise ([Images](/docs/providers-models#images)), `"disabled"` never                                                                                                                                                                                                                                                         |
| `contextWindowTokens`          | a positive integer                                                                                                          | unset        | The model's context window, unless the model's own sets one ([below](#provider-models)); unset, taken from a smaller window learned from the Provider's refusal of a request as too long, what the Provider's model list reported ([listed by itself](#model-metadata) unless `modelMetadata.discovery = "off"`), what models.dev gives ([when on](#model-metadata)) or a built-in table ([The context window and compaction](/docs/providers-models#compaction)) |
| `autoCompactionEnabled`        | boolean                                                                                                                     | `true`       | Whether the context is compacted automatically                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `autoCompactThresholdPercent`  | integer, 1–100                                                                                                              | `80`         | Compacts once the context uses this share of the window, or sooner when what is left could not hold a reply ([The context window and compaction](/docs/providers-models#compaction))                                                                                                                                                                                                                                                                              |
| `remoteCompaction`             | `"disabled"`, `"responses_compact"`, `"responses_compact_v2"`                                                               | `"disabled"` | Responses' remote compaction in place of a local summary                                                                                                                                                                                                                                                                                                                                                                                                          |
| `turnBudget`                   | table                                                                                                                       | unset        | A turn's limits (below)                                                                                                                                                                                                                                                                                                                                                                                                                                           |

`[modelPolicy.turnBudget]` is optional; when written it must have all eleven keys, each a positive integer:

| Key                                  | Default | Ceiling   | Means                                     |
| ------------------------------------ | ------- | --------- | ----------------------------------------- |
| `maximumCumulativeModelInputTokens`  | 8000000 | 100000000 | A turn's input tokens in all              |
| `maximumCumulativeModelOutputTokens` | 1000000 | 10000000  | A turn's output tokens in all             |
| `maximumToolInvocations`             | 256     | 10000     | A turn's tool calls                       |
| `maximumToolOutputBytes`             | 16 MiB  | 256 MiB   | A turn's tool output, in bytes            |
| `maximumHookFragmentBytes`           | 1 MiB   | 16 MiB    | What plugin hooks add, in bytes           |
| `maximumPendingInputItems`           | 64      | 1024      | Steering messages waiting                 |
| `maximumInFlightTools`               | 8       | 64        | Tool calls running at once                |
| `maximumConsecutiveStalledSteps`     | 4       | 32        | Steps in a row without progress           |
| `modelStreamIdleTimeoutSeconds`      | 120     | 86400     | How long the model's stream may be silent |
| `toolIdleTimeoutSeconds`             | 600     | 86400     | How long a tool may make no progress      |
| `approvalTimeoutSeconds`             | 900     | 86400     | How long an approval may wait             |

### [[providers]] [#providers]

At most 32.

| Key              | Type and values                                                 | Means                                                                                                                                                |
| ---------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | 1–64 letters, digits, `_` or `-`                                | The Provider's id; `providers add` gives the lowest free `provider-N`                                                                                |
| `displayName`    | 1–128 bytes                                                     | Its name                                                                                                                                             |
| `enabled`        | boolean                                                         | Whether it is enabled                                                                                                                                |
| `protocol`       | `"responses"`, `"chat_completions"`, `"anthropic_messages"`     | The protocol; see [Providers and models](/docs/providers-models#protocols)                                                                           |
| `baseUrl`        | An `http` or `https` URL without credentials, query or fragment | The endpoint; the protocol's path is appended to it                                                                                                  |
| `apiToken`       | string, optional                                                | The API token, kept as it is                                                                                                                         |
| `requestHeaders` | An array of `{ name, value }`, at most 32                       | Headers added to every request; not `Authorization`, `x-api-key`, `anthropic-version`, `Host`, `Content-Type` or the other headers the Agent manages |
| `models`         | A table of model ids, each a table (below), optional            | What is set for each of the Provider's models                                                                                                        |

When the default Provider is removed or disabled, the first enabled Provider in the list becomes the default.

### [providers.models."ID"] [#provider-models]

A model's own settings, by its id (1–256 bytes; quote it), which outweigh what its Provider's model list reports and what the Agent learned from refusals, and for this model the policy's `contextWindowTokens` ([Per-model settings](/docs/providers-models#per-model)). Every key is optional.

```toml
[providers.models."qwen3-coder"]
contextWindowTokens = 262144
maxOutputTokens = 65536
imageInput = "unsupported"
reasoningEfforts = []
```

| Key                   | Type and values                                                                                 | Means                                                                                                                                                                           |
| --------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contextWindowTokens` | a positive integer                                                                              | The model's context window                                                                                                                                                      |
| `maxOutputTokens`     | a positive integer                                                                              | Its largest output                                                                                                                                                              |
| `imageInput`          | `"auto"` (default), `"supported"`, `"unsupported"`                                              | Whether it is sent images: by what is known, always (a refusal still falls back for its request), or never; the policy's `inputCapabilities.imageInput = "disabled"` still wins |
| `reasoningEfforts`    | an array of `"minimal"`, `"low"`, `"medium"`, `"high"`, `"xhigh"` or other identifiers; or `[]` | The levels it takes, in place of what its model list names; `[]`: it takes no reasoning parameter                                                                               |

Each key falls back on its own: one that cannot be used (a window of 0, an effort list holding `none`) is left out and recorded as a repair, an entry that is not a table is dropped, and the Provider stays. A session takes them at its next turn. The `providers` commands and a Provider's record in the settings center keep them as they are; the center's Model overrides collection (Model tab, a record per `PROVIDER/MODEL`) adds, edits, unsets and deletes them, each write at the file's revision.

## mcp.toml [#mcp-toml]

`mcp.toml` has no layers and is readable by its owner only. `mcp add` writes a new server's defaults; `/mcp` in the terminal interface (the settings center's MCP servers and MCP secrets) edits a server, its credentials, protocol mode and per-tool policies, and the file can also be edited by hand.

```toml
revision = 3

[[servers]]
id = "github"
callTimeoutSeconds = 300

[servers.transport]
type = "stdio"
program = "github-mcp-server"
argv = ["stdio"]

[servers.transport.publicEnvironment]
GITHUB_TOOLSETS = "repos,issues"

[servers.transport.credentialEnvironment]
GITHUB_PERSONAL_ACCESS_TOKEN = "github-token"

[servers.toolApprovalPolicies]
get_issue = "allow"

[credentials.github-token]
value = "ghp_..."
generation = 1
```

`revision` is raised by one on each change, as in `providers.toml`; the Agent keeps it.

### [[servers]] [#servers]

At most 64. A key a server leaves out takes the value in the last column, what `mcp add` and the settings center write for a new server; the Agent writes every key when it writes the server. Only `id`, `transport` with its `type`, and a stdio transport's `program` or an HTTP transport's `url` have no default: a server without one, or with a value that is not of its key's type, is dropped, as a repair ([Configuration recovery](/docs/recovery)).

| Key                          | Type and values                                             | Default      | Means                                                                |
| ---------------------------- | ----------------------------------------------------------- | ------------ | -------------------------------------------------------------------- |
| `id`                         | 1–128 letters, digits, `-`, `_`, `.`                        |              | The server's id; a server with another id is dropped                 |
| `enabled`                    | boolean                                                     | `true`       | Whether it is enabled; enabled servers connect when the Agent starts |
| `required`                   | boolean                                                     | `false`      | A required server: a step fails when its tools cannot be used        |
| `protocolMode`               | `"legacy"`, `"v20260728"`                                   | `"legacy"`   | The MCP protocol version                                             |
| `transport`                  | table (below)                                               |              | The transport                                                        |
| `connectTimeoutSeconds`      | 1–86400                                                     | `15`         | Connecting                                                           |
| `initializeTimeoutSeconds`   | 1–86400                                                     | `30`         | Initializing                                                         |
| `listTimeoutSeconds`         | 1–86400                                                     | `30`         | Listing the tools                                                    |
| `callTimeoutSeconds`         | 1–86400                                                     | `120`        | A tool call                                                          |
| `shutdownTimeoutSeconds`     | 1–86400                                                     | `10`         | Shutting down                                                        |
| `maximumConcurrentCalls`     | 1–64                                                        | `4`          | Calls at once                                                        |
| `toolMaximumConcurrentCalls` | A table of tool name to 1–64                                | `{}`         | One tool's calls at once                                             |
| `enabledTools`               | An array of tool names                                      | `[]`         | Only these tools; empty means all                                    |
| `disabledTools`              | An array of tool names                                      | `[]`         | Not these tools                                                      |
| `approvalPolicy`             | `"allow"`, `"ask"`, `"deny"`                                | `"ask"`      | Whether a call needs an approval; see [MCP](/docs/mcp#policies)      |
| `toolApprovalPolicies`       | A table of tool name to approval policy                     | `{}`         | One tool's approval policy                                           |
| `exposurePolicy`             | `"direct"`, `"direct_model_only"`, `"deferred"`, `"hidden"` | `"deferred"` | How the tools are offered to the model                               |
| `toolExposurePolicies`       | A table of tool name to exposure policy                     | `{}`         | One tool's exposure policy                                           |

A number out of range is brought into it.

`transport` with `type = "stdio"`:

| Key                     | Means                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| `program`               | The program, required: an absolute path, or a name looked up on `PATH`                                       |
| `argv`                  | Its arguments, none when left out                                                                            |
| `cwd`                   | Its working directory, optional                                                                              |
| `publicEnvironment`     | A table of environment variable to value, empty when left out                                                |
| `credentialEnvironment` | A table of environment variable to credential key, empty when left out; the value comes from `[credentials]` |

`transport` with `type = "streamable_http"`:

| Key                 | Means                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `url`               | Required: an `http` or `https` URL without credentials or fragment                             |
| `publicHeaders`     | A table of header to value, empty when left out                                                |
| `credentialHeaders` | A table of header to credential key, empty when left out; the value comes from `[credentials]` |
| `oauth`             | `"disabled"` (the default), `"optional"`, `"required"`; not with an `Authorization` header     |

### [credentials] [#credentials]

| Key                          | Means                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `credentials.KEY.value`      | The credential's value, kept as it is                                                |
| `credentials.KEY.generation` | A positive integer; raise it when you change the value, so the Agent sees it changed |

A credential key has 1–128 letters, digits, `.`, `_` or `-`. A server that refers to a credential that does not exist cannot connect.
