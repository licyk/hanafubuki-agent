## What the Agent reads [#read]

| Variable                                             | Does                                                                                                                                                                                 |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `HANAFUBUKI_AGENT_HOME`                              | One directory in place of both the configuration and the data directory. A relative path is taken from the current directory (not `-C`); an empty value counts as unset              |
| `XDG_CONFIG_HOME`, `XDG_DATA_HOME`                   | On Linux, where the configuration and data directories are based; `~/.config` and `~/.local/share` by default                                                                        |
| `VISUAL`, `EDITOR`                                   | The editor `config edit` opens and Ctrl-G edits the draft in ([Terminal interface](/docs/terminal-interface#composer)), `VISUAL` first. It may have arguments, such as `code --wait` |
| The variable `--api-key-env` names                   | `providers add` reads the API token from it, once, when the Provider is added                                                                                                        |
| `PATH` (and `PATHEXT` on Windows)                    | Finding a stdio MCP server's program                                                                                                                                                 |
| `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` | The proxy of the requests to model Providers; see [Network and logging](/docs/network-logging#provider-proxy)                                                                        |

The Agent itself reads neither `RUST_LOG` nor `NO_COLOR`: the log level is `logLevel` and `--log-level`; see [Network and logging](/docs/network-logging#logging).

## The environment of commands and terminals [#commands]

The commands the model runs through its tools do not inherit the Agent process's environment. They get a clean one:

- Of the Agent's environment, only `PATH` and `TMPDIR`. On Windows, the system's variables, not the user's: `PATH`, `PATHEXT`, `SYSTEMROOT`, `WINDIR`, `COMSPEC`, `TEMP`, `TMP`, `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `ProgramData`, `ProgramFiles`, `ProgramFiles(x86)`, `SystemDrive`, `HOMEDRIVE`, `HOMEPATH`, `PSModulePath`, `PROCESSOR_ARCHITECTURE`, `NUMBER_OF_PROCESSORS` and `OS`, which Windows PowerShell's modules, git's global configuration and npm's cache need.
- So that a command neither waits on a pager nor fills its output with escape sequences: `NO_COLOR=1`, `TERM=dumb`, `LANG`, `LC_CTYPE` and `LC_ALL` set to `C.UTF-8`, `COLORTERM` empty, and `PAGER`, `GIT_PAGER` and `GH_PAGER` set to `cat`.
- So that Python writes UTF-8, on Windows too: `PYTHONUTF8=1` and `PYTHONIOENCODING=utf-8`. How the other shells' output is kept UTF-8 is in [Tools](/docs/tools#commands).
- The proxy variables `network.proxy` decides.
- For a [POSIX shell on Windows](/docs/tools#commands) (Git for Windows' or MSYS2's bash), what it needs to run like one: the shell's directory (`usr\bin`, where `ls` and the other MSYS programs are) first on `PATH`, since a shell that is not a login shell keeps the `PATH` it is given; `CHERE_INVOKING=1`, without which MSYS2's login shell changes to `$HOME`; `MSYS2_PATH_TYPE=inherit`, without which MSYS2's login shell keeps only the system directories of the Windows `PATH` (Git for Windows' keeps it all by default); and, when the Agent itself runs in an MSYS2 or Git Bash shell, its `MSYSTEM`. A variable the command already has is left as it is.

So a variable you set in your shell (an API token, a proxy) does not reach the commands the model runs.

stdio MCP servers differ: they inherit the Agent process's whole environment, plus the variables `mcp.toml` gives them, and then the proxy variables `network.proxy` decides, which win over both. A proxy change starts them anew under the new proxy.

## Proxy variables [#proxy]

`network.proxy` decides the proxy variables of the processes the Agent starts:

| `network.proxy`      | What commands, terminals and stdio MCP servers get                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------- |
| `"system"` (default) | No proxy variable (a stdio MCP server keeps those of the Agent's environment)                      |
| A proxy URL          | `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` set to the URL, and `NO_PROXY=localhost,127.0.0.1,::1` |
| `"disabled"`         | `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` removed, and `NO_PROXY=localhost,127.0.0.1,::1`        |

Each name is set or removed in upper and lower case (`https_proxy`, `no_proxy` and so on), except on Windows, where names are not case-sensitive. A change applies to the processes started after it. See [Network and logging](/docs/network-logging).
