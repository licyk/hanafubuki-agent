模型通过工具完成工作。每个工具来自一个插件，可以用 `disabledPlugins` 整个关闭（见[配置参考](/docs/config-reference#general)）。哪些工具需要审批见[权限与审批](/docs/permissions#what-asks)。

| 插件           | 工具                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| `execution`    | `exec_command`、`write_stdin`、`resize_execution`                                                             |
| `workspace-fs` | `read_file`、`list_directory`、`search_text`、`apply_patch`、`move_path`、`delete_path`                       |
| `web`          | `web_search`、`fetch_web_page`                                                                                |
| `view-image`   | `view_image`（只在模型接受图片时提供）                                                                        |
| `mcp`          | MCP 服务器的工具，以及 `list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource`               |
| `skills`       | `skills_list`、`skills_read`、`enable_skill`、`disable_skill`                                                 |
| `memory`       | `list_agent_memories`、`search_agent_memories`、`read_agent_memory`、`append_agent_memory_note`（启用记忆时） |
| `goal`         | `get_goal`、`create_goal`、`update_goal`                                                                      |
| `subagents`    | `spawn_agent`、`send_message`、`followup_task`、`wait_agent`、`list_agents`、`interrupt_agent`                |

另外有几个总是存在的工具：`update_plan`（更新任务计划）、`request_user_input`（向你提问）、`new_context`（开始新的上下文窗口），以及在有延迟提供的工具时出现的 `tool_search`。

## 命令和终端 [#commands]

`exec_command` 在 Shell 中运行一条命令：

| 系统         | Shell                                                               |
| ------------ | ------------------------------------------------------------------- |
| Linux、macOS | `/bin/bash`（没有时用 `/bin/sh`），默认以登录 Shell 运行（`-lc`）   |
| Windows      | `pwsh`（没有时用 `powershell`），输出为 UTF-8；也可以选择 `cmd.exe` |

- **长时间运行的命令**：命令默认最多等待 10 秒（模型可以要求最多 30 秒）。到时还没结束的命令继续在后台运行，模型用 `write_stdin` 读取后续输出或向它输入。
- **交互式终端**：模型可以要求在伪终端（PTY）中运行，此时可以输入任意内容，并用 `resize_execution` 调整大小；普通模式下只能发送 Ctrl-C。
- **输出**：每次调用最多返回 256 KiB 输出，一个进程的总输出默认最多 256 KiB。
- **时限**：每个进程最多运行 10 分钟。工具 10 分钟没有进展也会被停止。
- **沙箱**：命令在会话的[沙箱](/docs/permissions#sandbox)中运行：Linux 和 macOS 上默认只能写入工作区根目录和临时目录，不能使用网络；需要这台机器无法提供的沙箱的命令不会运行。
- **在沙箱之外运行**：和 Codex 一样，模型可以请求在沙箱之外运行一条命令，参数是 `sandbox_permissions`（`"use_default"`，即默认值，或 `"require_escalated"`）和 `justification`（随审批显示的一个问题，最多 1024 字节；只能和 `"require_escalated"` 一起使用，否则是模型会读到的错误）。这样的命令需要单独的审批，完全访问模式永远不会给出；见[权限](/docs/permissions#escalation)。
- **环境**：命令得到一个干净的环境，不继承你 Shell 中的变量，见[环境变量](/docs/environment#commands)。
- **文本编码**：输出以 UTF-8 交给模型。
  - PowerShell（5.1 和 7 都一样）开始时把控制台的输出和输入代码页，以及它通过管道传给程序的文本的编码（`$OutputEncoding`，5.1 中默认是 ASCII）设为不带字节顺序标记的 UTF-8，并关闭进度条（`$ProgressPreference = 'SilentlyContinue'`）。
  - `cmd.exe` 先运行 `chcp 65001`，因此它启动的、遵循控制台代码页的程序写出 UTF-8。它自己的内置命令（`dir`、`echo`、`type`）写入管道时仍使用 `cmd.exe` 启动时的代码页，即控制台的（OEM）代码页；在伪终端中，或从 PowerShell 中以 `cmd /c …` 运行时，它们的输出完整无误。
  - Python 写出 UTF-8（`PYTHONUTF8=1`、`PYTHONIOENCODING=utf-8`）。
  - 程序仍然用其他编码写出的内容会分段解码，因此同一段输出中可以混有多种编码：ASCII 原样保留，其余字节的每一段若是 UTF-8 就保持不变，否则按 Windows 的 ANSI 代码页读取（中文 Windows 上是 936，即 GBK；西文 Windows 上是 1252）。Linux 和 macOS 没有这样的后备编码，因为命令得到 `LANG=C.UTF-8`：不是 UTF-8 的字节显示为 `�`。
  - 后备编码是 ANSI 代码页，而不是控制台的（OEM）代码页。中文、日文和韩文 Windows 上两者相同（936、932、949、950），因此在那里 `cmd.exe` 的内置命令能被正确读取。其他 Windows 上两者不同（1252 和 437 或 850，1251 和 866，1253 和 737）：遵循控制台代码页的程序在 `chcp 65001` 或 PowerShell 的设置之后写出 UTF-8，但 `cmd.exe` 自己的内置命令写入管道的非 ASCII 文本会按错误的代码页读取。
  - 在伪终端中，Windows 的控制台主机自己把程序写出的内容转换为 UTF-8，按控制台代码页（即 UTF-8）读取：在那里仍然写出 ANSI 代码页的程序，输出依然显示为 `�`。
- **工作目录**：命令在模型指定的目录中运行，相对路径从第一个工作区根目录算起；模型没有指定时，在第一个工作区根目录运行：工作目录（`-C`），或 Agent 运行时改到的那个目录。
- **清理**：Agent 记录它启动的进程组，关闭时结束它们；崩溃后，下次启动时会清理遗留的进程。

终端界面中，运行中的命令显示为 `• Running ...`；`exec --json` 中是 `execution_progress` 事件。

在[评审](/docs/sessions#reviews)中只运行普通的 `git --no-pager` 读取命令；见[权限](/docs/permissions#review)。

## 文件 [#files]

| 工具             | 作用                                               |
| ---------------- | -------------------------------------------------- |
| `read_file`      | 读取文件，按页读取，每页最多 256 KiB               |
| `list_directory` | 列出目录                                           |
| `search_text`    | 用正则表达式搜索文本，遵循 `.gitignore` 等忽略规则 |
| `apply_patch`    | 以补丁的形式创建、修改和删除文件                   |
| `move_path`      | 移动或重命名                                       |
| `delete_path`    | 删除文件或目录                                     |

- 相对路径相对于第一个工作区目录。
- 读取不受工作区目录限制；写入、移动和删除在任何位置都需要审批，涉及工作区目录以外的路径时风险等级为严重，并在摘要中列出这些路径。
- 终端界面中，`apply_patch` 的审批和结果会显示修改的差异。

## 网页 [#web]

`web_search` 搜索网页，`fetch_web_page` 读取一个网页的正文。两者都不需要审批。`fetch_web_page` 只读取公网页面，即使通过代理，也会在本机检查页面的地址（[网页抓取与域名解析](/docs/network-logging#web-fetch-dns)）。

`webSearchProvider` 决定使用哪个搜索服务：

| 值               | 行为                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------ |
| `"auto"`（默认） | 设置了 `searxngBaseUrl` 时先用 SearXNG，没有结果或失败时改用 DuckDuckGo；否则用 DuckDuckGo |
| `"duckduckgo"`   | 总是用 DuckDuckGo                                                                          |
| `"searxng"`      | 总是用 SearXNG，需要设置 `searxngBaseUrl`                                                  |

```sh
hanafubuki-agent config set searxngBaseUrl https://searx.example.com
hanafubuki-agent config set webSearchProvider searxng
```

- 每次搜索最多 10 条结果，结果缓存 5 分钟。
- 抓取默认返回最多 50,000 字节的正文，可以分页继续读取。最多跟随 5 次重定向，单次 20 秒。
- 抓取拒绝私有地址、本机地址和带凭据的 URL。
- `webFetchUseJinaReader = true` 时，直接抓取失败（被拒绝、超时、内容为空、类型不支持等）后改用 `https://r.jina.ai/` 读取。这会把 URL 发送给 Jina。
- 网页工具使用 `network.proxy`，见[网络与日志](/docs/network-logging#proxy-scope)。

## 目标 [#goals]

`goal` 插件的工具操作会话的[目标](/docs/sessions#goals)：

- `get_goal` 读取目标：目标内容、状态、预算、已用的 token 和时间，以及预算中剩余的 token。
- `create_goal`（`objective`，可选的 `token_budget`）创建一个活动的目标。模型被告知只在你或指令要求时才创建目标；会话有未完成的目标时它会失败。
- `update_goal`（`status`：`complete`、`blocked` 或 `paused`）在目标达成并经过验证后把它标为完成，在同一个阻碍在三个目标回合中反复出现后标为阻塞，或按你的要求暂停。它不能恢复目标，也不能解除预算限制。

它们都不需要审批。计划模式中只提供 `get_goal`；在临时会话（旁路对话）中它们会失败。

## 子代理 [#subagents]

模型可以把任务交给子代理：一个独立的对话，是该会话的子会话（[会话](/docs/sessions#children)），在后台运行，使用该会话的权限模式；除非子代理的[角色](/docs/roles#subagents)另有规定，也使用该会话的模型和工具。这组工具来自 Codex（它的第二套多代理工具）：

| 工具              | 参数                                                               | 作用                                                                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spawn_agent`     | `task_name`、`message`、`fork_turns`（`all`/`none`）、`agent_type` | 以可派生角色 `agent_type`（不带时为该会话自己的角色）创建名为 `task_name`（小写字母、数字、下划线）的子代理，把 `message` 作为它的第一个回合运行；`all` 从当前回合之前的对话开始，`none` 从空白开始 |
| `send_message`    | `target`、`message`                                                | 运行中的子代理在下一步读到消息；空闲的子代理随下一个任务读到。不开始新回合                                                                                                                          |
| `followup_task`   | `target`、`message`                                                | 给子代理新任务：空闲时开始新回合，否则加入它正在运行的回合                                                                                                                                          |
| `wait_agent`      | `timeout_ms`（10 秒到 5 分钟，默认 30 秒）                         | 等到某个子代理结束一个回合，返回自上次等待以来结束的每个子代理的最终回答（或错误）                                                                                                                  |
| `list_agents`     |                                                                    | 该会话的子代理及各自的状态和角色                                                                                                                                                                    |
| `interrupt_agent` | `target`                                                           | 停止子代理的回合；它仍然接受消息和任务                                                                                                                                                              |

`target` 是子代理的任务名或会话 ID。

- **限制**：只有本身不是子会话的会话能创建子代理，所以子代理不能再创建子代理；一个会话同时最多运行 3 个子代理；同一会话中任务名不能重复。
- **审批**：这些工具不需要审批。子代理自己的工具调用在它自己的对话中审批，使用它在每个任务开始时从该会话取得的权限模式：需要你回答的调用会在那里等待，直到你打开该子代理并回答。
- **指引**：步骤提供 `spawn_agent` 的顶层会话（不在 Plan 模式下，也不在略去这个工具的[角色](/docs/roles#sessions)中）的模型还会读到协调子代理的指引（只在被要求时创建，并行运行彼此独立的步骤，回答之前等待它们）以及可以赋予它们的角色（[子代理的角色](/docs/roles#subagents)）。Plan 模式下只提供 `wait_agent` 和 `list_agents`。
- 子代理和其他会话一样：它的回合和事件在它自己的历史中，界面通过 `subagents` 调用列出会话的子代理（[嵌入 Agent](/docs/embedding#feature-calls)）。在 `disabledPlugins` 中加入 `subagents` 会去掉这些工具和指引。

## 工作区目录 [#workspace]

工作区目录告诉模型它在哪些目录中工作，依次是：

1. 工作目录：`-C 目录`，默认为当前目录；
2. 工作目录所在的 Git 仓库根目录；
3. 每个 `--add-dir 目录`。

位于前面某个目录之内的目录会被去掉。第一个目录是相对路径的基准，`@` 文件提及和 `/diff` 也使用它。

```sh
hanafubuki-agent -C ~/src/app --add-dir ~/src/shared-lib
```

## AGENTS.md [#agents-md]

每个回合开始时，Agent 读取这些说明文件并交给模型：

1. 你自己的说明：数据目录中的 `AGENTS.override.md`，没有时读 `AGENTS.md`（Linux 上是 `~/.local/share/hanafubuki-agent/AGENTS.md`）；
2. 每个工作区目录中的 `AGENTS.override.md`，没有时读 `AGENTS.md`。

只读取工作区目录本身中的文件，不读取 Git 根目录和工作目录之间各级目录中的文件。所有说明合计最多 32 KiB，每组最多 16 KiB。

关闭 `workspace-context` 插件后，模型不再看到这些说明、工作区目录和环境信息。
