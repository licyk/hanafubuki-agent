A **Provider** is a model service: an endpoint, a protocol, and an optional API token. You can configure several; one is the **default Provider**, which new sessions run on. The **model policy** sets the model new sessions run, their reasoning effort and how their context is compacted, for every Provider.

The Providers and the model policy are kept in `providers.toml` in the configuration directory; see the [Configuration reference](/docs/config-reference#providers-toml).

## Protocols [#protocols]

| Protocol           | `--protocol`          | Path (appended to the endpoint) | Authentication                                         | Typical services                                          |
| ------------------ | --------------------- | ------------------------------- | ------------------------------------------------------ | --------------------------------------------------------- |
| OpenAI Responses   | `responses` (default) | `responses`                     | `Authorization: Bearer TOKEN`                          | OpenAI, vLLM and other compatible servers                 |
| Chat Completions   | `chat-completions`    | `chat/completions`              | `Authorization: Bearer TOKEN`                          | DeepSeek, OpenRouter, Ollama and most compatible services |
| Anthropic Messages | `anthropic-messages`  | `messages`                      | `x-api-key: TOKEN` and `anthropic-version: 2023-06-01` | Anthropic                                                 |

A trailing `/` on the endpoint makes no difference: the protocol's path is appended to it, so `https://api.openai.com/v1` with `responses` is `https://api.openai.com/v1/responses`. A query string in the endpoint is kept. The model catalog is read from `models` on the same endpoint.

## Adding a Provider [#add]

<Tabs items={["OpenAI", "Anthropic", "Chat Completions", "A local server"]}>
  <Tab value="OpenAI">
    ```sh
    hanafubuki-agent providers add OpenAI --base-url https://api.openai.com/v1 --api-key-env OPENAI_API_KEY
    ```
  </Tab>
  <Tab value="Anthropic">
    ```sh
    hanafubuki-agent providers add Anthropic --protocol anthropic-messages \
      --base-url https://api.anthropic.com/v1 --api-key-env ANTHROPIC_API_KEY
    ```
  </Tab>
  <Tab value="Chat Completions">
    ```sh
    hanafubuki-agent providers add DeepSeek --protocol chat-completions \
      --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY
    ```

    The endpoint is everything before `chat/completions`.

  </Tab>
  <Tab value="A local server">
    ```sh
    hanafubuki-agent providers add Ollama --protocol chat-completions --base-url http://127.0.0.1:11434/v1
    ```

    Leave out `--api-key-env` for a server that needs no token.

  </Tab>
</Tabs>

- `--api-key-env VAR` reads the token from the environment variable when the Provider is added, and keeps it as it is in `providers.toml` (readable only by you). A token cannot be written on the command line, so it does not end up in your shell's history. When the variable is not set, the command exits with code 2.
- `--header NAME=VALUE` adds a request header sent with each of the Provider's requests (repeatable), kept in `providers.toml`. Unlike the token, its value is on the command line.
- `--disabled` adds the Provider turned off.
- The command prints the new Provider's id, such as `added provider-2`: the lowest free `provider-N`.

## Managing Providers [#manage]

```sh
hanafubuki-agent providers list
hanafubuki-agent providers default provider-2 --model deepseek-chat
hanafubuki-agent providers remove provider-1
```

```text
model: gpt-5.1
provider-1 OpenAI (default)  Responses  https://api.openai.com/v1  token: set
provider-2 DeepSeek  ChatCompletions  https://api.deepseek.com/v1  token: set
```

- The first Provider you add becomes the default. When the default is removed or disabled, the first enabled Provider in the list becomes the default.
- `providers list` never prints a token's or a header's value.
- To change a token or the request headers (`requestHeaders`), or enable a Provider, use `/providers` in the terminal interface ([below](#interface)), or edit `providers.toml` (quit any running Agent before you edit it).

## In the terminal interface [#interface]

`/providers` in the [terminal interface](/docs/terminal-interface#providers) does what the commands above do, and edits a Provider in place:

- **The list**: ★ marks the default; each Provider shows its protocol, base URL, `token set` or `no token`, and `disabled`. Enter edits, `a` adds, `d` deletes after asking, `e` enables or disables, `*` makes an enabled Provider the default, `p` edits the model policy, Esc closes.
- **The form**: name, protocol (`responses`, `chat_completions` or `anthropic_messages`), base URL, API token, enabled, and the request headers as rows. The token is shown as dots: leave it as it is to keep it, clear it to remove it. The keys are in [Forms](/docs/terminal-interface#forms).
- **Test** lists the models of what the form holds, with its token and headers, and saves nothing: it says how many models the Provider lists, or the Provider's error.
- **Save** writes the Provider whole. For an enabled Provider the model picker follows: the model you pick (or type, with **Enter a model id…**, when the Provider does not list it) becomes the one new sessions run, and the Provider the default. Esc leaves the model as it was. `/model` still changes only the running session's model.
- **The model picker** shows, beside each model its Provider's catalog lists, what the catalog reports of it: its window (`200K`), `vision` and `reasoning`. So does `/model`.
- **The model policy** (`p` in the list, or `/providers policy`): the default Provider and model, reasoning effort (a choice of the levels known for the model, from its catalog or its [own settings](#per-model), when any are, else free text), image input, context window (left empty, its placeholder names the window known for the model and where it came from, `200K, reported`), automatic compaction and its threshold, remote compaction, and either the Agent defaults or all eleven turn-budget fields. It writes through the same revision gate. A model's own settings are not in the form: they are written in `providers.toml` ([Per-model settings](#per-model)).
- Each write names the version of `providers.toml` the screen read. When something else changed the file meanwhile (a `providers` command in another terminal, say), the write is refused: the screen reads the Providers again, keeps what the form holds and says so, and saving again applies it.
- With no default Provider or no model, the interface opens this screen by itself at the start: see [First-run setup](/docs/terminal-interface#setup).

## The model [#model]

| How                                | For                                                                    |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `providers default ID --model`     | The model policy's model: what every new session runs from then on     |
| `-m MODEL`                         | This run's new (or resumed) sessions, on the default Provider          |
| `/model` in the terminal interface | The current session, picked from the enabled Providers' model catalogs |

`/model` lists each enabled Provider's model catalog (read from `models`); a Provider whose catalog cannot be read says why. From each model in a catalog the Agent reads the context window it reports and its largest output (see [The context window and compaction](#compaction)), whether it reads images (see [Images](#images)), and whether it reasons and at which efforts (see [Reasoning effort and thinking](#reasoning)). What a catalog reports is kept in the data directory's `model-metadata.json`, so it still holds after a restart; a model a later catalog leaves out keeps it for 7 days. The Agent also reads the catalogs by itself, in the background: the default Provider's when it starts, and a Provider's when a session is created on it, given one of its models or runs a turn on it, at most once a day per Provider (once every 15 minutes after a catalog that could not be read). Nothing waits for it, and a catalog that cannot be read is only tried again later. `modelMetadata.discovery = "off"` in `config.toml` turns this off ([Configuration reference](/docs/config-reference#model-metadata)); the catalogs you open are still read and kept. A model listed without a usable id is left out, and a field that cannot be read counts as not reported, so one odd model never fails the catalog. `doctor --online` checks that the default Provider lists its models, and shows what is known of each. A host can read the catalog of a Provider before saving it, to test the endpoint, token and headers (`test_provider_draft`, see [Embedding](/docs/embedding#configuration-in-a-host)).

## Reasoning effort and thinking [#reasoning]

The reasoning effort is set in `[modelPolicy]` of `providers.toml`; no command-line flag sets it:

```toml
[modelPolicy]
model = "gpt-5.1"
reasoningEffort = "medium"   # minimal, low, medium, high, xhigh
```

Every protocol carries it, as its own field:

| Protocol           | What a request sends                                                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Responses          | `reasoning: {effort, summary: "auto"}`                                                                                                                                                                                                        |
| Chat Completions   | `reasoning_effort`, OpenAI's field, which DeepSeek documents too and OpenRouter lists among its parameters (its reasoning guide names only its `reasoning` object for Anthropic models)                                                       |
| Anthropic Messages | Claude 4.6 and later: adaptive thinking, `thinking: {type: "adaptive", display: "summarized"}`, with `output_config: {effort}` (`minimal` is sent as `low`). Claude up to 4.5, and a model whose id names no Claude: a thinking budget, below |

With no effort set, a request carries none, and the Provider's default applies. `/status` shows the session's effort and, when what is known of the model changes it, what is sent (`reasoning xhigh, sends high`, or `not sent: the model takes none`).

The effort a request carries also depends on what is known of the model, from its Provider's catalog or from the Provider's refusal:

| What is known                           | The effort sent                                                                                                                                                                                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Nothing                                 | The effort set                                                                                                                                                                                                                                           |
| It reasons, at levels the catalog names | The effort set if listed; else its alias if listed (`minimal` → `low`, `xhigh` → `max`); else the nearest listed level on `minimal < low < medium < high < xhigh < max`, the lower on a tie; else none. A change is logged once per session as a warning |
| It reasons, levels not named            | The effort set                                                                                                                                                                                                                                           |
| It takes no reasoning                   | None, whatever is set                                                                                                                                                                                                                                    |

A catalog names levels as `supported_reasoning_levels` (Codex), `reasoning.supported_efforts` (OpenRouter) or `capabilities.effort` (Anthropic); `none` is never one, since an effort of `none` is not accepted: no effort set, or a model that takes none, is how a request goes without. A model's own `reasoningEfforts` ([Per-model settings](#per-model)) replaces the levels its catalog names, or says it takes none. When the policy's model has known levels, the policy form offers them as a choice instead of a text field.

A Provider that refuses the reasoning parameter (status 400 or 422, naming the parameter, see [Internals](/docs/internals#reasoning-refusals)) gets the request once more without it (`exec --json` reports `model_retry_scheduled` with the stage `reasoning_fallback`), and the model is then taken to take no reasoning for 7 days, kept in `model-metadata.json`, whatever its catalog says, until [forgotten](#forget). Under a model's own `reasoningEfforts` the request is still retried without it, but the next one carries the effort again.

**Anthropic's thinking budget.** For a model that takes a budget, the effort sets `budget_tokens`:

| Effort                                | `budget_tokens` |
| ------------------------------------- | --------------- |
| `minimal`                             | 1,024           |
| `low`                                 | 4,096           |
| `medium`, or one not on the list here | 8,192           |
| `high`                                | 16,384          |
| `xhigh`                               | 24,576          |
| `max`                                 | 32,000          |

`max_tokens` is the budget plus 16,384 for the answer, but never more than the model's largest output; with that unknown, it stays 16,384, and the budget is cut to leave the answer 4,096 of it. A budget that cannot keep 1,024 tokens is not sent. Thinking with a budget is also left out of a request that forces a tool, and of one that answers tool calls whose message holds no thinking to send back. With adaptive thinking `max_tokens` is 32,768 under the model's largest output, 16,384 when that is unknown.

The model's thinking is shown: as a `Thinking` line you can expand with Ctrl-O in the terminal interface (see [Terminal interface](/docs/terminal-interface#thinking)), and as the `reasoning_*` events of `exec --json` (see [exec --json events](/docs/json-events#reasoning)); `exec`'s human output and `sessions show` say only how long it took (`thought for 12s`). What there is to see depends on the Provider:

| Protocol           | The thinking                                                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Responses          | With a reasoning effort set, the Agent asks for a summary of the thinking; a compatible server (gpt-oss on vLLM, say) may send the raw thinking text instead |
| Chat Completions   | What the service sends in `reasoning_content` or `reasoning` (DeepSeek, Qwen, OpenRouter and others)                                                         |
| Anthropic Messages | The summary adaptive thinking is asked for, or the thinking a budget allows; a `thinking` block the service sends unasked is shown too                       |

The thinking is kept in the session's history, each stretch up to 256 KiB (the rest is cut). That text is there to be read: it is never sent to the model again. Two protocols require their thinking back, and get it:

- **Anthropic's thinking with a budget**: the turn's thinking blocks, whole and with their signatures, go back with the tool calls they preceded, for the rest of that turn only. They are kept in memory, never written to the history, so a turn recovered after a restart sends its next request without thinking. Adaptive thinking sends no block back: Anthropic allows leaving them out there, and its newest models refuse a block once what came before it changed, which the Agent's requests do from one step to the next.
- **Chat Completions' `reasoning_content`** (DeepSeek's thinking mode, which refuses a request with tools whose earlier assistant messages lack it): the whole text of each stretch that came as `reasoning_content`, up to 1 MiB, goes back as the `reasoning_content` of the assistant message it preceded, from every turn still in the context window, a compaction's request included, whether a reasoning effort is set or not. It is written to the history with its message, so a resumed session sends it too. Thinking that came as `reasoning` (OpenRouter's field) is not sent back. An assistant message with no text to send (one from before the Agent sent it back, or one whose thinking passed 1 MiB) goes without it, and DeepSeek with tools may refuse the session's requests, compaction's too, while that message is in the context window: start a new session then.

## The context window and compaction [#compaction]

The model's context window is, in order: the model's own `contextWindowTokens` ([Per-model settings](#per-model)), `contextWindowTokens` in `[modelPolicy]`, a window the Agent learned from the Provider's refusal (below) while it is the smaller, the value the Provider's model catalog last reported, the value [models.dev](#models-dev) gives when you turned it on, or a built-in table of common models (the GPT-5 family, Claude, Gemini 2.5 and others). With none, nothing is compacted automatically. A session takes its window when it is created or its model is chosen, and again as each of its turns starts, so a session created before its model's catalog was read gets the window at its next turn, and a window you set or change in `providers.toml` reaches it at its next turn too. A window you set wins. When nothing knows its model's window any more, a session keeps the one it has, unless that was set, learned or from models.dev and is no longer (removed, [forgotten](#forget), or models.dev turned off): then its window is unknown again. `/status` shows the window and where it came from: `200K (reported)`, `128K (models.dev)`, or `unknown (compacts on the Provider's error)`.

Once the context uses `autoCompactThresholdPercent` of the window (80% by default), the Agent compacts it before a turn or during one: the earlier conversation becomes a summary, and the recent messages stay. It compacts sooner when what is left of the window could not hold a reply: it keeps room for the model's largest output (32,768 tokens when its catalog does not say), but no more than a tenth of the window, at least 4,096 tokens, and never more than half of it. So at the default 80% the threshold decides on a window of 20,480 tokens and more, and on a window of 10,000 the Agent compacts at 5,904.

When the Provider refuses a request as too long for the model's window, the Agent compacts once and retries; if it is refused again, the turn fails (`context_window_exceeded`). It also learns from the refusal: the window it names (`maximum context length is 131072 tokens`), or, when it names none, the size of the refused request, which the window must be smaller than. The session takes that window at once, so the retry and the turns after it compact before the window fills, and the conversation says so (`The Provider refused the request as too long; this model's window is taken as 131072 from now on.`). Every later session on the same model of that Provider starts with it, after a restart too, for 7 days; only a smaller window replaces it before then, and [forgetting](#forget) it drops it. It is learned even with automatic compaction off, and never replaces a `contextWindowTokens` you set.

| Setting                       | Default      | Does                                                                                              |
| ----------------------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| `autoCompactionEnabled`       | `true`       | Whether the context is compacted automatically                                                    |
| `autoCompactThresholdPercent` | `80`         | The share of the window that triggers it                                                          |
| `remoteCompaction`            | `"disabled"` | `"responses_compact"` or `"responses_compact_v2"`: the server compacts, on the Responses protocol |
| `contextWindowTokens`         | unset        | Sets the context window                                                                           |

An existing session takes a changed `remoteCompaction` at its next turn or `/compact`, and a changed `contextWindowTokens` (the policy's or the model's own) at its next turn; it takes the other keys when its model is selected again (`/model`), and a new session takes them all. What reduces the context besides this compaction is the [compaction strategy](/docs/config-reference#compaction) in `config.toml`.

`/compact` in the terminal interface compacts now. `/status` shows the token use and how much context is left.

## Images [#images]

With `imageInput` of `[modelPolicy.inputCapabilities]` set to `"auto"` (the default), whether the Agent sends a model images (yours, and those `view_image` looks at) depends on what it knows of the model:

- **It reads images**, as its Provider's model catalog (or, when nothing else says, [models.dev](#models-dev)) says, or **nothing says**: images are sent, and `view_image` is offered. When the model refuses an image anyway, the Agent retries once without it, and from then on, for 7 days and across restarts, takes the model for one that reads none.
- **It reads none**, as its catalog says or a refusal taught: no image reaches it, so no request is refused first. The images already in the conversation are replaced by a note that they were left out, `view_image` is not offered, and a message with an image is refused (`the configured model does not support image input`).

A refusal outweighs the catalog: a model listed as reading images that refused one is sent none for those 7 days, until [forgotten](#forget). A conversation takes what is known when it starts, is given a model or is resumed, and again before each request, so a catalog read later applies from the next request. A model's own `imageInput` ([Per-model settings](#per-model)) outweighs both: `"supported"` sends it images whatever its catalog says or a refusal taught, `"unsupported"` never. `"disabled"` in the policy never sends images, whatever the model and its own setting.

## Per-model settings [#per-model]

What the catalog reports of a model, or what the Agent learned, can be wrong, and one policy cannot describe two models of one Provider. A model's own settings, under its Provider in `providers.toml`, outweigh both, for that model only:

```toml
[[providers]]
id = "provider-1"
# …

[providers.models."qwen3-coder"]
contextWindowTokens = 262144
maxOutputTokens = 65536
imageInput = "unsupported"
reasoningEfforts = []

[providers.models."openai/gpt-4.1"]
imageInput = "supported"
```

| Key                   | Values                                             | Does                                                                                                                                                                                                                                   |
| --------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contextWindowTokens` | a positive integer                                 | The model's window, over `contextWindowTokens` of `[modelPolicy]`, a learned window and the catalog's                                                                                                                                  |
| `maxOutputTokens`     | a positive integer                                 | Its largest output, which the threshold leaves room for and Anthropic's thinking is sized under ([The context window and compaction](#compaction), [Reasoning effort and thinking](#reasoning))                                        |
| `imageInput`          | `"auto"` (default), `"supported"`, `"unsupported"` | `"auto"` goes by what is known ([Images](#images)); `"supported"` sends images whatever the catalog says or a refusal taught: a refusal still falls back for its request, and the next request sends them again; `"unsupported"` never |
| `reasoningEfforts`    | a list of efforts, or `[]`                         | The levels the model takes, in place of the catalog's, which the effort sent is narrowed to and the policy form offers; `[]`: it takes none, and no effort is sent                                                                     |

Each key is optional, and a key left out leaves the others to say. A session takes them as its next turn starts (a new one, a resumed one, and one already open), so quit the Agent, edit the file, and carry on. A value that cannot be used is left out and the file is [repaired](/docs/recovery), the Provider and its other settings kept. They are written by hand only: the `/providers` screens and the `providers` commands keep them as they are.

## Forgetting what was learned [#forget]

What the Agent learned from a Provider's refusals (a smaller window, that a model reads no images, that it takes no reasoning) holds for 7 days. To try the model again before that, forget it:

- `/model forget` in the terminal interface, for the session's model;
- `hanafubuki-agent providers forget ID [--model MODEL]`, for one model of the Provider or all of its models ([Command-line reference](/docs/cli-reference#providers)).

What the catalog reported, the copy of [models.dev](#models-dev) and the per-model settings stay. A session takes the change at its next turn: its window becomes what else is known, or unknown when nothing is.

## models.dev [#models-dev]

[models.dev](https://models.dev) is a public catalogue of models by provider. With `modelMetadata.modelsDev = true` in `config.toml` (or `/config general`, **Use models.dev**), the Agent downloads it (`https://models.dev/api.json`) and takes from it what nothing better says of a model: its window (`limit.context`), its largest output (`limit.output`), that it reasons (`reasoning`) and that it reads images (`modalities.input` holding `"image"`). It is off by default: **turned on, this machine sends a request to models.dev, a third party**, about once a day, with a User-Agent naming the Agent and its version and no credential or anything of yours.

- **Behind everything else.** A model's own settings, the policy, what a refusal taught and what the Provider's catalog reports all come first; models.dev fills only what they leave unknown, before the built-in table. It only adds: it never says a model does not read images or does not reason, and a "reasons" from it leaves the effort you set as it is (it names no levels). Its window and largest output set when the session compacts, as a catalog's do, but never change a request: Anthropic's thinking is sized under a largest output only when something other than models.dev knows it ([Reasoning effort and thinking](#reasoning)).
- **Which entry.** A model id is compared in lowercase, without a `vendor/` prefix, a trailing `-latest` or a trailing `-YYYYMMDD` date (`anthropic/claude-3-5-haiku-20241022` is `claude-3-5-haiku`). The entry under the Provider's own name in models.dev comes first: one whose key is the Provider's id or a word of it (`openai`, `my-openai`), or a label of its endpoint's host (`api.deepseek.com` is `deepseek`), or whose API is at that host. Without one, every provider's entry for the model is taken together, the smaller of each limit (window, largest output) and any "yes", since one provider may publish another's limits.
- **When.** At start and whenever a session is bound to a Provider, as the catalogs are read ([The model](#model)), whatever `modelMetadata.discovery` says: at most once a day after a download, once every 15 minutes after a failed one. The copy is kept in `model-metadata.json` and used for a week, so models.dev unreachable, or answering something unusable, changes nothing and says nothing. `/model forget` and `providers forget` keep it; turning `modelsDev` off drops it, and with it a window a session took from it.

`/status`, `doctor --online` and the policy form's placeholder name what came from it `models.dev`.

## Retries and limits [#limits]

- A failed model request (it cannot connect, say) is tried up to three times; then the turn fails with `model_request_retries_exhausted`.
- A response stream that breaks off is retried; the terminal interface's status line says `Reconnecting`.
- A turn asks the model at most 32 times, and runs for at most 30 minutes (`agent turn stopped at its time limit of 30 minutes; send a message to continue`). A conversation still too long after compaction ends the turn with `the conversation is still too long for the model's context window after it was compacted; start a new conversation or attach less context`. The other limits are in [`turnBudget`](/docs/config-reference#model-policy).
- Requests to a Provider use the Agent process's proxy variables, not `network.proxy`; see [Network and logging](/docs/network-logging#provider-proxy).
