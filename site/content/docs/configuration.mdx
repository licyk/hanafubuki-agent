独立运行的 Agent 把配置保存在配置目录中，默认是 Linux 的 `~/.config/hanafubuki-agent/`、macOS 的 `~/Library/Application Support/hanafubuki-agent/` 和 Windows 的 `%APPDATA%\hanafubuki-agent\`。设置 `HANAFUBUKI_AGENT_HOME` 后，配置和数据都放在这一个目录中。完整说明见[数据目录](/docs/data-directory)。

<Callout>
  嵌入 Agent 的应用（例如
  Hanafubuki）使用自己指定的配置目录，并且只读取用户文件，不使用配置档、项目配置和 `-c`
  覆盖，通常由应用自己的设置页面来修改。
</Callout>

## 三个文件 [#files]

| 文件             | 内容                                                                                 | 分层 | 权限                 |
| ---------------- | ------------------------------------------------------------------------------------ | ---- | -------------------- |
| `config.toml`    | 设置：权限模式、记忆、插件、网页工具、代理、日志级别、终端界面；配置档；受信任的项目 | 有   | 普通                 |
| `providers.toml` | 模型 Provider、它们的令牌，以及模型策略（模型、推理强度、压缩）                      | 无   | 仅自己可读（`0600`） |
| `mcp.toml`       | MCP 服务器及其凭据                                                                   | 无   | 仅自己可读（`0600`） |

文件在需要时才创建：第一次 `config set` 时创建 `config.toml`，第一次 `providers add` 时创建 `providers.toml`，依此类推。没有文件时使用默认值。所有键使用 camelCase。每个键的类型和默认值见[配置参考](/docs/config-reference)。

`providers.toml` 和 `mcp.toml` 通常用 `providers` 和 `mcp` 命令修改，也可以直接编辑。

## 查看配置 [#read]

```sh
hanafubuki-agent config path            # 各个文件和目录的位置
hanafubuki-agent config get             # 应用所有分层后的全部设置
hanafubuki-agent config get logLevel    # 一个键的值
hanafubuki-agent config get memory      # 一个表
```

`config get` 输出的是最终生效的值，即默认值、用户文件、配置档、项目配置和 `-c` 叠加之后的结果。字符串原样输出，其他值输出为 TOML。代理 URL 中的用户名和密码显示为 `***`。没有设置的可选键不输出任何内容。

## 修改配置 [#write]

```sh
hanafubuki-agent config set logLevel debug
hanafubuki-agent config set memory.enabled true
hanafubuki-agent config set network.proxy http://127.0.0.1:7890
hanafubuki-agent config set tui.alternateScreen never
hanafubuki-agent config set profiles.review.permissionMode auto_review
hanafubuki-agent config set "projects.'$PWD'.trustLevel" trusted
```

`config set` 把一个键写入用户的 `config.toml`。键是 TOML 的点分键，包含特殊字符的部分要加引号（如上面的项目路径）。值按 TOML 解析，不是合法 TOML 时作为字符串，所以 `debug` 不需要加引号。

`config set` 接受：

- 任何设置的键，见[配置参考](/docs/config-reference#config-toml)；
- 配置档中的键：`profiles.名字.键`；
- 项目的信任级别：`projects."路径".trustLevel`，值为 `trusted` 或 `untrusted`。

它会拒绝不认识的键和 Agent 无法使用的值，例如：

```text
error: `nosuch` is not a setting of config.toml
```

写入只修改这一个键，保留文件中的注释和其他内容。`config set` 不能删除一个键；要删除，请编辑文件。终端界面的 [`/tui` 和 `/raw`](/docs/terminal-interface#modes) 以同样的方式写入它们的 `[tui]` 键。

## 编辑文件 [#edit]

```sh
hanafubuki-agent config edit
```

用 `$VISUAL` 或 `$EDITOR` 打开用户的 `config.toml`（目录不存在时先创建）。编辑器可以带参数，例如 `EDITOR="code --wait"`。

手动编辑的内容在下一次启动 Agent 时读取。如果文件中有无法使用的值，Agent 会修复它，并先把原文件复制到 `.recovery/`，见[配置恢复](/docs/recovery)。

## 钩子 [#hooks]

钩子是你配置的命令，在 Agent 触发某个事件时运行：工具调用之前或之后、会话开始时、你提交消息时、轮次结束之前。格式与 Codex 相同，所以它的 `hooks.json` 文件和 `[hooks]` 表可以原样使用。钩子只有在你信任之后才会运行。

它们从两个地方读取，每处都可以写成 `hooks.json` 或 `config.toml` 的 `[hooks]` 表（两者选其一）：

- 配置目录，即用户自己的钩子；
- 项目的 `.hanafubuki-agent/`，在读取项目配置时：用户的 `config.toml` 信任该项目（[配置层](/docs/config-layers#projects)），并且项目有 `.hanafubuki-agent/config.toml`。

每个轮次开始时都会重新读取，所以修改从下一个轮次起生效，不需要重启。

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|exec_command",
        "hooks": [{ "type": "command", "command": "~/bin/check-command.sh", "timeout": 30 }]
      }
    ],
    "Stop": [{ "hooks": [{ "type": "command", "command": "~/bin/tests-pass.sh" }] }]
  }
}
```

在 `config.toml` 中写法相同：

```toml
[[hooks.PreToolUse]]
matcher = "Bash|exec_command"

[[hooks.PreToolUse.hooks]]
type = "command"
command = "~/bin/check-command.sh"
timeout = 30
```

| 事件               | 时机                                           | `matcher` 匹配                                                               | 钩子可以                                                                                                                                                                                                              |
| ------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PreToolUse`       | 工具调用的审批之前                             | 工具名（`exec_command` 也作为 `Bash`，`apply_patch` 也作为 `Write`、`Edit`） | 拒绝调用：以退出码 2 退出并把原因写到 stderr，或输出 `{"hookSpecificOutput": {"permissionDecision": "deny", "permissionDecisionReason": "…"}}`（或 `{"decision": "block", "reason": "…"}`）；模型把原因读作调用的错误 |
| `PostToolUse`      | 调用运行之后                                   | 工具名，同上                                                                 | 为模型添加上下文：`{"hookSpecificOutput": {"additionalContext": "…"}}`，或以退出码 2 退出并写到 stderr                                                                                                                |
| `SessionStart`     | 会话的第一个轮次（Agent 运行期间每个会话一次） | `startup`                                                                    | 为会话添加上下文：stdout 上的纯文本，或 `additionalContext`                                                                                                                                                           |
| `UserPromptSubmit` | 你提交消息时                                   | （不使用）                                                                   | 为轮次添加上下文：stdout 上的纯文本，或 `additionalContext`；不能阻止消息                                                                                                                                             |
| `Stop`             | 模型给出最终回答时                             | （不使用）                                                                   | 让轮次继续：`{"decision": "block", "reason": "…"}` 或退出码 2，原因作为模型的下一条指示；`{"continue": false}` 结束轮次                                                                                               |

- **matcher** 为空或 `*` 时匹配一切；用 `|` 连接的名字精确匹配其中之一；其他写法是正则表达式。
- **命令**通过你的 shell 运行（`$SHELL -lc`，Windows 上为 `%COMSPEC% /C`），工作目录是当前工作目录，事件以 JSON 写到它的 stdin：`session_id`、`turn_id`、`cwd`、`hook_event_name` 和事件自己的字段（`tool_name`、`tool_input`、`tool_use_id` 与 `tool_response`；`prompt`；`source`；`stop_hook_active` 与 `last_assistant_message`）。Windows 上用 `commandWindows` 代替它。`timeout` 以秒计（默认 600）；`statusMessage` 在运行时显示。
- 退出码 0 且 stdout 为空表示什么都不做。其他退出码、超时或无法读取的 JSON 是钩子的失败：会被记录且不起作用，所以坏掉的钩子从不让调用或轮次停下。钩子的输出按宽松方式读取：Agent 不用的字段被忽略。
- 同一事件的钩子按配置顺序依次运行（用户的在前）；`PreToolUse` 遇到第一个拒绝就结束。
- 不支持 Codex 的其他事件（`PermissionRequest`、`PreCompact`、`PostCompact`、`SessionEnd`、`SubagentStart`、`SubagentStop`、`PreModelRequest`、`PostModelRequest`、`Interrupt`）、它的 `mcp_tool`、`prompt` 与 `agent` 钩子，以及 `async` 命令：它们会被报告，从不运行。文件中无法使用的内容逐项跳过；其余照常加载。

### 信任 [#hooks-trust]

钩子只有在你信任之后、并且处于启用状态时才会运行。每个钩子有一个键 `<文件>:<事件>:<组>:<钩子>`（`/home/me/.config/hanafubuki-agent/hooks.json:pre_tool_use:0:0`），信任它会记录它定义的哈希（事件、matcher、命令、超时和状态消息）。定义改变了的钩子是 `modified`，在你再次信任之前不会运行。基于 Agent 的应用通过门面的钩子调用列出钩子及其信任状态、信任它们并开关它们（[功能调用](/docs/embedding#feature-calls)）。信任与启用状态保存在数据目录的 `hooks-state.json` 中，而不是 `config.toml`；Codex 的 `[hooks.state]` 被忽略。

## 示例 [#example]

```toml
# ~/.config/hanafubuki-agent/config.toml
permissionMode = "manual"
logLevel = "info"

[memory]
enabled = true

[network]
proxy = "http://127.0.0.1:7890"

[tui]
fullscreenTranscript = true
rawOutput = false

# hanafubuki-agent -p review
[profiles.review]
permissionMode = "auto_review"

[projects."/home/me/src/my-project"]
trustLevel = "trusted"
```

配置档、项目配置和 `-c` 如何叠加，见[配置分层](/docs/config-layers)。
