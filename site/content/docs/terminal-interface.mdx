不带子命令运行 `hanafubuki-agent` 会打开终端界面。后面跟上一段文本时，它会作为第一条消息发送：

```sh
hanafubuki-agent
hanafubuki-agent "找出这个项目里没有测试覆盖的模块"
```

界面启动时没有会话：发送第一条消息时才创建会话，需要会话的命令（`/model`、`/mode`、`/compact`、`/status`）也会先创建一个。只是启动再退出不会留下空会话。没有默认 Provider 或没有选择模型时，界面会打开[首次设置](#setup)，而不是让第一条消息失败。因其他原因无法创建会话时，对话中会用红色说明原因，界面保持打开，下一条消息会再试一次。

终端界面需要标准输入和标准输出都是终端；在管道或重定向中运行时，它会提示改用 [exec](/docs/exec) 并以退出码 2 退出。`-m`、`-C`、`--add-dir`、`--permission-mode` 等[全局选项](/docs/cli-reference#global-flags)同样适用。

## Fullscreen 与 Scrollback [#modes]

界面以两种方式之一显示对话，启动时决定，直到退出都不变：

- **Fullscreen**（默认）：界面占用终端的备用屏幕，在底部区域上方自己绘制对话。滚动、选择、搜索和复制都在界面内完成（见[阅读对话](#reading)），退出后对话不会留在终端里。
- **Scrollback**：界面占据终端的下部，对话写进上方终端自己的滚动历史中，所以可以像普通命令输出一样向上滚动、选择和复制，退出后也会留在终端里。最新的条目留在界面绘制的部分，即尾部，在写入之前像 Fullscreen 一样就地更新和展开（[阅读对话](#reading)）。

除非下列设置另有要求，界面以 Fullscreen 启动，按顺序第一条适用的生效：

1. 命令行中的 `--no-alt-screen`：本次运行使用 Scrollback。
2. `tui.alternateScreen = "never"`：使用 Scrollback。`"auto"`（默认）在 SSH 会话中（设置了 `SSH_TTY` 或 `SSH_CONNECTION`）使用 Scrollback，`"always"` 从不。
3. `tui.fullscreenTranscript = false`：使用 Scrollback。`/tui` 在[设置中心](#config)中打开它。

这些键见[配置参考](/docs/config-reference#tui)。

## 界面布局 [#layout]

Fullscreen 下，对话占满底部区域上方的屏幕。Scrollback 下，界面绘制底部区域和它上方对话最新的条目（尾部），对话的其余部分在更上方的滚动历史中。

启动时（以及 `/new` 和恢复会话时），先显示一个信息框，包含版本、模型和工作目录。会话还没有创建时，显示的是它将使用的模型：`-m` 指定的，否则是配置中的。底部区域从上到下是：

1. **状态行**：回合进行中显示 `• Working 25s • esc to interrupt`，包括已用时间；回合思考过之后显示 `• Working 25s (Thinking 20.7s) • esc to interrupt`，括号中是整个回合到目前为止的思考时间，只在模型思考时增长（[思考过程](#thinking)）。模型请求重试时改为 `Reconnecting 1/3: 原因`。等待审批或回答问题时，工作计时暂停。状态行在整个回合中保持显示，模型输出回答时也是。
2. **等待中的消息**：有消息在等待回合时显示（[见下文](#composer)）。
3. **输入框**：以 `›` 开头。
4. **底栏**：输入框为空，或有草稿但没有回合在运行时，显示[状态栏](#status-line)，默认是模型及其推理强度、工作目录和会话标题；状态栏没有可显示的项目时显示 `? for shortcuts`。输入框为空且 Left 可以打开[指挥中心](#agents)时，后面接着显示 `← for agents`。回合进行中写的草稿改为显示 `tab to queue message`。

审批、提问以及 `/model` 和 `/mode` 的选择列表打开时，会暂时替换状态行和输入框。回合结束时，选择列表保持打开。各项设置（包括 `/providers` 和 `/mcp`）都在全屏的[设置中心](#config)中。

对话记录中，你的消息以 `›` 开头；工具调用在开始的位置显示为 `• Running 工具名: 对象`，并在原处就地变为 `• Called 工具名` 或 `• Failed 工具名`，输出只保留首尾各几行；`apply_patch` 会显示修改的差异；思考显示为 `• Thinking 3.4s`，之后变为 `• Thought · 20.7s`（[思考过程](#thinking)）；任务计划显示为 `• Updated Plan · 1/5 complete` 和它的步骤；错误以红色的 `■` 开头。一段工具调用之后，回答之前会有一条 `─ Worked for 1m 05s ─` 分隔线，回合思考过时为 `─ Worked for 1m 05s · thought for 20.7s ─`。

## 输入框 [#composer]

- **粘贴**：超过 1000 个字符的粘贴内容在输入框中显示为 `[Pasted Content 1234 chars]` 占位符，发送时展开；删除占位符就删除了这段粘贴。
- **历史**：Up/Down 翻看的是本次运行中发送过的消息（包括被 Ctrl-C 清空的草稿），不包括恢复的会话中的旧消息。
- **引导正在运行的回合**：回合进行中按 Enter 发送的消息交给正在运行的回合，模型在下一步读到它：正在进行的工具调用完成之后，或者给出回答之后，回合会接着进行。在此之前，它显示在输入框上方的 `Messages to be submitted after next tool call (press esc to interrupt and send immediately)` 之下；模型读到之后，它才写入对话。多条消息按顺序发送。回合还没开始时按 Enter，消息会排入队列（见下文）。
- **排队消息**：回合进行中按 Tab，消息排入 `Queued follow-up inputs`；没有回合运行时，Tab 和 Enter 一样直接发送。用 Tab 输入的命令和 Enter 一样立即执行。回合结束后，排队的消息从最早的一条开始，每条各开始一个回合，依次进行，回合失败后也一样。Shift+Left（或 Alt+Up）把最后一条排队的消息放回输入框，放在草稿之前，供你修改。
- **不会丢失消息**：回合没有读到的补充消息（回合先结束了、失败了，或 Agent 拒收了这条消息）会在回合结束时发送，等待期间显示在 `Messages to be submitted at end of turn` 之下；多条会合并成一条消息，先于排队的消息发送。
- **中断**：有补充消息在等待时按 Esc，会中断回合并立即把它们合并成一条，作为下一个回合发送（`Model interrupted to submit steer instructions.`）；队列和你的草稿保持不变。Ctrl-C，或没有补充消息等待时按 Esc，只中断、不发送：等待中的消息（补充消息、等待回合结束的消息和排队的消息）回到输入框，每条一行，放在草稿之前。
- **每个对话各有一个队列**：主对话、[旁路对话](#side)和正在显示的[子代理](#subagents)各自排队，在后台的对话也会继续处理它的队列。旁路对话关闭或离开子代理时，它等待中的消息随之丢弃。有回合运行或有消息等待时，不能把对话切换到另一个会话（`/new`、`/resume`、编辑之前的消息）。

- 除 `/model`（`forget`）、`/permissions`、`/role`、`/rename`、`/resume`、`/fork`、`/review`、`/side`、`/goal`、`/export`、`/cd`、`/clear`、`/compression`（`cache`）、`/raw`、`/config`、`/providers`（`policy`）、`/mcp`、`/statusline`、`/title` 和 `/keymap` 外，命令不带参数。`/compact now` 这样在名字后面写了内容的消息会作为普通消息发给模型；`/model` 后面跟 `forget` 以外的内容时，会提示 `Usage: /model [forget]`。`/mcp` 后面跟 `verbose` 或 `login ID` 以外的内容时，会提示 `Usage: /mcp [verbose | login ID]`；`/providers` 后面跟 `policy` 以外的内容时提示 `Usage: /providers [policy]`，`/compression` 后面跟 `cache` 以外的内容时提示 `Usage: /compression [cache]`。
- `/raw` 立即生效并保存（`tui.rawOutput`），下次启动时沿用。Fullscreen 下整个对话以原始形式重新显示；Scrollback 下已经写入滚动历史的内容保持不变，只有之后的内容是原始形式。`/raw` 后面跟 `on`、`off` 以外的内容时，会提示 `Usage: /raw [on|off]`。
- `tui.fullscreenTranscript`（`/tui`）从下次启动起生效：正在运行的界面保持当前方式。届时 `--no-alt-screen` 和 `tui.alternateScreen` 仍然适用。
- 命令或它打开的列表因内部错误（panic）失败时，该命令在本次运行的剩余时间内关闭：对话中显示 `'/x' failed and is turned off for the rest of this run`，命令列表不再列出它，再输入它会提示它已关闭。会话、输入框和其他命令照常工作。聊天本身（输入框、对话内容、流式回答）的内部错误仍会结束界面，结束前会恢复终端状态。

## 会话命令 [#session-commands]

- **`/rename`** 打开一行输入框，填有会话的标题。输入框打开时，会请会话的模型根据目前的对话给出一个标题：它显示在输入框下方（`Suggested: …`），按 Tab 填入输入框。Enter 重命名，Esc 取消。`titles` 插件关闭或无从建议时，会显示 `No title suggestion`。`/rename 名字` 直接重命名。没有会话时，`/rename` 会先创建一个。
- **`/archive`** 和 **`/delete`** 会先确认（默认选中“No”一项）。之后界面与 `/new` 之后一样没有会话。归档的会话可以在恢复选择器的归档列表（Tab）中找到，在那里按 Ctrl+A 或 Enter 恢复。删除无法撤销，会一并删除会话的子会话。见[会话](/docs/sessions#archive-delete)。
- **`/fork [名字]`** 在会话最新提交的记录处分叉：副本带有完整的对话，界面之后在副本中继续，原会话保持原样。给了名字时副本使用这个名字。工作目录位于 Git 仓库中且 `worktree` 插件在运行时，会先询问副本在哪里运行：Fork here（在这里），或 Fork into a new worktree（在新的工作树中），后者就是 `/worktree` 的 Continue this conversation（[见下文](#worktrees)）。
- **`/clear [名字]`** 在 Scrollback 下清空终端的滚动历史和屏幕，在 Fullscreen 下清空对话，然后与 `/new` 一样离开会话。给了名字时，下一条消息创建的会话使用这个名字。
- **`/export`** 提供 Copy to clipboard（复制到剪贴板）和 Save to file（保存到文件）。保存时会询问文件名，默认是第一个工作区目录下的 `hanafubuki-agent-session-ID.md`。`/export 路径` 直接保存到该路径。相对路径以第一个工作区目录为基准（不展开 `~`）；已有的文件不会被替换，导出会失败。格式见[会话](/docs/sessions#export)。
- **`/copy`** 提供整个最后回答（Markdown）、每个围栏代码块（原样，不含围栏）和每段引用（不含 `>`）；Fullscreen 下还有 Select in the transcript（在对话中选择）：对话中出现一个光标，方向键移动它，v 或空格开始选择，y 或 Enter 复制，Esc 或 q 退出。回答从会话的历史中读取，所以恢复的会话的最后回答也能复制。
- **`/ps`** 把会话的后台终端写入对话：每个命令、它的状态（和退出码）、目录和最后三行输出。**`/stop`**（或 `/clean`）先确认，然后停止全部后台终端，并说明停止了几个；没能停止的会单独报告。
- **`/recap`** 先写出 `Writing a recap…`，再写出回顾：对话是关于什么的、进展到哪里，有待回答的问题或约定的下一步时，以 `Next:` 给出。它读取最近的几轮交流，不含工具输出，不会向会话提交任何内容。`recap` 插件关闭时，会说明回顾不可用及原因。
- **`/init`** 把一段固定的提示作为你的消息发送：写一份 `AGENTS.md`，即仓库的简短贡献指南（结构、命令、风格、测试、提交约定），已有的 `AGENTS.md` 保持不变。提示来自 Codex。

## 角色 [#role]

会话的[角色](/docs/roles#sessions)收窄它可以使用的东西：它的工具、为它贡献内容的插件、最宽松的权限模式。新会话的角色是 `--role` 指定的那个，否则是 `default`。

- **`/role 名字`** 在下一个轮次之前给会话这个角色：它的指令、它设置了的模型和推理强度，以及它的收窄。对话中显示 `Role set to 名字`。没有任何来源定义的角色、或不可用的角色会被拒绝，并列出可用的角色。**`/role default`** 再去掉所有收窄。
- 单独的 **`/role`** 列出可用的角色及其描述的第一行，会话当前的角色被标出；选中的那个按 `/role 名字` 的方式设置。
- 轮次进行中不可用。没有会话时，`/role` 会先创建一个。
- 角色显示在 `/status` 中，也可以用状态栏的 `role` 项显示。

## 权限 [#permissions]

权限模式一开始是配置中的模式（`permissionMode` 或 `--permission-mode`）；见[权限](/docs/permissions#modes)。

- **`/permissions`** 列出 Codex 的[预设](/docs/permissions#presets)，每个都是一个权限模式加一个沙箱模式：Read only（手动，`read-only`）、Default（手动，`workspace-write`）、Auto-review（自动审查，`workspace-write`）和 Full access（完全访问，没有沙箱）。生效的预设被选中：会话自己的模式，否则是配置的模式；两者组成不了预设时，不选中任何一个。选择 Full access 时会先确认（默认选中 Cancel）。这台机器没有沙箱时，需要沙箱的预设不能选择。选中一个预设会为本会话同时设置两种模式。没有会话时，`/permissions` 会先创建一个。
- **`/permissions read-only`** 或 **`/permissions default`** 直接设置这个预设。**`/permissions manual`**、**`/permissions auto-review`** 或 **`/permissions full-access`**（也可以写 `auto_review` 和 `full_access`）只直接设置权限模式，不再确认，沙箱保持不变：模式的名字不会被当作预设。
- 这些模式只属于本会话，直到界面退出：`permissionMode` 和 `sandboxMode` 保持不变，其他会话和分叉出的会话仍使用配置的模式，已经在运行的回合保持它开始时的模式。见[单个会话的模式](/docs/permissions#session-mode)和[单个会话的沙箱](/docs/permissions#session-sandbox)。
- **`/approve`** 列出本会话中被自动审查拒绝的操作，最新的在前：每个都有摘要和审查给出的理由，可以搜索。界面为每个会话保留从打开它起最近的十个，所以恢复的会话不会列出之前的拒绝。选中的操作会获得批准：模型从下一次请求起看到这次批准，重试仍要经过审查（[批准被拒绝的操作](/docs/permissions#approve-denied)）。没有被拒绝的操作时，会显示 `No denied actions to approve.`。回合进行中 Agent 会拒绝批准，对话中会说明原因。

## 工作目录和工作树 [#worktrees]

- **`/cd [路径]`** 把 `路径` 设为工作目录：第一个工作区目录，后面跟着它的 Git 根目录和 `--add-dir` 指定的目录。相对路径以当前工作目录为基准；`~` 和 `~/…` 表示主目录，只输入 `/cd` 也是。会话在那里继续：它的下一个回合在新的工作区目录中工作。回合、压缩或后台终端正在运行时，以及目录不存在时，Agent 会拒绝，对话中会说明原因，什么都不会改变。
- 项目配置不会跟随 `/cd`：它的信任级别和项目的 `config.toml` 仍是界面启动时读取的那些，直到重新启动界面。
- **`/worktree`** 在工作目录位于 Git 仓库中且 `worktree` 插件在运行时打开一个菜单（否则说明为什么不可用）：
  - **Continue this conversation**（继续当前对话）新建一个工作树，把会话分叉到其中（[工作树](/docs/sessions#worktrees)），把工作目录切换过去，之后在分叉出的会话中继续。还没有对话时，这一项不可选。
  - **Start a new conversation**（开始新对话）新建一个工作树并把工作目录切换过去，此时没有会话：你的下一条消息创建的会话归属于这个工作树。
  - **Browse worktrees**（浏览工作树）列出仓库的工作树，每个都带有提交、分支（新建的显示 `detached`）和所属会话。选中一个后可以选择 Resume session N（恢复会话）、Copy path（复制路径）和 Remove worktree（删除工作树）；删除前会先确认（默认选中 Cancel），会删除检出的文件及其本地修改，会话保留。工作目录所在的工作树不会被删除：先用 `/cd` 离开它。
- 新建工作树之后的某一步（分叉、切换目录）失败时，工作树会保留，对话中会说明它的位置；可以在 Browse worktrees 中删除它。

## 首次设置 [#setup]

界面启动时如果没有默认 Provider（没有配置，或者都未启用），或者没有为新会话选择模型（也没有用 `-m` 指定），它会在 Provider 处打开[设置中心](#config)，而不是让第一条消息失败：

- 没有 Provider：按 `a` 添加一个。填写名称、协议、基础 URL 和令牌，再选择 **Add a Provider**：第一个 Provider 就是默认的。在它上面按 Enter 打开它的记录，其中 **List models** 测试它，**Choose the model** 列出它的模型：选中的模型和这个 Provider 就是新会话使用的。
- 有 Provider 但都未启用：打开其中一个的 **Enabled**，或添加一个。
- 有默认 Provider 但没有模型：选择它的 **Choose the model**。

按 Esc 返回上一页，在标签页上关闭设置中心，输入框随即可用。设置完成前发送的消息会留在输入框中，对话中有一行说明原因，设置中心会再次打开。选好模型后，下一条消息就会创建会话。`/new` 会像启动时一样重新检查。

## 表单 [#forms]

设置中心各页面中的表单（插件的选项和设置、预设、手动输入的模型 ID）使用这些按键：

| 按键               | 作用                                   |
| ------------------ | -------------------------------------- |
| Tab、Down          | 下一个字段；在最后一个时回到第一个     |
| Shift+Tab、Up      | 上一个字段；在第一个时回到最后一个     |
| Enter              | 下一个字段；在操作（**Save**）上执行它 |
| Space、Left、Right | 切换选项或开关（`[x]`）                |
| Esc                | 返回                                   |

- 文本字段使用与输入框相同的编辑键。每个字段有自己的剪切缓冲区（Ctrl-K、Ctrl-U、Ctrl-W，然后 Ctrl-Y），从机密字段中删掉的文本不能粘贴（yank）到另一个字段。
- 机密值显示为圆点，只在输入时显示最后一个字符。粘贴的文本进入当前获得焦点的字段，换行会被去掉。
- 字段有问题时，会在它下方用红色说明，焦点也移到那里。保存时 Agent 拒绝的内容会显示在表单下方，表单中填写的内容保留。

## Provider [#providers]

`/providers` 在[设置中心](#config)打开 Provider：每一项显示协议和基础 URL，默认的一项旁标有 `default`，停用的旁标有 `off`。Provider 的记录包含它的字段（已设置的令牌显示为 `••••`，不会显示令牌本身）以及动作 **Make default**、**List models**（用于测试）、**Choose the model** 和 **Delete**。`/providers policy` 打开模型策略。字段和模型页面见 [Provider 与模型](/docs/providers-models#interface)。

## 插件 [#plugins]

`/plugins` 打开插件浏览器（对应 Codex 的插件目录），它是[设置中心](#config)的一个页面（Plugins 中的 Plugin browser），有三个标签页，用 ←/→ 切换：**Installed**（已安装）、**Marketplaces**（市场）和 **Built-in**（内置）。每个改动立即保存；进行中时页面会显示（`Installing…`），完成后重新读取全部内容。对应的命令见[命令行参考](/docs/cli-reference#plugins)。

- **Installed** 列出[已安装插件](/docs/cli-reference#plugins)：每个插件的状态、版本、需要审查的 hook 和问题。空格启用或停用选中的插件；Enter 打开它（它的来源、版本、格式、Skill、MCP 服务器、hook、[角色](/docs/roles#plugins)和问题）；`o` 打开代码插件的选项，前提是它的 `configSchema` 能降低为选项（即下面的通用选项表单；保存时写入它的设置，选项未描述的键保留，并重新启动它的代码）；**Install from a directory…** 要求输入一个插件目录，按 `<名字>@local` 安装。
- 插件页面提供 **Disable plugin** 或 **Enable plugin**、有 hook 等待信任时的 **Trust its N hook(s)**、代码插件的权限未授予时的 **Grant its permissions**（说明它的代码能访问什么；**Code** 一行显示它的访客状态）、代码插件的 **Settings**（一个以单个 JSON 对象编辑其设置的表单，按清单的 `configSchema` 校验；留空表示移除；它的代码以新设置重新启动）、**Update plugin**（从它的市场或目录重新安装）、**Retry plugin**（重新加载，并再次启动失败的访客）和 **Uninstall plugin**（会询问是否保留它的数据目录）。下面列出它的来源、版本、格式、Skill、MCP 服务器、hook 和问题。
- **Marketplaces** 列出已添加的市场，每个显示来源和其中已安装的插件数量。Enter 打开一个市场：列出它的插件，标为 **Available**、**Installed**、**Disabled** 或 **Not installable**；在未安装的插件上按 Enter 显示 **Install plugin**。Ctrl+U 升级 git 市场，Ctrl+R 确认后删除市场。**Add a marketplace…** 要求输入来源：`owner/repo`、git URL 或本地市场目录。
- 安装带 hook 的插件后，会列出这些 hook 的命令并询问是否信任（**Trust them**，或 **Not now**：之后在 `/hooks` 或插件页面信任）。hook 只有被信任后才会运行。
- **Built-in** 列出编译进 Agent 的插件（以及宿主的插件）及其状态和摘要：空格或 Enter 启用或停用（`disabledPlugins`；核心插件不能停用），`r` 重新启动失败的插件，`o` 打开有选项的插件的选项（`[pluginOptions.名字]`）。
- **选项表单**是通用的：插件的每个选项一个字段，标签为它的摘要和键，形式为开关、数字（占位符显示它的界限）、选择、文本（机密时显示为圆点）或用逗号分隔的文本列表。保存时按写入的方式检查每个值，不合适的字段下显示原因；只写入改动过的值，写入用户的 `config.toml`（内置插件的 [`[pluginOptions.NAME]`](/docs/config-reference#plugin-options)，代码插件的 [`[plugins."ID"].settings`](/docs/config-reference#plugins)），插件立即接受它们。这些选项同样是设置中心 Plugins 标签页中该插件自己分节的行。

Esc 返回上一页，在标签页上回到设置中心。用 `--safe-mode` 启动时，浏览器会提示没有加载任何已安装插件。

## MCP 服务器 [#mcp]

`/mcp` 在[设置中心](#config)打开 MCP 服务器（在 Tools 中）：每一项显示命令或 URL、连接阶段、连接后的工具数量和最近的错误。服务器的记录包含传输方式、环境变量或 HTTP 头、协议模式和各项策略（包括按工具的策略），以及动作 **Delete**、**Connect**、**Disconnect**、**Refresh**、**Log out** 和 **Log in**（打开它的 OAuth 登录）。它的机密在旁边的 **MCP secrets** 中。启用的已安装插件运行的服务器是同样在旁边的 **Plugins' MCP servers**：每一项显示所属插件、连接阶段和工具，你可以启用或停用它，只保留某些工具或去掉某些工具（`[plugins."ID".mcpServers.NAME]`，[插件](/docs/config-reference#plugins)）；它如何运行仍由插件决定，`/mcp verbose` 也会列出它们。见 [MCP](/docs/mcp#interface)。

## 评审 [#review]

`/review` 打开评审目标的选择器：**Review uncommitted changes**（未提交的改动：已暂存、未暂存和未跟踪的文件）、**Review against a base branch**（相对基础分支：仓库的本地分支，当前分支标为 `(current)`，可搜索）、**Review a commit**（一个提交：最近 100 个提交，可按标题或哈希搜索）和 **Custom review instructions**（自定义要求：一行输入框）。在列表中按 Esc 回到预设。不在 Git 仓库中时，基础分支和提交两项不可用，并显示原因。`/review 要求` 直接按你的要求评审。评审如何运行见[会话](/docs/sessions#reviews)。

- 评审会把结果报告回对话，所以会话必须已经有过一个回合：发送第一条消息之前，`/review` 会提示 `Send a message first; a review reports back into a conversation.`。回合进行中或另一个评审运行时，不会开始评审。
- 评审运行时，对话中显示 `>> Code review started: … <<`，状态行显示 `Reviewing …`。按 Esc、Ctrl-C 或输入 `/review cancel` 取消它（`<< Code review cancelled >>`）。这期间你发送的消息显示在输入框上方的 `Messages to be submitted at end of turn` 之下，评审结束后再发送，这样它开始的回合能读到评审的发现。有这样的消息等待时，Esc 不会取消评审（会给出提示）：Ctrl-C 会取消，并把消息放回输入框。
- 评审结束后，`<< Code review finished >>` 之后依次是结论及其置信度、说明，以及每条发现：优先级和标题、文件和行，以及正文。
- `review` 插件关闭时，`/review` 会说明评审不可用及原因。

## 目标 [#goal]

`/goal 目标内容` 为会话设置目标（[会话](/docs/sessions#goals)）；`/goal --tokens N 目标内容` 同时设置 token 预算（`200000`、`200k`、`2m`）。会话的目标尚未完成时，会先询问 **Replace goal?**（替换目标？），默认选中保留当前目标。Agent 从你的下一条消息起推进目标；在回合进行中设置的目标，会在该回合的下一个回答时被接手。

- 只输入 `/goal` 时显示目标：目标内容、状态、已用 token（及预算）和已用时间，以及可做的操作：**Pause goal**（暂停，活动的目标）或 **Resume goal**（恢复，暂停或阻塞的目标）、**Edit objective**（编辑目标内容）、**Set token budget**（设置 token 预算）和 **Clear goal**（清除目标）。没有目标时会说明，并给出用法。
- `/goal pause`、`/goal resume` 和 `/goal clear` 直接执行；`/goal edit` 打开填有目标内容的输入框。编辑目标内容或设置预算都会重新设置目标：用量从零开始。
- 没有会话时，`/goal` 会先创建一个。`goal` 插件关闭时，会说明目标不可用及原因。
- [状态行](#status-line)的 `goal` 项显示目标：打开会话时读取，之后随每次 `/goal` 以及回合中会话的事件更新。

## 钩子 [#hooks]

`/hooks` 打开钩子浏览器，它是[设置中心](#config)的一个页面（Tools 中的 Hook review）：列出[钩子](/docs/configuration#hooks)事件，每个事件显示它有几个钩子、几个在运行（已信任且开启）、几个需要审查，下方列出配置中被跳过的内容及原因。Enter 打开一个事件：每个钩子显示它的 matcher 和命令、信任状态（`trusted`、`new, review required` 或 `modified since trusted, review required`）、是否开启、配置它的文件和超时。空格或 Enter 开启或关闭选中的钩子，`t` 信任它，Esc 返回，在事件列表上回到设置中心。在事件列表中，`t` 经确认后信任所有需要审查的钩子。每个改动立即保存，作为 Hooks 集合的动作（Tools 标签页，每个钩子的记录显示它完整的定义：命令、超时、状态消息和写在哪里），之后重新读取钩子。钩子在它的文件中定义，从不在设置中心定义。

界面启动时如果有需要审查的钩子（新的，或信任之后被修改的），对话中会显示 `N hooks need review: /hooks`，并记下这条警告；不会有任何东西等你处理。

## 旁路对话 [#side]

`/side`（或 `/btw`）打开会话的[旁路对话](/docs/sessions#side)：在会话旁边临时开的一段对话，用来快速问一个问题，而不打扰会话正在做的事。`/side 问题` 打开它并把问题发到那里。会话必须已经有过回合：在你发送第一条消息之前，`/side` 会提示 `'/side' is unavailable until the current conversation has started.`。[评审](#review)运行期间，或会话的上下文正在压缩时，也会拒绝打开。

- **Fullscreen**：旁路对话是停靠在对话右侧的窗格，有自己的对话、输入框和状态栏；每个窗格顶部有一行标题，两个窗格之间有分隔线。窗格打开时获得焦点。它的消息发给旁路会话，主对话的消息发给主会话，两边都保持运行：一边的回合在你于另一边输入时继续进行。屏幕窄于 100 列或放大（`leader z`）时，获得焦点的对话占满屏幕，上方显示它的标题。用鼠标拖动分隔线，或用 `leader <` 和 `leader >`，调整窗格宽度；`leader =` 让两个窗格等宽；在另一个窗格中单击会让它获得焦点。
- **Scrollback**：界面切换到旁路对话：先在回滚区写入 `Side conversation · Esc returns · /side close closes it`，再写旁路对话。这期间主对话写出的内容会先保留，回到主对话时再写入。
- **返回和关闭**：在空输入框上、没有任务运行时按 Esc（`chat.edit_previous` 的按键），或 `leader left`，回到主对话。旁路对话保持打开：`/side`、`leader right` 或 `leader tab` 会再次显示它，连同它的记录和草稿。`/side close` 或 `leader x` 关闭它：中断它正在运行的回合并丢弃这个会话（`Side conversation closed.`）。主对话切换到别的会话时（`/new`、`/resume`、`/fork` 等），它也会被关闭。
- 旁路对话中的**命令**是 Codex 在那里允许的那些：`/copy`、`/agents`、`/export`、`/raw`、`/diff`、`/mention`、`/status`、`/warnings`、`/pwd` 和 `/side`。弹出列表只列出这些；其他命令会提示 `'/x' is unavailable here; Esc returns to the main conversation.`。旁路对话中之前的消息不能编辑。

窗格的按键是[按键映射](#keymap)中的动作，默认是前导键（Ctrl-X）再按一个键：

| 按键     | 动作                                                    | 作用                                               |
| -------- | ------------------------------------------------------- | -------------------------------------------------- |
| `left`   | `global.focus_pane_left`                                | 回到主对话                                         |
| `right`  | `global.focus_pane_right`                               | 让旁路对话获得焦点                                 |
| `tab`    | `global.toggle_side_conversation`                       | 切换到另一个对话                                   |
| `<`、`>` | `global.move_divider_left`、`global.move_divider_right` | 移动分隔线（Fullscreen）                           |
| `=`      | `global.equalize_pane_widths`                           | 让两个窗格等宽（Fullscreen）                       |
| `z`      | `global.toggle_pane_zoom`                               | 只显示获得焦点的窗格，或恢复两个窗格（Fullscreen） |
| `x`      | `global.hide_pane`                                      | 关闭旁路对话，或离开正在显示的子代理               |

在 Fullscreen 中，打开了第二个对话时，前导键等待第二个键期间，获得焦点的窗格中会有一个方框列出这些按键。

## 子代理 [#subagents]

`/subagents` 把会话的[子代理](/docs/sessions#subagents)写入对话，每个都带有状态（`running`、`idle` 或 `failed`）和它最近一次回答的开头，然后打开它们的列表；有子代理在运行时，列表会跟着它们的状态更新。Enter 用选中的子代理代替会话显示，上方是 `Subagent NAME · from PARENT · Esc or ctrl-x left returns`：它的记录和 `/resume` 显示的一样；它在运行时，它的回合会继续显示（回答逐步输出，工具调用逐个出现，它等待的批准在那里询问，包括显示它之前就已提出的批准，Esc 中断它）。在那里发送的消息发给这个子代理。

- 在空输入框上、没有任务运行时按 Esc，或 `leader left`、`leader x`，回到会话；会话自己的回合在这期间一直在继续。
- 在 Fullscreen 中子代理占满屏幕；在 Scrollback 中界面切换到它，和[旁路对话](#side)一样。它可用的命令和旁路对话相同。打开了旁路对话时不能显示子代理：先关闭旁路对话。
- **子代理的审批**：子代理使用父会话的权限模式，所以在 Manual 模式下它的工具调用要等你确认。会话的子代理在运行时（或会话的回合在运行时），界面大约每 0.4 秒读取一次它们的状态，把子代理等待的审批作为普通的[审批](#approvals)显示，摘要以 `Subagent NAME:` 开头；你的回答发给这个子代理。会话自己的回合结束时它仍然保留，在别处（正在显示的子代理中）回答后或子代理的回合结束时关闭。旁路对话获得焦点时，它在主对话中等待：Fullscreen 中主对话的窗格会显示它，Scrollback 中回到主对话时才看得到。

## 指挥中心 [#agents]

`/agents`、在空输入框上按 Left（此时底栏显示 `← for agents`）或 `global.open_agents`（没有默认按键）会在整个屏幕上打开指挥中心（Scrollback 中使用备用屏幕）。只有在输入框获得按键且为空、没有打开弹出列表、这个对话中可以运行 `/agents`，并且 Left 仍是 `editor.move_left` 的按键时，Left 才会打开它；否则 Left 和以前一样移动光标。

它列出没有父会话的会话，和恢复会话选择器一样；每个会话的状态是它自己和它的子会话（子代理和评审）中最紧急的那个：

- **Needs input**（红色 `●`）：会话或它的某个子会话在等待[审批](#approvals)或[提问](#questions)的回答。
- **Error**（红色 `!`）：它自己的最近一个回合失败了。
- **Working**（绿色 `●`）：有回合在运行。
- **Ready**（青色 `○`）：最近一个回合已完成。
- **Inactive**（暗色 `○`）：最近一个回合被中断或取消。回合失败的子会话算作 Inactive：它的失败不需要你处理。

会话按标题分组，标题后是数量（筛选隐藏了一部分时显示为 `2 of 5`）：按项目、目录、状态或模型分组，由 `tui.agentsGrouping` 决定。项目是会话目录在仓库主检出中对应的目录，所以仓库某个工作树中的会话归入创建这个工作树的检出。同一标题下最近的会话在前。正在显示的会话标有 `(shown)`，打开指挥中心时选中它。向下滚动时会读取更多会话。

- **置顶**：在已读取的会话中，你置顶（`p`）的会话排在最前，位于 `Pinned` 标题下，无论按什么分组。
- **未读**：自上次显示以来有变化（它自己或它的某个子会话）的会话标题加粗；不需要你处理时显示蓝色 `●`。主对话显示一个会话时，以及指挥中心在显示它时打开，都算显示过它；从未在这里显示过的会话不会标为未读，在指挥中心里做的重命名或恢复也不算新变化。
- **隐藏**：`h` 把会话从所有标签页中隐藏。搜索会再次列出它，标有 `(hidden)`；打开它就会重新显示。

置顶、隐藏的会话以及每个会话上次显示的时间属于界面自己，保存在数据目录的 `tui-state.json` 中（[数据目录](/docs/data-directory#contents)）；会话本身对此一无所知。

宽度达到 90 列时，列表旁的详情面板会显示选中会话的更多信息：标题和状态、模型和推理强度、分支和已用 token、目录；它的子会话（子代理和评审）及其状态；它和它的子会话中最紧急的那个在等你做什么（审批的对象或提问）以及正在做什么；它最近的回答（`Last message`）和引出这个回答的消息（`Prompt`）。`c` 把按键交给它的子会话：Up 和 Down 选择，Enter 或 Right 像 [`/subagents`](#subagents) 那样在父会话旁显示这个子会话，`x` 中断子会话的回合（子代理通过子代理自己的中断，这样它仍能接受后续任务），Esc、Left 或 `c` 回到会话列表。不足 90 列时，子会话获得按键期间，详情面板代替列表显示。

| 按键                          | 作用                                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------- |
| Up、Down（`k`、`j`）          | 移动选择；越过一端时到另一端                                                                        |
| Page Up、Page Down、Home、End | 移动一页，或到第一个、最后一个会话                                                                  |
| Enter、Right                  | 用这个会话代替正在显示的会话。在 Archived 中恢复它                                                  |
| Tab、Shift-Tab、`1`–`6`       | 筛选：All、Needs you、Working、Ready、Inactive、Archived，除 Archived 外都显示数量                  |
| `/`、F3                       | 搜索标题：输入的文字会缩小列表，Enter 打开选中的会话，Esc 结束搜索                                  |
| `n`                           | 离开正在显示的会话：下一条消息开始新会话                                                            |
| `w`                           | 进入新的工作树，和 `/worktree` 的“开始新对话”一样：下一条消息在那里开始会话（[工作树](#worktrees)） |
| `f`                           | 在会话的最新位置分叉，并在副本中继续                                                                |
| `r`                           | 重命名会话：就地编辑标题，Enter 保存，Esc 取消                                                      |
| `x`                           | 中断会话的回合                                                                                      |
| `p`                           | 置顶会话，或取消置顶                                                                                |
| `h`                           | 隐藏会话                                                                                            |
| `c`                           | 把按键交给详情面板中会话的子会话（见上文）                                                          |
| `a`                           | 先确认，再归档会话及其子会话；在 Archived 中恢复它                                                  |
| Backspace                     | 先确认，再删除会话及其子会话                                                                        |
| `g`                           | 切换到下一种分组：项目、目录、状态、模型，并保存到 `tui.agentsGrouping`                             |
| `?`                           | 显示按键说明                                                                                        |
| 点击、滚轮                    | 点击标签页显示那个筛选，点击会话或子会话选中它，点击已选中的那个打开它；滚轮移动三行                |
| Esc、`q`                      | 关闭指挥中心                                                                                        |

确认框默认选中 Cancel：Up 或 Down 选择，Enter 确认，Esc 取消。会话操作的按键（`/`、F3、`n`、`w`、`f`、`r`、`x`、`p`、`h`、`c`、`a`、Backspace 和 `g`）属于按键映射的 `agents` 上下文（[见下文](#keymap)）；其他按键保持不变。

打开、新建（包括在工作树中新建）和分叉会改变主对话，所以在它的回合运行期间会被拒绝。正在显示的会话用 `/archive` 和 `/delete` 归档和删除，不在这里操作。指挥中心从不等待读取：会话、它们的子会话和选中会话最近的一轮交流，都在它自己的线程上读取，时机是打开时、滚动时和每次操作后。指挥中心打开期间，这个线程还会每秒四次查看 Agent 持有的会话：每个会话的变化、它在等待的审批或提问，以及它正在做什么。有变化的内容会重新读取，指挥中心不需要按键就会跟着更新：没有父会话的会话变化时重读列表，子会话变化时重读其父会话的子会话，选中的会话变化时重读详情。外观层（facade）没有覆盖所有会话的事件流，所以这里的查看和[子代理的查看](#subagents)一样，读取会话的当前状态；Agent 没有持有的会话不会变化。

## @ 文件提及 [#mentions]

输入 `@` 和几个字符，会弹出工作区目录中模糊匹配的文件，最多 20 个。`.gitignore` 等忽略规则会生效，即使不在 Git 仓库中也是如此。按 Tab 或 Enter 把 `@...` 替换为文件路径：第一个工作区目录中的文件使用相对路径，其他目录中的文件使用完整路径，含空格的路径加引号。

发送的只是路径文本，模型会用自己的工具读取文件。

## 阅读对话 [#reading]

Fullscreen 下，对话会跟随最新输出，直到你向上滚动。向上滚动后，回合继续运行时视图停留在原处，输入框上方会出现 `↓ Back to bottom · esc` 控件（下方有新内容时为 `New activity · ...`），用它回到最新输出。

| 按键或操作                              | 作用                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 鼠标滚轮                                | 滚动三行                                                                                                           |
| Page Up/Page Down                       | 滚动一页                                                                                                           |
| Ctrl-Home、Ctrl-End（Alt-`<`、Alt-`>`） | 到会话开头（会读取更早的消息）或最新输出                                                                           |
| Esc、点击控件                           | 回到最新输出                                                                                                       |
| 输入框为空时按 Enter                    | 回到最新输出                                                                                                       |
| 拖动                                    | 选择文本；双击选择一个词，三击选择一行，Shift-点击扩展选择                                                         |
| Ctrl-Space                              | 用键盘开始选择；方向键和 Shift-方向键移动                                                                          |
| Ctrl-X `[`                              | 选择模式：对话中出现一个光标，用按键移动，选择并复制                                                               |
| Ctrl-C、Ctrl-Shift-C、Ctrl-Insert       | 有选择时：复制                                                                                                     |
| Enter                                   | 有选择时：复制并回到最新输出                                                                                       |
| 右键单击                                | 复制选择的内容                                                                                                     |
| Esc                                     | 有选择时：取消选择                                                                                                 |
| F3                                      | 查找文本：输入查询，Enter 接受匹配，Ctrl-P/Ctrl-N 转到更早或更新的匹配，Esc 取消                                   |
| 点击条目的控件或标题行                  | 显示或隐藏它的详情：在标题行的同一个格子上按下并松开，所以从标题行开始的拖动仍然是选择（见下文）                   |
| F4                                      | 聚焦最近的活动（工具调用、思考、任务计划、较长的消息）：Up/Down 在活动间移动，Enter 或点击显示或隐藏详情，Esc 离开 |
| Ctrl-T                                  | 就地显示整个对话的详细内容（每次思考的全文、工具调用的完整输出）；Ctrl-T 或 Esc 返回                               |

还有更多内容可显示的条目，下方单独一行带有控件：思考（它的文本）、输出比首尾几行更长的工具调用（`+ 12 lines`）或折叠显示的 `compress` 调用（`+ Show details`）、带说明或超过三个步骤的任务计划（折叠时显示三个步骤：先是进行中的，然后是待办的，最后是已完成的），以及超过 12 行的你的消息（折叠时显示前 12 行，`+ 8 lines`）。展开后控件变为 `− Hide details` 或 `− Show less`。没有更多内容的条目没有控件。条目的标题行是它第一行有文字的行（消息的第一行）：点击标题行也会切换，紧接着的第二次点击会再切换回来，而不是选择一个词。每个条目单独展开，进行中的条目完成时保持原来的状态。

选择、搜索或聚焦活动期间，对话下方的底栏会显示相应的按键。复制的内容放到系统剪贴板；没有系统剪贴板时（例如通过 SSH），内容发送给终端（OSC 52），大多数终端会把它放到自己的剪贴板上，界面会提示这次复制未经确认。复制的结果在输入框上方显示几秒钟。

审批、提问或列表打开时，按键由它们处理；鼠标仍然可以滚动和选择，Ctrl-C 仍然复制已选择的内容。

Fullscreen 会捕获鼠标，所以使用终端自己的选择时通常需要按住 Shift 拖动。要用终端的选择复制，可以用 `/raw` 显示不带样式的对话。

Scrollback 下，对话由终端保存：用终端滚动、选择和复制。最新的条目留在底部区域上方的尾部，排版与 Fullscreen 相同：思考和工具调用在其中就地更新，条目的控件（`+ 12 lines`、`+ Show details`）显示或隐藏它的详情。

- 尾部将要超过屏幕的 60%（至少 8 行）时，其中最早的已完成条目按显示的样子写入滚动历史；折叠且还有更多内容的条目末尾写有 `ctrl + t to expand`。回答超过上限时逐行写入。仍在进行的条目不会被写入：比尾部还高时，显示它的第一行和最新的几行。
- 你发送下一条消息时，先把尾部整个写入，所以已结束回合的条目在此之前都可以展开。在原处打开另一个会话（`/new`、恢复会话）、切换到另一个对话和调整终端大小时也会写入，退出时写入剩下的部分。
- 回合进行中尾部不会变矮：折叠一个条目会留下空行，直到下一次写入。
- 点击控件或条目的标题行显示或隐藏详情，按 F4 再按 Enter 也可以（Up/Down 在尾部的活动之间移动，Esc 离开）。
- 为了接收点击，尾部显示控件时界面会捕获鼠标。滚轮的第一次滚动把鼠标交还给终端，终端从下一次滚动起开始滚动，直到你按下一个键或出现下一个条目。按住 Shift 拖动仍由终端选择。设置 `tui.scrollbackMouse = "off"` 时从不捕获鼠标；按键和[对话记录](#transcript)仍然可用。
- 已经写入的条目在[对话记录](#transcript)（Ctrl-T）中展开。

会话的上下文每压缩一次，对话就在发生的位置显示 `• Context compacted`：`/compact` 之后，回合压缩上下文时（达到阈值、模型请求新上下文、Provider 报告上下文窗口错误之后），以及回合安装一个[在后台](/docs/config-reference#compaction)运行的压缩时。恢复的会话以同样的方式显示之前的压缩。回合运行的压缩失败时，对话显示一条警告 `⚠ Context compaction failed: …`，带着错误，[`/warnings`](#warnings) 会保留它；`/compact` 失败时改由它的回复说明（`the conversation was not compacted: …`）。被取消的压缩不显示任何内容。Provider 以请求过长为由拒绝、会话采用由此学到的窗口时（[上下文窗口与压缩](/docs/providers-models#compaction)），对话会在随后的压缩之前提示一次：`• The Provider refused the request as too long; this model's window is taken as 131072 from now on.`

## 分层压缩 [#compression]

在 `hierarchical` [压缩策略](/docs/configuration#compaction)下，模型用它的 `compress` 工具把对话中的片段折叠成它自己写的摘要。`compress` 调用以折叠的形式显示：标题行列出它折叠的范围及其主题（`• Called compress: m00002–m00005 Setup`），下面是它回执的第一行（`[Compressed m00002–m00005 → 1 block(s), ~8000 tokens saved.]`）。模型写的摘要和回执的其余部分是它的详情，在[对话记录](#transcript)、Fullscreen 下的 Ctrl-T 和 F4 中显示。恢复的会话以同样的方式显示它的 `compress` 调用。

`/compression` 读取会话的压缩情况，既不改变会话，也不询问模型：

- **面板**（来自 billion-context）：上下文相对窗口的占用、压缩之后发送的内容及其构成、折叠提醒及其给出的范围，以及每个活动块的层级、它替换的 token 数、摘要的大小和主题。下面是计数（已应用的 `compress` 调用、压缩和吸收的 token、存储和取回的工具结果），`contentStore` 开启时还有内容存储的大小。
- **`/compression cache`** 显示缓存报告：最近一次请求的 token 和每次折叠，以及折叠节省的量。Provider 的响应流不向 Agent 报告缓存命中的 token，所以都不计为缓存。
- 从未运行过该策略的会话会说明它没有使用分层压缩。

[状态栏](#status-line)的 `compression` 项显示活动块数和折叠掉的 token 数。

如果压缩在某次请求中失败（其算法发生 panic），对话会显示一条警告 `⚠ Context compression failed; this turn goes on with the full history: …`，回合余下部分按 `standard` 运行；[`/warnings`](#warnings) 会保留这条警告。

## 对话记录 [#transcript]

Scrollback 下，Ctrl-T 在终端的备用屏幕上打开整个会话的对话记录（`T R A N S C R I P T`），以紧凑方式显示，条目的控件显示它的详情（点击控件或标题行，或按 F4 再按 Enter，与[阅读对话](#reading)相同；Ctrl-O 切换每一次思考）；再按一次 Ctrl-T 显示每个条目的详细内容，第三次关闭。`/diff` 以同样的方式显示差异。Fullscreen 下，Ctrl-T 改为就地显示对话的详细内容（见上文），`/diff` 覆盖屏幕直到你关闭它。

| 按键                                 | 作用                       |
| ------------------------------------ | -------------------------- |
| Up/Down（`k`/`j`）                   | 滚动一行                   |
| Page Up/Page Down（Space、Ctrl-B/F） | 滚动一页                   |
| Ctrl-U/Ctrl-D                        | 滚动半页                   |
| Home/End                             | 到开头/结尾                |
| `q`、Esc、Ctrl-C                     | 关闭                       |
| Ctrl-T（对话记录）                   | 详细，再关闭               |
| Ctrl-O                               | 展开每一次思考，或全部折叠 |

详细内容中，对话记录显示每次思考的全文和工具调用的完整输出（滚动历史只显示输出的开头和结尾几行）。两种方式下，仍在进行的思考和工具调用都显示在它们开始的位置，并就地更新。其中的选择、复制和搜索与[阅读对话](#reading)相同（拖动、Ctrl-Space、F3）。

分页器打开期间回合继续运行，新内容立即出现在对话记录中，关闭后出现在尾部。

## 编辑之前的消息 [#edit]

输入框为空、没有回合运行、也没有打开任何列表或界面时，按 Esc 会显示 `esc again to edit a previous message`；按其他任意键则取消。再按一次 Esc 开始浏览你发过的消息，并高亮最近的一条：Fullscreen 下就地浏览，Scrollback 下在对话记录中浏览，两者都使用简洁视图。底部显示 `Browsing · ←/→ prompt · ↑/↓ scroll · ctrl+t details · ↵ edit · esc back`。

| 按键           | 作用                           |
| -------------- | ------------------------------ |
| ←/→（`h`/`l`） | 上一条或下一条消息             |
| ↑/↓（`k`/`j`） | 滚动一行                       |
| Ctrl-T         | 显示或隐藏详细内容             |
| Enter          | 编辑高亮的消息                 |
| Esc            | 回到开始浏览时的位置，不做编辑 |

Fullscreen 下，对话的其他按键（Page Up/Page Down、Home/End、F3）照常可用，按其他任意键则结束浏览；Scrollback 下对话记录的按键照常可用，`q` 关闭它。

Enter 在会话的副本中编辑：会话在这条消息所在回合之前分叉，界面切换到分叉出的会话，它的对话停在这条消息之前，这条消息回到输入框中，供你修改后发送。原会话被完整归档：`hanafubuki-agent sessions list --archived` 可以找到它（见[会话](/docs/sessions#edit)）。Agent 修改过的文件不会恢复，本次运行中第一次编辑时会提示这一点。消息附带的图片不会放回，因为输入框无法附加图片；会有一行说明有几张。

- 回合进行中发送的消息（补充消息）不是一个独立回合的开始，不能单独编辑：请编辑开始那个回合的消息。
- 回合运行时，Esc 和以前一样中断回合；在没有回合运行、也没有消息等待之前，编辑会被拒绝。
- 还没有发过消息时，第二次 Esc 显示 `No previous message to edit.`。Fullscreen 下只能浏览已加载的消息，向上滚动会加载更早的消息；Scrollback 下为恢复的会话最近 200 项中的消息。

## 思考过程 [#thinking]

模型的每一段思考（一个推理条目）都是单独的条目，位于对话中发生的位置，与回答和工具调用按顺序排列：一个先思考、调用工具、再思考然后回答的步骤显示四个条目。模型思考时它显示为 `• Thinking 3.4s`，以十分之一秒计数；这段思考结束时，它在原处变为 `• Thought · 20.7s`（超过一分钟时为 `1m 05s`）。

每个条目默认折叠为这一行，收到文本后带有 `+ Show details` 控件。点击控件或这一行本身（Fullscreen 下、Scrollback 下条目还在尾部时，以及在对话记录中），或按 F4 再按 Enter，会在下方以暗色的 Markdown 显示文本，模型仍在思考时随流更新；`− Hide details` 再将它隐藏。每个条目单独展开，完成时保持展开。Ctrl-O 一次展开对话中的每一次思考（Scrollback 下是尾部中的思考，对话记录打开时是其中的思考），全部已展开时则全部折叠；之后的思考仍然以折叠开始。

Provider 没有发送文本时只有这一行，没有控件。如果回合在思考结束前就结束了（出错或被中断），这一行以已经过去的时间结束。Scrollback 下，思考离开尾部时按显示的样子写入滚动历史，之后无法再更改；对话记录（Ctrl-T）仍可展开它，再按一次 Ctrl-T 显示每一次思考的全文，与 Fullscreen 下 Ctrl-T 的详细对话一样。恢复会话时，每一段思考以同样的方式重放，默认折叠；文本在 Agent 的上限处被截断的思考显示为 `• Thought · 20.7s (truncated)`。

[状态行](#layout)会加上整个回合的思考时间 `(Thinking 20.7s)`，回答之前的分隔线也会写明 `thought for 20.7s`。

能看到什么取决于 Provider 发送了什么：有的只发送思考摘要，有的发送原始思考文本，有的什么也不发送。见 [Provider 与模型](/docs/providers-models#reasoning)。

## 审批 [#approvals]

[权限模式](/docs/permissions)要求审批的工具调用会弹出确认框，标明操作类型（如 `Would you like to run the following command?`）、摘要和风险等级：

| 选项                                                                                | 按键       |
| ----------------------------------------------------------------------------------- | ---------- |
| `Yes, proceed`：允许这一次                                                          | `y` 或 `1` |
| `Yes, and don't ask again this session`：本会话内同类操作不再询问（仅在可用时提供） | `a` 或 `2` |
| `No`：拒绝                                                                          | `n` 或 Esc |

模型请求[在沙箱之外](/docs/permissions#escalation)运行的命令，会在摘要中说明这一点，并附上模型的问题（`… outside the sandbox in 目录: 命令 (reason: 问题)`）；对它选择本会话内允许，只允许这条命令以后在沙箱外运行。

也可以用 Up/Down 选择后按 Enter。Ctrl-C 拒绝当前请求以及排在后面的所有请求。其他请求会排队，依次弹出。对话记录中会留下 `✔ You approved ...` 或 `✗ You did not approve ...`。

子代理等待的审批也以同样的方式显示在它的父会话中，摘要以 `Subagent NAME:` 开头（[子代理](#subagents)）。

## 提问 [#questions]

模型可以向你提出一个或多个问题，每个问题都有几个选项。界面显示 `Question 1/2`、问题和选项：

- Up/Down（`k`/`j`）选择，Enter 确认并进入下一题，最后一题按 Enter 提交。
- 数字键直接选择对应的选项并前进。
- Left 回到上一题，Right 或 Tab 进入下一题。
- Esc 或 Ctrl-C 中断回合。

问题只能从选项中选择，不能输入自由文本。

## 恢复会话 [#resume]

```sh
hanafubuki-agent resume           # 打开恢复选择器
hanafubuki-agent resume 12        # 恢复会话 12
hanafubuki-agent resume --last    # 恢复最近一个运行过回合的会话
hanafubuki-agent resume 12 "继续" # 恢复后发送一条消息
```

恢复选择器按最后更新时间列出运行过回合的会话：更新时间、创建时所在的 Git 分支和目录（有会话带有它们时才显示），以及标题（还没有命名时是第一条消息）。子会话不列出。直接输入文字可以搜索标题，Up/Down 和 Page Up/Page Down 移动，Enter 恢复，Esc 返回（在 `resume` 启动时则回到没有会话的界面），Ctrl-C 退出。

- **归档的会话。** Tab 在会话和归档的会话之间切换。Ctrl+A 归档选中的会话；在归档列表中则是恢复它（在那里按 Enter 也会恢复），它随即离开列表。界面正在显示的会话不能在这里归档，要用 `/archive`。
- **在界面中。** `/resume` 打开选择器。`/resume ID` 恢复该 ID 的会话，`/resume 标题` 恢复唯一有这个标题的会话；没有或有多个会话使用这个标题时，选择器打开并搜索它。

恢复后，界面显示信息框和会话最近的 200 项记录：消息、模型提出的计划、工具调用及其输出、上下文压缩。Fullscreen 下，向上滚动到更早的记录时，每次读取 200 项（`↑ Loading earlier messages…`）；输出先于调用被读取的工具调用不显示输出。Scrollback 下更早的记录不显示，并提示 `Earlier messages are not shown.`。之后发送的消息接着这个会话继续。

没有可恢复的会话时，`resume --last` 与 `hanafubuki-agent` 一样以没有会话的状态启动。会话 ID 可以用 `hanafubuki-agent sessions list` 查看，见[会话](/docs/sessions)。

## 退出 [#quit]

输入 `/quit` 或 `/exit`，或者在 1 秒内按两次 Ctrl-C（输入框为空时也可以按两次 Ctrl-D）。退出时界面恢复终端状态（Fullscreen 下离开备用屏幕，对话也随之消失）并关闭 Agent，不额外打印内容。

退出码为 0；Agent 无法启动、要恢复的会话无法打开或无法设置 `-m` 指定的模型、终端无法使用时为 1；没有终端时为 2。

## 语法高亮 [#highlighting]

回答中的围栏代码（` ```rust `）按语言高亮：语言可以是名称、别名或文件扩展名。没有标明语言，或者语言界面不认识的代码块保持纯文本。差异（补丁的差异、`/diff` 的输出）按每个文件的扩展名高亮；`+` 和 `-` 保留各自的颜色，删除的行变暗。超过 512 KiB 或 10,000 行、或者有一行超过 4 KiB 的代码不做高亮。

语法和 32 个主题来自 [two-face](https://github.com/CosmicHorrorDev/two-face) 附带的集合（选自 bat）。`/theme` 在[设置中心](#config)打开主题页面，列出它们和自定义主题：

- 在列表中移动时，高亮的主题立即生效，并显示在一段示例差异上：终端较宽时在列表旁边，否则在列表下方。输入文字可以筛选列表。
- Enter 保留这个主题，并保存为 `tui.theme`。Esc 和 Ctrl-C 恢复打开列表时使用的主题。
- 自定义主题是[数据目录](/docs/data-directory#contents)下 `themes/` 目录中的 `.tmTheme` 文件，名字是去掉 `.tmTheme` 的文件名。无法作为主题读取的文件不会列出；与内置主题同名的自定义主题以内置主题为准。
- 没有设置 `tui.theme` 时使用 `ansi` 主题，它用终端自己的调色板着色，因此在浅色和深色背景下都清晰。`tui.theme` 指定的主题不存在，或者自定义主题无法读取时，会产生一条[警告](#warnings)，并使用默认主题。
- 对话中已经显示的内容保持绘制时的颜色。

| `app-name`      | `hanafubuki-agent`   |
| `project-name`  | 工作目录的名称       |
| `current-dir`   | 工作目录             |
| `activity`      | 回合运行时的旋转指示 |
| `run-state`     | `Ready` 或 `Working` |
| `session-title` | 会话标题             |
| `model`         | 模型                 |
| `task-progress` | `Tasks 2/5`          |

- 不带参数的 `/statusline` 或 `/title` 在[设置中心](#config)打开它的设置页面：上下键移动，空格打开或关闭高亮的项目，左右键调整它的顺序，Enter 保存（`tui.statusLine` 和 `tui.statusLineColors`，或 `tui.terminalTitle`），Esc 取消。状态栏的设置界面预览这一行，会话还没有的值用示例代替。标题的设置界面打开期间直接设置终端标题；Esc 会恢复原来的标题。
- 带参数时只对本次运行有效，不会保存。`/statusline git-branch context-remaining` 按这个顺序显示这些项目；`--colors` 和 `--no-colors` 打开或关闭颜色。`/title app-name model` 设置标题的项目；`/title --clear` 把标题交还给终端。不认识的项目会被拒绝，并列出所有项目。
- `[tui]` 中界面不认识的项目会被忽略，每个都产生一条[警告](#warnings)。
- 标题写入前会清理：删除控制字符和不可见的或双向文本格式字符，连续空白合并为一个空格，最长 240 个字符。在 GNU Screen 中（设置了 `STY`）只使用 ASCII。
- 第一次设置标题前，界面把终端原来的标题压入终端的标题栈（XTWINOPS），不再设置标题时和退出时再弹出恢复。不支持标题栈的终端会留下空标题。

## 按键映射 [#keymap]

下表中的每个动作都有默认按键，`tui.keymap.上下文.动作` 可以修改它们：一个按键或一组按键，`[]` 表示取消这个动作的绑定。动作先取它所在上下文中的设置，没有时取 `tui.keymap.global.动作`（只要没有同名的全局动作：`global.page_up` 同时设置 `transcript.page_up` 和 `pager.page_up`），再没有时使用默认按键。

```toml
[tui.keymap.global]
open_transcript = "ctrl-g"
leader = "ctrl-b"

[tui.keymap.chat]
toggle_thinking = ["ctrl-o", "f2"]
open_presets = "ctrl-b 1"

[tui.keymap.editor]
yank = []
```

- **按键**写作修饰键加按键，用 `-` 连接：`ctrl-t`、`alt-<`、`shift-enter`、`page-down`、`f3`、`space`、`minus`；大写字母等于 `shift-` 加这个字母。
- **组合键**是用空格分开的两个按键（`ctrl-g o`）：第一个键等待第二个键一秒钟。`leader K` 是前导键（`global.leader`，默认 Ctrl-X）再按 `K`；前导键会一直等到下一个键。没有完成任何组合的按键，或 Esc，会把两个键都丢弃。如果配置的某个按键正是默认前导键，它优先：除非 `global.leader` 另行设置，前导键就没有绑定。
- **上下文**是读取按键的地方：`global` 处处有效，`chat` 和 `composer` 在输入框获得按键时有效，`editor` 在所有文本输入框中有效，`transcript` 在 Fullscreen 的对话中（与输入框同时）有效，`pager` 在对话记录和 `/diff` 中有效，`agents` 在[指挥中心](#agents)中有效。在输入框旁边，不能绑定会输入文字的按键（不带 Ctrl 或 Alt 的字母），也不能绑定以它开头的组合键。
- **冲突**：同一个按键（或组合键）不能触发同时读取的两个动作，不能是另一个动作的组合键的开头，也不能是界面保留的 Ctrl-C（以及 Ctrl-D，编辑框和分页器中除外）。默认就共用按键的动作仍然允许：`chat.interrupt_turn` 和 `chat.edit_previous`（Esc）、`composer.submit` 和 `editor.insert_newline`（Enter）、历史和编辑框的 Up、Down、`global.open_transcript` 和 `pager.close_transcript`。
- 无法使用的设置（不认识的上下文或动作、不是按键的字符串、冲突）会让这个动作保留默认按键，并产生一条[警告](#warnings)。

`/keymap` 在[设置中心](#config)打开按键映射页面，列出所有动作及其按键（输入文字可以搜索）。选中一个动作后，可以替换它的按键或增加一个（一个按键、两个按键，或前导键加一个按键）、删除其中一个、取消绑定，或恢复默认按键。新的按键在按下时捕获（Esc 取消）；冲突的按键会被拒绝并说明原因，可以再换一个。修改保存到 `tui.keymap`，立即生效。`/keymap debug` 列出每个动作的按键，并标明 `default`（默认）或 `configured`（已配置）。

弹出列表、列表、表单、审批和提问保留它们自己的按键（方向键、Enter、Esc、Tab），对话中的选择、搜索和选择模式，以及浏览之前的消息也一样。

## 预设 [#presets]

预设是保存在 0 到 9 号位置中的一段输入（`tui.presets."N"`），可以带一个标签。运行时，它像输入后发送一样经过斜杠命令的解析，因此可以是一条消息，也可以是 `/status`、`/statusline git-branch --colors` 这样的命令。输入不能为空，不能超过 8000 字节，也不能以 `!` 开头。

`/presets`（或 Ctrl-X P）在[设置中心](#config)打开预设页面，列出所有位置；运行预设时先关闭设置中心：

| 按键    | 作用                                                                                          |
| ------- | --------------------------------------------------------------------------------------------- |
| `0`–`9` | 运行这个位置的预设                                                                            |
| Enter   | 运行选中的预设                                                                                |
| `n`     | 新建预设：位置（第一个空位）、输入和标签                                                      |
| `s`     | 从当前设置新建预设：会话的 `/permissions …`、终端标题的 `/title …` 或状态栏的 `/statusline …` |
| `e`     | 编辑选中的预设                                                                                |
| `d`     | 按 `y` 确认后删除选中的预设                                                                   |

本界面中 `/model` 不接受模型作为参数，所以模型不能做成预设。配置档、项目配置或 `-c` 中设置的预设优先于用户文件中的：保存到这个位置时会说明这一点。

## 设置 [#config]

`/config` 在整个屏幕上打开设置中心（Scrollback 下是备用屏幕），仿照 Codex 的 `/config`：Agent 的所有设置，从它的[设置目录](/docs/architecture#settings-catalog)读取，分在几个标签页中（General、Model、Tools、Memory、Context、Network、Interface、Plugins、Advanced；标签页会显示它有几个值存在问题）。每一行是标签 · 值 · 说明：`[x] On` 或 `[ ] Off`、选项的标签、数字、文本（为空时是 `(empty)`）、列表的各项（没有时是 `(none)`）、已设置的机密显示为 `••••`、`(unset)`，当你的 `config.toml` 之上的某一层设置了它时，后面会有暗色的 `· profile NAME`、`· project` 或 `· -c`。某一层的值无法使用时，说明的位置改为显示原因。标题下方显示 `Changes save automatically`，或上一次改动的结果：`Saved`、`Saved · the project layer overrides it`（或 `the profile NAME layer`、`the -c layer`）、`Saved · applies at next launch`、`Saved · applies from the next session`、`Could not save: …`。最底一行说明选中行的按键作用。说明列不足 45 列时，选中行的说明移到列表下方。

- **左**、**右**键切换标签页；上、下、Page Up、Page Down、Home、End 移动；Esc 返回，在标签页上则关闭设置中心。
- **`/`** 搜索所有标签页：设置、集合、记录和页面的标签、键、值、关键词和摘要。结果的说明是它所在的标签页和分节。Enter 离开搜索框进入结果，Esc 清空搜索。
- **布尔值**用 Enter 或空格立即保存。**选项**打开它的值列表，当前值标有 `(current)`，不能选的值变暗并显示原因；选中一个即保存。**文本、数字或路径**在行内编辑：Enter 按写入的方式检查并保存，被拒绝时编辑框保留并显示原因（Esc 取消）。**文本列表**以列表打开：Enter 编辑或添加一项，`d` 删除一项，每次改动都会保存。需要一起保存的设置（网页搜索服务及其 URL）以带 Save 的小表单打开。
- **`r`** 重置选中的设置：从你的 `config.toml` 中删除它，下一层（或默认值）重新生效。
- **集合**（Provider、模型覆盖、模型策略、MCP 服务器、MCP 机密、插件的 MCP 服务器、插件、已安装的插件、市场、钩子、角色；独立模式下还有 profile 和项目）打开它的记录，每条显示状态和摘要，上方显示它无法读取的部分。Enter 把一条记录打开为字段表单，每个字段改动时即保存；记录拒绝的字段保持标记为 `unsaved`，随下一次改动一起发送（例如先改 MCP 服务器的传输方式，再填它的 URL）。在记录的字段上按 `r` 取消设置它（profile 的某个键、模型的窗口、插件服务器回到插件自己的工具）。表单的其余行是记录的动作（Make default、List models、Connect、Update、Trust、Delete……）；其中一些（如 Delete 和 Trust）会先询问。`a` 添加一条记录（一个由 Add 保存的表单，字段从 add 将写入的值开始；MCP 服务器、模型覆盖、profile、项目和角色在其中命名，已安装的插件用 `PLUGIN@MARKETPLACE` 或它的目录命名），`d` 在询问后删除选中的记录。机密从不显示：`••••` 表示已设置，输入新值会替换它。在别处写入的记录（角色文件、profile 或插件中的角色、内置角色）只显示，并说明写在哪里；钩子的定义是它的摘要，写在它的文件中。对 `providers.toml` 或 `mcp.toml` 的写入如果被其他改动抢先，会被拒绝：记录会重新读取，你的改动保留，可以再次保存。模型策略是只有一条记录的集合，直接以表单打开。
- **页面**：语法主题、状态栏和终端标题这几行打开主题选择和两个设置界面；Keymap 和 Presets 行（Interface）、Plugin browser（Plugins）、Hook review（Tools）和 Memory store（Memory）打开按键映射、预设、插件浏览器、钩子浏览器，以及记忆的状态、参与和重置。Provider 的 **Choose the model** 和 MCP 服务器的 **Log in** 是它们记录的页面。Esc 回到打开它们的那一行。页面保存的内容（绑定的按键、预设、主题）也会显示在标题下方。这些页面只在设置中心中：原来打开它们的命令现在在设置中心打开它们。
- **鼠标**：滚轮移动选择，点击标签页显示它，点击一行选中它，点击已选中的行等同于 Enter。

`/config 目标` 在某个标签页（`memory`）、分节（`web`、`compaction`、`tui`、`pluginOptions.subagents`）、集合（`providers`、`providerModels`、`modelPolicy`、`mcp`、`mcpSecrets`、`pluginMcp`、`packages`、`roles`）或页面（`theme`、`statusline`、`title`、`keymap`、`presets`、`plugin-browser`、`hook-review`、`memory-store`）打开设置中心。各命令是它的快捷方式：`/providers` 即 `/config providers`（`policy`：`modelPolicy`），`/mcp` 即 `/config mcp`，`/plugins` 对应 `plugin-browser`，`/hooks` 对应 `hook-review`，`/memories` 对应 `memory`，`/tui` 对应 `tui`，`/theme`、`/statusline`、`/title`、`/keymap` 和 `/presets` 对应各自的页面。每次写入都在界面的事件循环之外进行，一次一个；设置中心从不等待它。分层不再是一个页面：每一行会标出设置它的那一层，profile 和项目是集合，[`/warnings`](#warnings) 保留各层无法使用的内容。会话角色由 [`/role`](#role) 负责。目标不对应其中任何一个时，会提示没有这样的设置页面。`config set` 是修改单个键的命令行等价方式。

## 警告 [#warnings]

界面或 Agent 无法按配置使用的内容会在本次运行中保留下来，`/warnings` 列出它们：最新的在前，每条只出现一次，并按来源计数：

- **configuration**：读取 `config.toml`、`providers.toml` 和 `mcp.toml` 时做的修复（[配置恢复](/docs/recovery)），以及 `config.toml` 的某一层中设置无法使用的内容：不认识的键，或被下一层替换的值；
- **roles**：读取[角色](/docs/roles#issues)时略去的内容、同一来源中定义了两次的角色，以及每个不可用的角色及其原因；
- **plugins**：失败的插件，或被排除在回合之外的插件；
- **installed plugins**：[已安装插件](#plugins)无法使用的内容：清单字段、组件、它的[角色](/docs/roles#plugins)略去的内容、因同名而让位的 MCP 服务器；代码失败的插件（10 分钟内第四次失败，或启动失败），直到重试为止，以及它的代码遗漏的内容；
- **MCP**：服务器最近的错误或警告，以及读取 `mcp.toml` 时做的修复；
- **hooks**：钩子配置中的问题；
- **panics**：Agent 捕获到的内部错误；
- **compaction**：回合运行的压缩失败（[上文](#reading)）；
- **interface**：因内部错误而关闭的命令、`[tui]` 中不认识的主题或项目、无法使用的按键映射设置。

启动时如果有警告，会有一行说明数量（`2 warnings: /warnings`）。在列表中，`c` 复制选中的警告，`d` 在本次运行的剩余时间内忽略它。没有警告时，`/warnings` 显示 `No warnings.`。

## 终端要求 [#terminal]

- 终端需要响应光标位置查询，否则界面无法启动。
- 只使用基本的 ANSI 颜色和粗体、暗色、斜体。
- Fullscreen 使用备用屏幕和鼠标（SGR 报告）。
- Scrollback 下，分页器和恢复选择器使用备用屏幕，期间鼠标滚轮相当于方向键；对话记录会捕获鼠标用于选择和控件。在它们之外，Scrollback 只在尾部显示控件时捕获点击和滚轮（SGR 报告；Windows 上是控制台的鼠标输入，捕获期间关闭快速编辑模式），直到滚轮第一次滚动（`tui.scrollbackMouse`）。
