## Proxy [#proxy]

`network.proxy` sets the Agent's proxy:

```sh
hanafubuki-agent config set network.proxy http://127.0.0.1:7890
hanafubuki-agent config set network.proxy socks5h://user:pass@proxy.example.com:1080
hanafubuki-agent config set network.proxy disabled
hanafubuki-agent config set network.proxy system
```

| Value                | Means                                                                                                            |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `"system"` (default) | No proxy of its own: what the Agent process's environment says                                                   |
| `"disabled"`         | No proxy                                                                                                         |
| A proxy URL          | That proxy: `http`, `https`, `socks4`, `socks4a`, `socks5` or `socks5h`, with a user name and password if needed |

`config get network.proxy` prints a URL's user name and password as `***`.

### What it applies to [#proxy-scope]

| What                                                  | Uses                                                                                                                                                           |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web search and fetch (`web_search`, `fetch_web_page`) | `network.proxy`, each redirect and the Jina Reader fallback too; the page's name is still resolved here unless you opt out ([below](#web-fetch-dns))           |
| MCP Streamable HTTP servers and OAuth                 | `network.proxy` (login and token refresh too); a change reconnects those servers                                                                               |
| The commands and terminals the model runs             | The environment variables `network.proxy` decides (below)                                                                                                      |
| MCP stdio servers                                     | The same variables, over their own environment; a change restarts them                                                                                         |
| Plugin package and marketplace downloads (`git`)      | The same variables (a `http.proxy` in your git configuration wins over them)                                                                                   |
| Requests to model Providers and their model lists     | `network.proxy`; a change reaches each session's next turn (below)                                                                                             |
| The models.dev download (`modelMetadata.modelsDev`)   | `network.proxy`                                                                                                                                                |
| The update check at the terminal interface's launch   | `network.proxy`; what it sends is in [Terminal interface](/docs/terminal-interface#updates)                                                                    |
| `hanafubuki-agent update`                             | `network.proxy` for the lookup and the download (the system's when the configuration cannot be read); what it sends is in [update](/docs/cli-reference#update) |

### The commands' proxy variables [#child-processes]

The commands the model runs get a clean environment (see [Environment](/docs/environment#commands)), whose proxy variables `network.proxy` decides:

- a proxy URL: `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` set to it;
- `"disabled"`: `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` removed;
- both of these also set `NO_PROXY=localhost,127.0.0.1,::1`;
- `"system"`: no proxy variable at all. Since the commands' environment is clean, your shell's proxy variables do not reach them either: to have commands use a proxy, set a proxy URL.

Each name is set or removed in upper and lower case (`https_proxy`, `no_proxy` and so on), except on Windows, where names are not case-sensitive. A change applies to the commands started after it.

MCP stdio servers get the same variables over the Agent's environment and their own variables from `mcp.toml`, so `network.proxy` wins over a proxy variable either gives them (with `"system"`, they keep those). A proxy change starts the enabled ones anew under it, as it reconnects the Streamable HTTP ones.

### The model Providers' proxy [#provider-proxy]

Requests to model Providers (turns, compaction, titles, recaps, memory extraction and each Provider's model list) use `network.proxy`. A change applies to what is built after it: a session takes it at its next turn, and a request already streaming finishes where it started.

With `"system"`, they follow what the Agent process's environment and the operating system say: `HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY` and `NO_PROXY` (in either case) set before the Agent starts, else the system's proxy settings on macOS and Windows:

```sh
HTTPS_PROXY=http://127.0.0.1:7890 hanafubuki-agent
```

`"disabled"` goes direct whatever the environment says; a proxy URL is used for every Provider, `NO_PROXY` notwithstanding, except one on this machine (`localhost`, `127.0.0.0/8`, `::1`, such as Ollama or LM Studio), which is reached directly. The same holds for MCP's Streamable HTTP servers and OAuth, and for the models.dev download.

### Web fetch and name resolution [#web-fetch-dns]

`fetch_web_page` refuses a page that is not on a public address (private, loopback, link-local). To know, it resolves the page's host name on this machine before each request, before each redirect it follows and before it asks the Jina Reader, also when `network.proxy` names a proxy, which then resolves the name again itself. So, through a proxy:

- On a network where only the proxy can resolve public names (this machine's DNS cannot), every fetch fails with `web page host could not be resolved safely`. `web_search` is not affected.
- A name this machine resolves to a private address is refused with `web page target is not a public web address`, even if the proxy would reach a public one.

The check keeps a fetch, which needs no approval, from reaching this machine or its network. To fetch through a proxy that alone resolves names, either let this machine resolve public names (its own DNS, or a resolver it can reach), or turn on `webFetchResolveThroughProxy` (`/config`, Web tools):

```sh
hanafubuki-agent config set webFetchResolveThroughProxy true
```

With it on and `network.proxy` a proxy URL, a name this machine cannot resolve is left to the proxy instead of failing the fetch. A name that resolves here is still checked, and a private address or a name such as `localhost` is still refused. What the proxy reaches for a name the Agent could not check is not checked: a page could lead the model to an internal name only the proxy resolves, an intranet behind a company proxy among them. With a `socks5://` proxy the name is resolved here anyway; use `socks5h://` for the proxy to resolve it. The setting does nothing with `"system"` or `"disabled"`.

## Logging [#logging]

The standalone Agent logs to `logs/hanafubuki-agent.log` in the data directory; `hanafubuki-agent config path` prints where it is. Past 8 MiB the file is rotated to `hanafubuki-agent.log.1`, keeping at most three old files.

`logLevel` sets the level, and `--log-level` sets it for one run:

```sh
hanafubuki-agent config set logLevel debug
hanafubuki-agent --log-level trace exec "…"
```

| Level            | Records                                                  |
| ---------------- | -------------------------------------------------------- |
| `off`            | Nothing                                                  |
| `error`, `warn`  | Errors; and warnings                                     |
| `info` (default) | Starts, shutdowns, connections and the other main events |
| `debug`          | More detail, to track a problem down                     |
| `trace`          | The model's and the tools' content too                   |

- **Only `trace` records content**: what is sent to the model and what it returns, the tools' input and output. Each piece is cut at 64 KiB.
- **No level records credentials**: API tokens, request headers and MCP credentials never reach the log.
- The records of other libraries go up to `info` only, even at `debug` or `trace`.

<Callout type="warn">
  A `trace` log holds the content of conversations and tool output: code, file contents and other
  sensitive information. Read it before you share it, and go back to `info` once you are done.
</Callout>

`logLevel` and `network.proxy` are the standalone Agent's; an application that embeds the Agent uses its own logger and proxy.
