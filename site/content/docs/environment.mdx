## Agent 读取的变量 [#read]

| 变量                                                 | 作用                                                                                                                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HANAFUBUKI_AGENT_HOME`                              | 用一个目录同时代替配置目录和数据目录。相对路径相对于当前目录解析（不是 `-C`）；设为空值等于没有设置                                                                    |
| `XDG_CONFIG_HOME`、`XDG_DATA_HOME`                   | Linux 上配置目录和数据目录的基准位置，默认分别是 `~/.config` 和 `~/.local/share`                                                                                       |
| `VISUAL`、`EDITOR`                                   | `config edit` 打开的编辑器，以及 Ctrl-G 编辑草稿所用的编辑器（[终端界面](/docs/terminal-interface#composer)），先看 `VISUAL`。可以带参数，例如 `code --wait`           |
| `--api-key-env` 指定的变量                           | `providers add` 从中读取 API 令牌，只在添加时读取一次                                                                                                                  |
| `HANAFUBUKI_AGENT_NO_UPDATE_CHECK`                   | 任意非空值都会关闭终端界面的[更新检查](/docs/terminal-interface#updates)及其提示，无论 `tui.checkForUpdates` 如何设置                                                  |
| `GITHUB_TOKEN`                                       | [`update`](/docs/cli-reference#update) 查询 GitHub 发布时以 `Authorization: Bearer` 发送它，可以提高 GitHub 的速率限制；下载归档时不发送，终端界面的更新检查也从不发送 |
| `PATH`（Windows 上还有 `PATHEXT`）                   | 查找 stdio MCP 服务器的程序                                                                                                                                            |
| `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY` | 访问模型 Provider 时使用的代理，见[网络与日志](/docs/network-logging#provider-proxy)                                                                                   |
| `HANAFUBUKI_AGENT_TEST_RELEASE_URL`                  | 只用于调试构建：代替 GitHub 的发布查询地址（`http` 只能指向回环地址）；没有它，调试构建不查询任何发布                                                                  |

Agent 本身不读取 `RUST_LOG` 或 `NO_COLOR`：日志级别由 `logLevel` 和 `--log-level` 决定，见[网络与日志](/docs/network-logging#logging)。

## 命令和终端的环境 [#commands]

模型通过工具运行的命令不会继承 Agent 进程的全部环境。它们只得到一个干净的环境：

- 从 Agent 的环境中只保留 `PATH` 和 `TMPDIR`。Windows 上保留系统的变量，而不是用户的变量：`PATH`、`PATHEXT`、`SYSTEMROOT`、`WINDIR`、`COMSPEC`、`TEMP`、`TMP`、`USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、`ProgramData`、`ProgramFiles`、`ProgramFiles(x86)`、`SystemDrive`、`HOMEDRIVE`、`HOMEPATH`、`PSModulePath`、`PROCESSOR_ARCHITECTURE`、`NUMBER_OF_PROCESSORS` 和 `OS`，Windows PowerShell 的模块、git 的全局配置和 npm 的缓存需要它们。
- 为了不让命令等待分页器或输出控制字符，固定设置 `NO_COLOR=1`、`TERM=dumb`、`LANG`、`LC_CTYPE`、`LC_ALL` 为 `C.UTF-8`、`COLORTERM` 为空，以及 `PAGER`、`GIT_PAGER`、`GH_PAGER` 为 `cat`。
- 为了让 Python 写出 UTF-8（Windows 上也是）：`PYTHONUTF8=1` 和 `PYTHONIOENCODING=utf-8`。其他 Shell 的输出如何保持 UTF-8，见[工具](/docs/tools#commands)。
- 再加上由 `network.proxy` 决定的代理变量。
- 对于 [Windows 上的 POSIX Shell](/docs/tools#commands)（Git for Windows 或 MSYS2 的 bash），加上它像 POSIX Shell 一样运行所需的变量：把 Shell 所在目录（`usr\bin`，`ls` 等 MSYS 程序所在的目录）放在 `PATH` 的最前面，因为非登录 Shell 原样使用得到的 `PATH`；`CHERE_INVOKING=1`，否则 MSYS2 的登录 Shell 会切换到 `$HOME`；`MSYS2_PATH_TYPE=inherit`，否则 MSYS2 的登录 Shell 只保留 Windows `PATH` 中的系统目录（Git for Windows 默认保留全部）；以及 Agent 本身运行在 MSYS2 或 Git Bash 的 Shell 中时，它的 `MSYSTEM`。命令已有的变量保持不变。

因此，你在 Shell 中设置的变量（例如 API 令牌或代理）不会自动传给模型运行的命令。

stdio MCP 服务器不同：它们继承 Agent 进程的完整环境，再加上 `mcp.toml` 中为它们配置的变量，最后是由 `network.proxy` 决定的代理变量，后者优先于前两者。修改代理后，它们会在新代理下重新启动。

## 代理变量 [#proxy]

`network.proxy` 决定 Agent 为它启动的进程设置哪些代理变量：

| `network.proxy`    | 命令、终端和 stdio MCP 服务器得到的变量                                                   |
| ------------------ | ----------------------------------------------------------------------------------------- |
| `"system"`（默认） | 不设置代理变量（stdio MCP 服务器保留 Agent 环境中的代理变量）                             |
| 一个代理 URL       | `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY` 为这个 URL，`NO_PROXY=localhost,127.0.0.1,::1` |
| `"disabled"`       | 去掉 `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY`，`NO_PROXY=localhost,127.0.0.1,::1`       |

每个变量名都同时处理大写和小写（`https_proxy`、`no_proxy` 等），Windows 除外，因为 Windows 的变量名不区分大小写。修改只影响之后启动的进程。详见[网络与日志](/docs/network-logging)。
