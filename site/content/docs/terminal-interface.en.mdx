`hanafubuki-agent` with no command opens the terminal interface. Text after it is sent as the first message:

```sh
hanafubuki-agent
hanafubuki-agent "Find the modules in this project that no test covers"
```

The interface starts with no session: your first message creates it, as does a command that needs one (`/model`, `/mode`, `/compact`, `/status`). Starting and quitting leaves no empty session behind. With no default Provider or no model chosen, the interface opens the [setup](#setup) instead of letting the first message fail. When the session cannot be created for another reason, the conversation says why in red and the interface stays open; the next message tries again.

The interface needs a terminal on both standard input and standard output; in a pipe or a redirection it points you to [exec](/docs/exec) and exits with code 2. `-m`, `-C`, `--add-dir`, `--permission-mode` and the other [global flags](/docs/cli-reference#global-flags) apply as usual.

## Fullscreen and Scrollback [#modes]

The interface shows the conversation one of two ways, chosen when it starts and kept until it quits:

- **Fullscreen** (the default): the interface takes the terminal's alternate screen and draws the conversation itself, above the bottom area. You scroll, select, search and copy inside it (see [Reading the conversation](#reading)), and it does not stay in the terminal after you quit.
- **Scrollback**: the interface takes a few lines at the bottom of the terminal, and the conversation is written into the terminal's own scrollback above it, so you scroll back through it, select and copy like any other output, and it stays in the terminal after you quit.

It starts in Fullscreen unless one of these says otherwise, the first that applies winning:

1. `--no-alt-screen` on the command line: Scrollback for this run.
2. `tui.alternateScreen = "never"`: Scrollback. `"auto"` (the default) is Scrollback in an SSH session (`SSH_TTY` or `SSH_CONNECTION` set), `"always"` never.
3. `tui.fullscreenTranscript = false`: Scrollback. `/tui` sets it.

The keys are in the [Configuration reference](/docs/config-reference#tui).

## Layout [#layout]

In Fullscreen the conversation fills the screen above the bottom area. In Scrollback the bottom area is all the interface draws, and the conversation goes into the scrollback above it.

At the start (and after `/new` or a resume) a box shows the version, the model and the working directory. Before a session exists, the model is the one it will get: `-m`'s, else the configured one. The bottom area holds, from the top:

1. **The running tool calls**: `• Running TOOL: SUBJECT`. In Fullscreen they are the end of the conversation instead.
2. **The status line**: during a turn, `• Working (12s • esc to interrupt)` with the elapsed time. While a model request is retried it reads `Reconnecting 1/3: reason`. The timer pauses while an approval or a question waits for you. Once the model's answer starts streaming, the status line is hidden.
3. **The composer**, starting with `›`.
4. **The footer**: the [status line](#status-line), by default the model and its reasoning effort, the working directory and the session's title, while the composer is empty or holds a draft with no turn running; `? for shortcuts` when it shows no item.

An approval, a question, the `/model` and `/mode` lists and the screens of `/providers` and `/mcp` take the place of the status line and the composer while they are open. A screen stays open when a turn ends.

In the conversation your messages start with `›`; a tool call is `• Called TOOL` or `• Failed TOOL`, with the first and last lines of its output; `apply_patch` shows the diff it made; the task plan is `• Updated Plan`; errors start with a red `■`. After a stretch of tool calls, a `─ Worked for 1m 05s ─` rule comes before the answer.

## Keys [#keys]

| Key                        | Does                                                                                                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Enter                      | Sends the message: a new turn, or, while one runs, a message that steers it (below). In a popup, picks its entry                                                 |
| Shift+Enter, Ctrl+J        | A new line. Shift+Enter needs a terminal with the enhanced keyboard protocol; otherwise use Ctrl+J                                                               |
| Up, Down (Ctrl-P, Ctrl-N)  | On an empty composer, the messages sent in this run; in a popup, its entries                                                                                     |
| Tab                        | In the command popup, completes the command; in the file popup, inserts the path                                                                                 |
| Esc                        | Closes a popup; otherwise interrupts the turn while the status line is shown. With no turn running, twice on an empty composer: edits an earlier message (below) |
| Ctrl-C                     | In turn: denies an approval; clears a composer with text; interrupts a running turn; a second press within one second quits                                      |
| Ctrl-D                     | On an empty composer, two presses within one second quit; with text, deletes the next character                                                                  |
| Ctrl-T                     | Fullscreen: shows the conversation in detail, in place; Scrollback: opens the transcript (below)                                                                 |
| Ctrl-O                     | Shows or hides the model's thinking (below)                                                                                                                      |
| `?` on an empty composer   | Shows the shortcuts                                                                                                                                              |
| Ctrl-X P                   | Opens the [presets](#presets)                                                                                                                                    |
| Ctrl-X Left, Right, Tab, X | With a side conversation or a subagent open: the main conversation, the side one, the other one; closes it ([below](#side))                                      |

Fullscreen has the conversation's keys too: Page Up/Page Down, F3, F4, Ctrl-Space and the others in [Reading the conversation](#reading).

These are the default keys. [The keymap](#keymap) changes the keys of its actions (Enter, the history, Esc to interrupt, Ctrl-T, Ctrl-O, the editing keys, the conversation's and the pagers' keys); Ctrl-C, Ctrl-D, Tab, `?` and the keys of popups and lists stay as they are.

The composer has the usual Emacs-style editing keys: Ctrl-A/E for the start and end of the line, Ctrl-W to delete the previous word, Ctrl-U/K to delete to the start or end of the line, Alt-B/F to move by word, and so on.

<Callout>
  Once the model's answer starts streaming the status line is hidden, and Esc no longer interrupts
  the turn: use Ctrl-C.
</Callout>

## The composer [#composer]

- **Pasting**: a paste of more than 1000 characters shows as a `[Pasted Content 1234 chars]` placeholder, expanded when you send; deleting the placeholder deletes the paste.
- **History**: Up and Down go through the messages sent in this run (drafts cleared with Ctrl-C included), not the earlier messages of a resumed session.
- **Steering a running turn**: a message you send with Enter while a turn runs does not wait for it to end: it goes to the running turn, and the model sees it at its next step. If the turn ends before the message reaches it, the message is dropped.

- A command that is not available during a turn says `'/x' is disabled while a task is in progress.`
- A `/name` that is no command is not sent; you get `Unrecognized command` instead. A path with a slash in it (`/usr/bin/env`), or text that starts with a space, is sent as a message.
- Commands take no arguments, but `/permissions`, `/rename`, `/resume`, `/fork`, `/review`, `/side`, `/goal`, `/export`, `/cd`, `/clear`, `/raw`, `/mcp`, `/statusline`, `/title` and `/keymap`. A message such as `/model gpt-5.1`, with text after the name, goes to the model as an ordinary message. `/mcp` with anything but `verbose` or `login ID` says `Usage: /mcp [verbose | login ID]`.
- `/raw` applies at once and is saved (`tui.rawOutput`), so the next launch starts with it. In Fullscreen the whole conversation is shown again in its raw form; in Scrollback what is already in the scrollback stays as it is, and only what follows is raw. `/raw` with anything but `on` or `off` says `Usage: /raw [on|off]`.
- `/tui` saves `tui.fullscreenTranscript` and applies from the next launch: the running interface keeps its mode. `--no-alt-screen` and `tui.alternateScreen` still apply then.
- A command, or a list it opened, that fails with an internal error (a panic) is turned off for the rest of the run: the conversation says `'/x' failed and is turned off for the rest of this run`, the popup leaves it out, and typing it says it is off. The session, the composer and the other commands go on. An internal error in the chat itself (the composer, the conversation, a streaming answer) still ends the interface, after the terminal is restored.

## Session commands [#session-commands]

- **`/rename`** opens a one-line prompt with the session's title. While it is open the session's model is asked for a title for the conversation as it stands: it shows under the field (`Suggested: …`), and Tab puts it into the field. Enter renames, Esc cancels. With the `titles` plugin off, or nothing to suggest from, the prompt says `No title suggestion`. `/rename NAME` renames at once. Without a session, `/rename` creates one first.
- **`/archive`** and **`/delete`** ask first (the "No" choice is selected). Then the interface shows no session, as after `/new`. An archived session is found again in the resume picker's archived list (Tab), and Ctrl+A or Enter there restores it. Deletion cannot be undone, and deletes the session's child sessions too. See [Sessions](/docs/sessions#archive-delete).
- **`/fork [name]`** forks the session at its latest committed item: the copy has the whole conversation, and the interface continues in it; the original is kept as it was. With a name the copy is renamed. When the working directory is in a Git repository and the `worktree` plugin runs, it first asks where the copy runs: Fork here, or Fork into a new worktree, which is `/worktree`'s Continue this conversation ([below](#worktrees)).
- **`/clear [name]`** clears the terminal's scrollback and screen in Scrollback, or the conversation in Fullscreen, and leaves the session as `/new` does. With a name, the session your next message creates gets it.
- **`/export`** offers Copy to clipboard or Save to file. Save asks for a file name, filled with `hanafubuki-agent-session-ID.md` in the first workspace root. `/export PATH` saves there at once. A relative path is read against the first workspace root (`~` is not expanded), and an existing file is not replaced: the export fails instead. The format is described in [Sessions](/docs/sessions#export).
- **`/copy`** offers the last answer whole (as Markdown), each fenced code block (as written, without the fence), and each quote (without its `>`); in Fullscreen also Select in the transcript: a caret in the conversation, which the arrows move; v or Space starts a selection, y or Enter copies it, Esc or q leaves. The answer is read from the session's history, so a resumed session's last answer is offered too.
- **`/ps`** writes the session's background terminals into the conversation: each command, its state (and exit code), its directory and its last three lines of output. **`/stop`** (or `/clean`) asks first, then stops them all and says how many it stopped; one that would not stop is reported.
- **`/recap`** writes `Writing a recap…`, then the recap: what the conversation is about and where it stands, and `Next:` with an open question or the agreed next step when there is one. It reads the latest exchanges, without tool output, and commits nothing to the session. With the `recap` plugin off, it says recaps are unavailable and why.
- **`/init`** sends a fixed prompt as your message: write `AGENTS.md`, a short contributor guide for the repository (structure, commands, style, tests, commit conventions), and leave an existing `AGENTS.md` unchanged. The prompt is Codex's.

## Permissions [#permissions]

The permission mode starts as the configuration's (`permissionMode`, or `--permission-mode`); see [Permissions](/docs/permissions#modes).

- **`/permissions`** lists Codex's [presets](/docs/permissions#presets), each a permission mode with a sandbox mode: Read only (Manual, `read-only`), Default (Manual, `workspace-write`), Auto-review (Automatic review, `workspace-write`) and Full access (Full access, no sandbox). The one in effect is selected: the session's own modes, else the configured ones; when they make no preset, none is. Full access asks first (Cancel is selected). Where this machine has no sandbox, the presets that need one cannot be chosen. Choosing one sets both modes for the session. Without a session, `/permissions` creates one first.
- **`/permissions read-only`** or **`/permissions default`** sets that preset at once. **`/permissions manual`**, **`/permissions auto-review`** or **`/permissions full-access`** (`auto_review` and `full_access` too) sets the permission mode alone, at once and without asking, and keeps the sandbox: a mode's name is never a preset's.
- The modes are the session's only, until the interface quits: `permissionMode` and `sandboxMode` stay as they are, other sessions and forks keep the configured modes, and a turn already running keeps the modes it started with. See [One session's mode](/docs/permissions#session-mode) and [One session's sandbox](/docs/permissions#session-sandbox).
- **`/approve`** lists the actions automatic review denied in this session, the latest first: each with its summary and the review's rationale, searchable. The interface keeps the latest ten of each session, from the time it opened it, so a resumed session lists none of its earlier ones. The one chosen is approved: the model sees the approval from its next request, and a retry is still reviewed ([Approving a denied operation](/docs/permissions#approve-denied)). With none, it says `No denied actions to approve.` While a turn runs the Agent refuses the approval, and the conversation says why.

## Working directory and worktrees [#worktrees]

- **`/cd [path]`** makes `path` the working directory: the first workspace root, with its Git root and the `--add-dir` directories after it. A relative path is read against the current working directory; `~` and `~/…` are your home directory, as is `/cd` alone. The session goes on there: its next turn works in the new roots. The Agent refuses while a turn, a compaction or a background terminal runs, and a directory that does not exist; the conversation says why, and nothing changes.
- The project configuration does not follow `/cd`: its trust level and the project's `config.toml` stay the ones read when the interface started, until you start it again.
- **`/worktree`** opens a menu, when the working directory is in a Git repository and the `worktree` plugin runs (otherwise it says why there is none):
  - **Continue this conversation** makes a new worktree, forks the session into it ([Worktrees](/docs/sessions#worktrees)), changes the working directory to it, and continues in the fork. Without a conversation yet, this row cannot be chosen.
  - **Start a new conversation** makes a new worktree and changes the working directory to it, with no session: the session your next message creates belongs to the worktree.
  - **Browse worktrees** lists the repository's worktrees, each with its commit, its branch (`detached` for a new one) and its session. Choosing one offers Resume session N, Copy path and Remove worktree; removing asks first (Cancel is selected), deletes the checkout with its local changes and keeps the session. The worktree the working directory is in is not removed: `/cd` out of it first.
- When a step after the worktree was made fails (the fork, the change of directory), the worktree is kept, and the conversation says where; Browse worktrees removes it.

## First-run setup [#setup]

When the interface starts with no default Provider (none is configured, or none is enabled), or with no model chosen for new sessions and none given with `-m`, it opens the Provider setup over the composer instead of letting the first message fail:

- With no Provider: the form to add one. Fill in its name, protocol, base URL and token, choose **Test** to list its models, then **Save**. The model picker follows; the model you pick, on that Provider, is the one new sessions run.
- With Providers but none enabled: the Provider list, where `e` enables one and `a` adds one.
- With a default Provider but no model: the model picker straight away.

Esc goes back and then closes the setup; the composer is yours again. A message sent before the setup is done stays in the composer, a line says why, and the setup opens again. Once a model is chosen, the next message creates the session. `/new` checks again, as a start does.

## Forms [#forms]

The screens of `/providers` and `/mcp` edit in a form:

| Key                | Does                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| Tab, Down          | The next field; from the last, the first                                                               |
| Shift+Tab, Up      | The previous field; from the first, the last                                                           |
| Enter              | The next field; on an action (**Test**, **Save**), runs it; on **+ Add …**, adds a row; opens Advanced |
| Space, Left, Right | Switches a choice or a toggle (`[x]`), and a row between `[public]` and `[secret]`                     |
| Esc                | Back: from the form to the list, from the list closed                                                  |
| Ctrl-C             | Closes the screen                                                                                      |

- Text fields have the composer's editing keys. Each field keeps its own kill buffer (Ctrl-K, Ctrl-U, Ctrl-W, then Ctrl-Y), so text deleted from a secret cannot be yanked into another field.
- A token or a secret value is drawn as dots, its last character shown only while you type it. A paste goes into the field that has the focus, without its line breaks.
- In a list of rows (request headers, environment variables, HTTP headers), **+ Add …** adds a row; a row whose name is empty is dropped when the form is saved.
- What is wrong with a field is said in red under it, and the focus goes there. What the Agent refuses on saving (an invalid header, say) is said under the form, whose entries are kept.

## Providers [#providers]

`/providers` lists the Providers: ★ marks the default, and each shows its protocol, base URL, whether a token is set (never the token) and whether it is disabled. Enter edits the highlighted one, `a` adds one, `d` deletes it after asking, `e` enables or disables it, `*` makes it the default, Esc closes the list. The form, **Test**, saving and the model picker are in [Providers and models](/docs/providers-models#interface).

## MCP servers [#mcp]

`/mcp` lists the MCP servers, each with its transport, connection phase, number of tools and last error. Enter edits the highlighted one, `a` adds one, `d` deletes it after asking, `e` enables or disables it, `c` connects it (a connected one reconnects), `l` starts its OAuth login, `o` logs it out, Esc closes the list. The form and its secrets are in [MCP](/docs/mcp#interface).

## Reviews [#review]

`/review` opens a picker of what to review: **Review uncommitted changes** (staged, unstaged and untracked), **Review against a base branch** (the repository's local branches, the current one marked `(current)`, searchable), **Review a commit** (the latest 100 commits, searchable by subject or hash) and **Custom review instructions** (a one-line prompt). Esc on a list goes back to the presets. Outside a Git repository the branch and the commit are unavailable and say why. `/review INSTRUCTIONS` reviews with your instructions at once. How a review runs is in [Sessions](/docs/sessions#reviews).

- A review reports back into the conversation, so the session must have had a turn: before your first message `/review` says `Send a message first; a review reports back into a conversation.` It does not start during a turn, nor while another review runs.
- While it runs, the conversation shows `>> Code review started: … <<` and the status line `Reviewing …`. Esc, or `/review cancel`, cancels it (`<< Code review cancelled >>`). A message you send meanwhile waits and is sent when the review ends, so the turn it starts reads what the review found.
- When it ends, `<< Code review finished >>` is followed by the verdict and its confidence, the explanation, and each finding: its priority and title, its file and lines, and its body.
- With the `review` plugin off, `/review` says reviews are unavailable and why.

## Goals [#goal]

`/goal OBJECTIVE` gives the session a goal ([Sessions](/docs/sessions#goals)); `/goal --tokens N OBJECTIVE` gives it a token budget too (`200000`, `200k`, `2m`). When the session's goal is not complete, a question asks first, **Replace goal?**, with keeping the current goal selected. The Agent pursues the goal from your next message; one set during a turn is taken up at that turn's next answer.

- `/goal` alone shows the goal: its objective, status, tokens used (of the budget) and time used, with what can be done: **Pause goal** (an active goal) or **Resume goal** (a paused or blocked one), **Edit objective**, **Set token budget** and **Clear goal**. Without a goal it says so, with the usage.
- `/goal pause`, `/goal resume` and `/goal clear` act at once; `/goal edit` opens a prompt filled with the objective. Editing the objective, or setting the budget, sets the goal again: its usage starts from zero.
- Without a session, `/goal` creates one first. With the `goal` plugin off, it says goals are unavailable and why.
- The [status line](#status-line)'s `goal` item shows the goal: read when a session opens, then updated by every `/goal` and, during a turn, by the session's events.

## Hooks [#hooks]

`/hooks` lists the [hook](/docs/configuration#hooks) events, each with how many hooks it has, how many run (trusted and on) and how many need review, above what in the configuration was skipped and why. Enter opens an event: each hook with its matcher and command, its trust (`trusted`, `new, review required` or `modified since trusted, review required`), whether it is on, the file it is configured in and its timeout. Space or Enter turns the highlighted hook on or off, `t` trusts it, Esc goes back. On the events, `t` trusts every hook that needs review, after a question. Each change is saved at once, and the hooks are read again.

When the interface starts with hooks that need review (new, or modified since they were trusted), the conversation says `N hooks need review: /hooks`, and the warning is kept; nothing waits for you.

## Side conversations [#side]

`/side` (or `/btw`) opens the session's [side conversation](/docs/sessions#side): a temporary conversation beside it, for a quick question that should not disturb the session's work. `/side QUESTION` opens it and sends the question there. The session must have had a turn: before your first message `/side` says `'/side' is unavailable until the current conversation has started.` It is refused too while a [review](#review) runs or while the session's context is being compacted.

- **Fullscreen**: the side conversation is a pane docked on the right of the conversation, with its own transcript, composer and status line; a title row tops each pane and a divider separates them. The pane opens focused. Its messages go to the side session, the main conversation's to the main session, and both stay live: a turn in one goes on while you type in the other. Narrower than 100 columns, or zoomed (`leader z`), the focused conversation fills the screen under its title. Drag the divider with the pointer, or use `leader <` and `leader >`, to resize the panes; `leader =` makes them equal; a click in the other pane focuses it.
- **Scrollback**: the interface switches to the side conversation: `Side conversation · Esc returns · /side close closes it` is written into the scrollback, then the side conversation. What the main conversation writes meanwhile waits, and is written when you return to it.
- **Returning and closing**: Esc on an empty composer with nothing running (the `chat.edit_previous` key), or `leader left`, returns to the main conversation. The side conversation stays open: `/side`, `leader right` or `leader tab` shows it again, with its transcript and its draft. `/side close`, or `leader x`, closes it: its running turn is interrupted and the session is dropped (`Side conversation closed.`). It is closed too when the main conversation moves to another session (`/new`, `/resume`, `/fork` and the like).
- **Commands** in a side conversation are those Codex allows there: `/copy`, `/agents`, `/export`, `/raw`, `/diff`, `/mention`, `/status`, `/warnings`, `/pwd` and `/side`. The popup lists only those; another says `'/x' is unavailable here; Esc returns to the main conversation.` An earlier message of a side conversation is not edited.

The panes' keys are [keymap](#keymap) actions, by default the leader (Ctrl-X) then a key:

| Key      | Action                                                  | Does                                                       |
| -------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| `left`   | `global.focus_pane_left`                                | Returns to the main conversation                           |
| `right`  | `global.focus_pane_right`                               | Focuses the side conversation                              |
| `tab`    | `global.toggle_side_conversation`                       | Switches to the other conversation                         |
| `<`, `>` | `global.move_divider_left`, `global.move_divider_right` | Moves the divider (Fullscreen)                             |
| `=`      | `global.equalize_pane_widths`                           | Gives the panes equal widths (Fullscreen)                  |
| `z`      | `global.toggle_pane_zoom`                               | The focused pane alone, or both again (Fullscreen)         |
| `x`      | `global.hide_pane`                                      | Closes the side conversation, or leaves the subagent shown |

In Fullscreen, while the leader waits for its second key with a second conversation open, a box in the focused pane lists them.

## Subagents [#subagents]

`/subagents` writes the session's [subagents](/docs/sessions#subagents) into the conversation, each with its status (`running`, `idle` or `failed`) and the start of its latest answer, then opens a list of them; while one runs, the list follows their statuses. Enter shows the one selected in place of the session, under `Subagent NAME · from PARENT · Esc or ctrl-x left returns`: its transcript as `/resume` shows it and, while it runs, its turn as it goes on (its answer streams, its tool calls show, an approval it waits on is asked there, including one it asked for before it was shown, and Esc interrupts it). A message you send there goes to the subagent.

- Esc on an empty composer with nothing running, `leader left` or `leader x` returns to the session, whose own turn went on meanwhile.
- In Fullscreen the subagent fills the screen; in Scrollback the interface switches to it, as to a [side conversation](#side). Its commands are a side conversation's. While a side conversation is open, a subagent is not shown: close it first.
- **A subagent's approvals**: a subagent runs in its parent's permission mode, so in Manual mode its tool calls wait for you. While the session's subagents run (or its turn does), the interface reads them about every 0.4 seconds and shows an approval a subagent waits on as an ordinary [approval](#approvals) whose summary starts `Subagent NAME:`; your answer goes to the subagent. It stays open when the session's own turn ends, and closes once it is answered elsewhere (in the subagent shown) or the subagent's turn ends. While a side conversation has the focus, it waits in the main conversation: in Fullscreen its pane shows it, in Scrollback you see it when you return.

## The command center [#agents]

`/agents` opens the command center over the whole screen (the alternate screen in Scrollback): the sessions, the latest first, as the resume picker lists them, each followed by its children (subagents and reviews, marked `subagent` or `review`), with their status and how long ago they changed. The session shown is marked `(shown)`. More sessions are read as you scroll.

| Key                                     | Does                                                                                                                                                                |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Up, Down, Page Up, Page Down, Home, End | Moves the selection                                                                                                                                                 |
| Tab, Shift-Tab, Left, Right, `1`–`5`    | The filter: All, Running, Idle, Failed, Archived. Running, Idle and Failed list a session that matches, or one of whose children does, with its children that match |
| Enter                                   | Opens the session in place of the one shown; a child is shown beside its parent, as `/subagents` shows it. Under Archived, restores the session                     |
| `n`                                     | Leaves the session shown: the next message starts a new one                                                                                                         |
| `f`                                     | Forks the session at its head and continues in the copy                                                                                                             |
| `a`                                     | Archives the session with its children; under Archived, restores it                                                                                                 |
| `d`                                     | Asks, then deletes the session with its children: `y` deletes, any other key keeps it                                                                               |
| `i`                                     | Interrupts the turn the session runs; for a subagent, through the subagents' own interrupt                                                                          |
| Esc, `q`                                | Closes the command center                                                                                                                                           |

Opening, starting and forking move the main conversation, so they wait while its turn runs. The session shown is archived and deleted with `/archive` and `/delete`, not from here. Archiving and deleting run on the interface's thread, as in the resume picker.

## @ file mentions [#mentions]

`@` followed by a few characters opens a popup of up to 20 files in the workspace roots that match them fuzzily. `.gitignore` and the other ignore files are honoured, even outside a Git repository. Tab or Enter replaces the `@…` with the file's path: relative for a file in the first workspace root, whole for one in another root, and quoted when it has spaces.

Only the path is sent; the model reads the file with its tools.

## Reading the conversation [#reading]

In Fullscreen the conversation follows the latest output until you scroll. Scrolled up, it stays where you are while the turn goes on, and a `↓ Back to bottom · esc` control above the composer (`New activity · …` when something was added below) brings you back.

| Key or gesture                         | Does                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mouse wheel                            | Scrolls three lines                                                                                                                                      |
| Page Up/Page Down                      | Scrolls one page                                                                                                                                         |
| Ctrl-Home, Ctrl-End (Alt-`<`, Alt-`>`) | To the start of the session (loading its earlier messages) or to the latest output                                                                       |
| Esc, a click on the control            | Back to the latest output                                                                                                                                |
| Enter on an empty composer             | Back to the latest output                                                                                                                                |
| Drag                                   | Selects; a double click selects a word, a triple click a line, Shift-click extends the selection                                                         |
| Ctrl-Space                             | Starts a selection with the keyboard; arrows and Shift-arrows move it                                                                                    |
| Ctrl-X `[`                             | Select mode: a cursor in the conversation, moved with the keys, to select and copy                                                                       |
| Ctrl-C, Ctrl-Shift-C, Ctrl-Insert      | With a selection: copies it                                                                                                                              |
| Enter                                  | With a selection: copies it and goes back to the latest output                                                                                           |
| Right click                            | Copies the selection                                                                                                                                     |
| Esc                                    | With a selection: clears it                                                                                                                              |
| F3                                     | Finds text: type the query, Enter accepts the match, Ctrl-P/Ctrl-N go to the older or newer one, Esc cancels                                             |
| F4                                     | Focuses the latest activity (a tool call, a thinking): Up/Down move between them, Enter or a click on its control shows or hides its details, Esc leaves |

The footer under the conversation shows the keys of a selection, a search or a focused activity while it lasts. A copy goes to the system clipboard; where there is none (over SSH, say) it is sent to the terminal (OSC 52), which most terminals put on their clipboard, and the interface says it is unconfirmed. A copy's result shows above the composer for a few seconds.

While an approval, a question or a list is open, the keys are its own; the mouse still scrolls and selects, and Ctrl-C copies a selection.

Fullscreen captures the mouse, so the terminal's own selection usually needs Shift held while you drag. To copy with the terminal's selection, `/raw` shows the conversation without its styles.

Each time the session's context is compacted, the conversation shows `• Context compacted` where it happened: after `/compact`, when a turn compacts it (at the threshold, when the model asks for a new context, after the Provider's context-window error), and when a turn installs a compaction that ran [in the background](/docs/config-reference#compaction). A resumed session shows its earlier compactions the same way.

## The transcript [#transcript]

In Scrollback, Ctrl-T opens the whole session's transcript (`T R A N S C R I P T`) on the terminal's alternate screen; `/diff` shows its diff the same way. In Fullscreen, Ctrl-T shows the conversation in detail in place instead (above), and `/diff` covers the screen until you close it.

| Key                                              | Does                    |
| ------------------------------------------------ | ----------------------- |
| Up/Down (`k`/`j`)                                | Scrolls one line        |
| Page Up/Page Down (Space, Ctrl-B/F)              | Scrolls one page        |
| Ctrl-U/Ctrl-D                                    | Scrolls half a page     |
| Home/End                                         | To the start or the end |
| `q`, Esc, Ctrl-C; for the transcript also Ctrl-T | Closes it               |

The transcript shows every thinking's text and a tool call's whole output, where the scrollback shows its first and last lines, and the tool calls still running after what has completed. Its selection, copying and search are the ones of [Reading the conversation](#reading) (drag, Ctrl-Space, F3).

The turn goes on while a pager is open, and what it writes meanwhile appears in the transcript at once and in the scrollback once you close it.

## Editing an earlier message [#edit]

On an empty composer, with no turn running and nothing open, Esc shows `esc again to edit a previous message`; any other key cancels it. A second Esc browses your messages with the latest highlighted: in place in Fullscreen, in the transcript in Scrollback, in the compact presentation either way. The footer reads `Browsing · ←/→ prompt · ↑/↓ scroll · ctrl+t details · ↵ edit · esc back`.

| Key           | Does                                           |
| ------------- | ---------------------------------------------- |
| ←/→ (`h`/`l`) | The earlier or the later message               |
| ↑/↓ (`k`/`j`) | Scrolls one line                               |
| Ctrl-T        | Shows or hides the details                     |
| Enter         | Edits the highlighted message                  |
| Esc           | Back to where browsing started, nothing edited |

In Fullscreen the conversation's other keys (Page Up/Page Down, Home/End, F3) still work, and any other key ends browsing; in Scrollback the transcript's keys work, and `q` closes it.

Enter edits in a copy of the session: it is forked before the message's turn and the interface switches to the fork, whose conversation ends before the message, with the message back in the composer to change and send. The original session is archived, whole: `hanafubuki-agent sessions list --archived` finds it ([Sessions](/docs/sessions#edit)). Files the Agent changed are not restored, which the first edit of a run says. Images the message had are not put back, since the composer cannot attach them; a line says how many.

- A message sent while a turn ran (steering) did not start a turn of its own and cannot be edited by itself: edit the message that started the turn.
- While a turn runs, Esc interrupts it, as before; the edit is refused until no turn runs.
- With no message yet, the second Esc says `No previous message to edit.` In Fullscreen, browsing reaches the messages loaded so far; scrolling up loads earlier ones. In Scrollback, those of a resumed session's latest 200 items.

## Thinking [#thinking]

While the model thinks, the conversation shows a `• Thinking 5s` line that counts up, collapsed by default; the status line stays `Working`. Ctrl-O expands it to the thinking as the model streams it (dim Markdown) and collapses it again. The choice applies to the thinking shown now and to every later one until you press Ctrl-O again, for as long as the interface runs. While thinking is live, the footer says `ctrl + o to show thinking` (or `to hide thinking`).

When the thinking ends, it is written into the scrollback as it is shown at that moment: `• Thought for 12s` (whole seconds, rounded down) when collapsed, or that line and the text when expanded. A Provider that sends no text leaves only the line. Thinking that ends while an answer streams is written after that answer, so the scrollback keeps the model's order. If the turn ends before the thinking does (an error, an interrupt), the line is completed with the time so far. Scrollback cannot be changed afterwards, but the transcript (Ctrl-T, in Fullscreen the detailed conversation) always shows every thinking's text. A resumed session replays its thinking the same way, collapsed unless Ctrl-O expanded thinking; a thinking whose text was cut at the Agent's bound says `• Thought for 12s (truncated)`.

What you see depends on what the Provider sends: some send a summary of the thinking, some the raw thinking text, some nothing. See [Providers and models](/docs/providers-models#reasoning).

## Approvals [#approvals]

A tool call the [permission mode](/docs/permissions) asks about opens an approval with the kind of operation (such as `Would you like to run the following command?`), its summary and its risk level:

| Option                                                                                              | Key        |
| --------------------------------------------------------------------------------------------------- | ---------- |
| `Yes, proceed`: allows it once                                                                      | `y` or `1` |
| `Yes, and don't ask again this session`: allows the same for the rest of the session (when offered) | `a` or `2` |
| `No`: denies it                                                                                     | `n` or Esc |

A command the model asks to run [outside the sandbox](/docs/permissions#escalation) says so in its summary, with the model's question (`… outside the sandbox in DIR: COMMAND (reason: QUESTION)`); allowing it for the session allows only that command outside the sandbox again.

Up, Down and Enter pick an option too. Ctrl-C denies the open request and every one waiting behind it. Further requests wait their turn. The conversation records `✔ You approved …` or `✗ You did not approve …`.

An approval a subagent waits on is shown the same way in its parent, its summary starting `Subagent NAME:` ([Subagents](#subagents)).

## Questions [#questions]

The model can ask you one or more questions, each with a few options. The interface shows `Question 1/2`, the question and its options:

- Up/Down (`k`/`j`) select, Enter confirms and moves on, and on the last question submits.
- A number picks that option and moves on.
- Left goes back a question, Right or Tab forward.
- Esc or Ctrl-C interrupt the turn.

You answer by picking an option; there is no free text.

## Resuming a session [#resume]

```sh
hanafubuki-agent resume                    # the resume picker
hanafubuki-agent resume 12                 # session 12
hanafubuki-agent resume --last             # the latest session a turn ran in
hanafubuki-agent resume 12 "Carry on"      # resume, then send a message
```

The resume picker lists the sessions a turn ran in, the latest first: when each was last updated, the Git branch and the directory it was created in (when any session has them), and its title (the first message until the session is named). Child sessions are not listed. Type to search the titles; Up/Down and Page Up/Page Down move, Enter resumes, Esc goes back (at `resume`'s start, to the interface with no session), and Ctrl-C quits.

- **Archived sessions.** Tab switches between the sessions and the archived ones. Ctrl+A archives the selected session, or, in the archived list, restores it (Enter restores there too); it leaves the list. The session the interface shows is not archived from here: `/archive` does that.
- **From the interface.** `/resume` opens the picker. `/resume ID` resumes the session with that id, and `/resume TITLE` the one session with that title; when no session, or several, have it, the picker opens searching for it.

A resumed session shows its box and its latest 200 items: messages, the plans the model proposed, tool calls with their output, and context compactions. In Fullscreen the earlier items are read 200 at a time as you scroll up to them (`↑ Loading earlier messages…`); a tool call whose output was read before its call shows without its output. In Scrollback they are left out, with `Earlier messages are not shown.` Your next message continues the session.

With no session to resume, `resume --last` starts with no session, as `hanafubuki-agent` does. `hanafubuki-agent sessions list` shows the session ids; see [Sessions](/docs/sessions).

## Quitting [#quit]

Type `/quit` or `/exit`, or press Ctrl-C twice within one second (or Ctrl-D twice on an empty composer). Quitting restores the terminal (in Fullscreen, leaving the alternate screen, and the conversation with it) and shuts the Agent down, and prints nothing more.

The exit code is 0; 1 when the Agent could not start, the session to resume could not be opened or given the `-m` model, or the terminal could not be used; 2 without a terminal.

## Syntax highlighting [#highlighting]

Fenced code in an answer (` ```rust `) is highlighted by its language: a name, an alias or a file extension. A block with no language, or in one the interface does not know, keeps its plain text. A diff (a patch's, `/diff`'s) is highlighted by each file's extension; the `+` and `-` keep their colors and a removed line is dimmed. Code over 512 KiB or 10,000 lines, or with a line over 4 KiB, is not highlighted.

The grammars and the 32 themes are the ones [two-face](https://github.com/CosmicHorrorDev/two-face) bundles, curated from bat. `/theme` lists them with the custom themes:

- Moving through the list makes the highlighted theme the one in use, shown on a sample diff: beside the list in a wide terminal, under it otherwise. Typing filters the list.
- Enter keeps the theme and saves it as `tui.theme`. Esc and Ctrl-C put back the theme in use when the list opened.
- A custom theme is a `.tmTheme` file in the `themes/` directory of the [data directory](/docs/data-directory#contents), named by its file name without `.tmTheme`. A file that cannot be read as a theme is not listed; a custom theme with a bundled theme's name is the bundled one.
- Without `tui.theme` the theme is `ansi`, which colors with the terminal's own palette and so reads on a light background as on a dark one. A `tui.theme` that names no theme, or a custom theme that cannot be read, is a [warning](#warnings), and the default is used.
- What the conversation already shows keeps the colors it was drawn with.

## The keymap [#keymap]

Each action in the table below has default keys, and `tui.keymap.CONTEXT.ACTION` changes them: one key or a list of them, `[]` to unbind the action. An action takes its context's entry, else `tui.keymap.global.ACTION` (when no global action has that name: `global.page_up` sets both `transcript.page_up` and `pager.page_up`), else its default keys.

```toml
[tui.keymap.global]
open_transcript = "ctrl-g"
leader = "ctrl-b"

[tui.keymap.chat]
toggle_thinking = ["ctrl-o", "f2"]
open_presets = "ctrl-b 1"

[tui.keymap.editor]
yank = []
```

- **Keys** are modifiers then a key, joined with `-`: `ctrl-t`, `alt-<`, `shift-enter`, `page-down`, `f3`, `space`, `minus`; an upper-case letter is `shift-` and the letter.
- **Chords** are two keys separated by a space (`ctrl-g o`): the first waits a second for the second. `leader K` is the leader key (`global.leader`, Ctrl-X by default) then `K`; the leader waits until the next key. A key that completes no chord, or Esc, drops both. A configured key that is the default leader's takes it: the leader is then unbound unless `global.leader` sets one.
- **Contexts** are where the keys are read: `global` everywhere, `chat` and `composer` while the composer has the keys, `editor` in every text field, `transcript` in the Fullscreen conversation beside the composer, `pager` in the transcript and `/diff`. Beside the composer, a key that types text (a letter without Ctrl or Alt) cannot be bound, and neither can a chord that starts with one.
- **Conflicts**: one key (or chord) cannot trigger two actions read together, nor start another action's chord, nor be Ctrl-C (or Ctrl-D but in the editor and the pagers), which the interface keeps. The pairs that share keys by default stay allowed: `chat.interrupt_turn` and `chat.edit_previous` (Esc), `composer.submit` and `editor.insert_newline` (Enter), the history and the editor's Up and Down, `global.open_transcript` and `pager.close_transcript`.
- What cannot be used (an unknown context or action, a key that is not one, a conflict) leaves the action its default keys, with a [warning](#warnings).

`/keymap` lists the actions with their keys (type to search). Picking one offers to replace its keys or add one (a key, two keys, or the leader and a key), to remove one, to unbind it, and to put its defaults back. A new key is captured as it is pressed (Esc cancels); one that conflicts is refused with the reason, and another can be tried. A change is saved into `tui.keymap` and applies at once. `/keymap debug` lists every action's keys, each marked `default` or `configured`.

Popups, lists, forms, approvals and questions keep their own keys (arrows, Enter, Esc, Tab), and so do a selection, a search and select mode in the conversation, and browsing the earlier messages.

## Presets [#presets]

A preset is an input kept in a slot from 0 to 9 (`tui.presets."N"`), with an optional label: run, it goes through the slash commands as if typed and sent, so it is a message or a command such as `/status` or `/statusline git-branch --colors`. Its input cannot be empty, longer than 8,000 bytes, or start with `!`.

`/presets` (or Ctrl-X P) lists the slots:

| Key     | Does                                                                                                                                         |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`–`9` | Runs that slot's preset                                                                                                                      |
| Enter   | Runs the selected one                                                                                                                        |
| `n`     | A new preset: its slot (the first free one), input and label                                                                                 |
| `s`     | A new preset from the current settings: the session's `/permissions …`, the terminal title's `/title …` or the status line's `/statusline …` |
| `e`     | Edits the selected one                                                                                                                       |
| `d`     | Deletes the selected one, after `y`                                                                                                          |

`/model` takes no argument in this interface, so the model cannot be a preset. A preset that a profile, the project's file or `-c` sets wins over the user's file: saving into its slot says so.

## Settings [#config]

`/config` gathers the `[tui]` settings and the compaction strategy: Space or Enter turns one on or off (Left and Right for a choice), and each change is applied and saved at once.

| Row                | Key                        | Applies                                                                          |
| ------------------ | -------------------------- | -------------------------------------------------------------------------------- |
| Raw output         | `tui.rawOutput`            | At once, as `/raw`                                                               |
| Status line colors | `tui.statusLineColors`     | At once                                                                          |
| Fullscreen         | `tui.fullscreenTranscript` | At the next launch                                                               |
| Alternate screen   | `tui.alternateScreen`      | At the next launch                                                               |
| Compaction         | `compaction.strategy`      | At each session's next turn; see [Compaction](/docs/config-reference#compaction) |

Its other rows open the editors: Providers (`/providers`), MCP servers (`/mcp`), Memories (`/memories`), Theme (`/theme`), Status line (`/statusline`), Terminal title (`/title`), Keyboard (`/keymap`), Presets (`/presets`) and Interface mode (`/tui`).

## Warnings [#warnings]

What the interface or the Agent could not use as configured is kept for the run, and `/warnings` lists it, newest first, each once, counted by source:

- **configuration**: what reading `config.toml`, `providers.toml` and `mcp.toml` had to repair ([Configuration recovery](/docs/recovery)), and what a layer of `config.toml` holds that the settings cannot use: an unknown key, or a value the layer below replaces;
- **plugins**: a plugin that failed, or that is left out of turns;
- **MCP**: a server's latest error or warning, and what reading `mcp.toml` repaired;
- **hooks**: the hooks' configuration problems;
- **panics**: the internal errors the Agent caught;
- **interface**: a command turned off after an internal error, a theme or an item of `[tui]` it does not know, a keymap entry it could not use.

When there are any at launch, one line says how many (`2 warnings: /warnings`). In the list, `c` copies the selected warning and `d` dismisses it for the rest of the run. With none, `/warnings` says `No warnings.`

## Terminal requirements [#terminal]

- The terminal must answer the cursor-position query, or the interface cannot start.
- Only the basic ANSI colours, bold, dim and italic are used.
- Fullscreen uses the alternate screen and the mouse (SGR reporting).
- In Scrollback, the pagers and the resume picker use the alternate screen, where the mouse wheel acts as the arrow keys; the transcript captures the mouse for its selection.
