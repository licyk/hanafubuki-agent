**Provider** 是一个模型服务：一个接口地址、一种协议，以及可选的 API 令牌。可以配置多个 Provider，其中一个是**默认 Provider**，新会话在它上面运行。**模型策略**决定新会话使用的模型、推理强度和上下文压缩方式，对所有 Provider 生效。

Provider 和模型策略都保存在配置目录的 `providers.toml` 中，见[配置参考](/docs/config-reference#providers-toml)。

## 协议 [#protocols]

| 协议               | `--protocol`         | 请求路径（追加在接口地址后） | 认证                                                 | 常见服务                                      |
| ------------------ | -------------------- | ---------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| OpenAI Responses   | `responses`（默认）  | `responses`                  | `Authorization: Bearer 令牌`                         | OpenAI、vLLM 等兼容服务                       |
| Chat Completions   | `chat-completions`   | `chat/completions`           | `Authorization: Bearer 令牌`                         | DeepSeek、OpenRouter、Ollama 等大多数兼容服务 |
| Anthropic Messages | `anthropic-messages` | `messages`                   | `x-api-key: 令牌` 和 `anthropic-version: 2023-06-01` | Anthropic                                     |

接口地址末尾的 `/` 可有可无，协议的路径直接追加在它后面：`https://api.openai.com/v1` 加上 `responses` 就是 `https://api.openai.com/v1/responses`。地址中的查询参数会保留。模型列表从同一地址的 `models` 读取。

## 添加 Provider [#add]

<Tabs items={["OpenAI", "Anthropic", "Chat Completions", "本地服务"]}>
  <Tab value="OpenAI">
    ```sh
    hanafubuki-agent providers add OpenAI --base-url https://api.openai.com/v1 --api-key-env OPENAI_API_KEY
    ```
  </Tab>
  <Tab value="Anthropic">
    ```sh
    hanafubuki-agent providers add Anthropic --protocol anthropic-messages \
      --base-url https://api.anthropic.com/v1 --api-key-env ANTHROPIC_API_KEY
    ```
  </Tab>
  <Tab value="Chat Completions">
    ```sh
    hanafubuki-agent providers add DeepSeek --protocol chat-completions \
      --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY
    ```

    接口地址填到 `chat/completions` 之前的部分即可。

  </Tab>
  <Tab value="本地服务">
    ```sh
    hanafubuki-agent providers add Ollama --protocol chat-completions --base-url http://127.0.0.1:11434/v1
    ```

    不需要令牌的服务可以省略 `--api-key-env`。

  </Tab>
</Tabs>

- `--api-key-env 变量` 在添加时从环境变量读取令牌，并原样保存在 `providers.toml` 中（仅自己可读）。令牌不能直接写在命令行上，避免留在 Shell 历史里。变量没有设置时，命令以退出码 2 退出。
- `--header 名称=值` 添加一个随该 Provider 的每个请求发送的请求头（可重复），保存在 `providers.toml` 中。与令牌不同，它的值写在命令行上。
- `--disabled` 添加一个禁用的 Provider。
- 命令打印新 Provider 的 ID，例如 `added provider-2`。ID 是最小的空闲 `provider-N`。

## 管理 Provider [#manage]

```sh
hanafubuki-agent providers list
hanafubuki-agent providers default provider-2 --model deepseek-chat
hanafubuki-agent providers remove provider-1
```

```text
model: gpt-5.1
provider-1 OpenAI (default)  Responses  https://api.openai.com/v1  token: set
provider-2 DeepSeek  ChatCompletions  https://api.deepseek.com/v1  token: set
```

- 第一个添加的 Provider 成为默认 Provider。默认 Provider 被删除或禁用时，默认改为列表中第一个启用的 Provider。
- `providers list` 从不打印令牌和请求头的值。
- 更换令牌或请求头（`requestHeaders`）、启用 Provider，可以在终端界面中使用 `/providers`（[见下文](#interface)），也可以编辑 `providers.toml`（编辑前请先退出正在运行的 Agent）。

## 在终端界面中 [#interface]

[终端界面](/docs/terminal-interface#providers)中的 `/providers` 在 Provider 处打开[设置中心](/docs/terminal-interface#config)，可以完成上面这些命令的工作，并直接编辑 Provider：

- **Provider 列表**：每个 Provider 显示协议和基础 URL，默认的一项旁标有 `default`，停用的旁标有 `off`。`a` 添加一个（它的字段由 **Add a Provider** 一起保存），`d` 确认后删除，Enter 打开。
- **Provider**：名称、是否启用、协议（`responses`、`chat_completions` 或 `anthropic_messages`）、基础 URL、API 令牌和请求头，每个字段改动时即保存。已设置的令牌显示为 `••••`，从不返回：输入新值会替换它，`r` 删除它。请求头是 `NAME=VALUE` 形式的条目，只按名称列出：它们的值从不显示，只写名称的条目保留原来的值。
- **Make default** 把它设为默认 Provider，**List models** 测试它（显示 Provider 列出的模型数量和前几个，或 Provider 返回的错误），**Delete** 确认后删除它。
- **Choose the model** 列出它的模型，每个模型旁显示目录报告的信息：窗口（`200K`）、`vision` 和 `reasoning`（`/model` 也一样）。选中的模型（Provider 没有列出时，用 **Enter a model id…** 手动输入）成为新会话使用的模型，这个 Provider 成为默认 Provider。按 Esc 则保持原来的模型。`/model` 仍然只修改当前会话的模型。
- **模型策略**（`/providers policy`，或 Model 标签页中的 Model policy）：默认 Provider 和模型、推理强度（旁边写出该模型已知的档位，来自其目录或其[单独设置](#per-model)）、图片输入、上下文窗口（未设置时，旁边写出该模型已知的窗口及其来源）、自动压缩及其阈值、远程压缩，以及 **Custom turn budget**：关闭时回合使用 Agent 的上限；打开时是它的十一个字段，从这些上限开始。模型的单独设置不在其中：它们是 Model 标签页中它旁边的 **Model overrides**（[按模型的设置](#per-model)）。
- 每次写入都会带上设置中心读取时 `providers.toml` 的版本。如果期间文件被其他地方修改（例如另一个终端中的 `providers` 命令），写入会被拒绝：设置中心重新读取 Provider，保留改动并给出提示，再保存一次即可。
- 没有默认 Provider 或没有模型时，界面启动时会自动在 Provider 处打开设置中心，见[首次设置](/docs/terminal-interface#setup)。

## 模型 [#model]

| 方式                           | 作用范围                                                     |
| ------------------------------ | ------------------------------------------------------------ |
| `providers default ID --model` | 模型策略中的模型：之后所有新会话的默认模型                   |
| `-m 模型`                      | 本次运行中的新会话（以及恢复的会话），在默认 Provider 上运行 |
| 终端界面的 `/model`            | 当前会话；从已启用 Provider 的模型目录中选择                 |

`/model` 列出每个已启用 Provider 的模型目录（从 `models` 接口读取）。某个 Provider 的目录无法读取时，列表会显示原因。Agent 从目录中的每个模型读取它报告的上下文窗口和最大输出（见[上下文窗口与压缩](#compaction)）、是否读图（见[图片](#images)），以及是否推理、支持哪些推理强度（见[推理强度与思考过程](#reasoning)）。目录报告的内容保存在数据目录的 `model-metadata.json` 中，重启后依然有效；之后的目录不再列出的模型会再保留 7 天。Agent 也会自己在后台读取目录：启动时读取默认 Provider 的目录；在某个 Provider 上创建会话、选用它的模型或在它上面运行轮次时，读取该 Provider 的目录，每个 Provider 每天最多一次（目录读取失败后每 15 分钟最多一次）。没有什么会等待它，读取失败的目录只是稍后再试。在 `config.toml` 中设置 `modelMetadata.discovery = "off"` 可以关闭它（[配置参考](/docs/config-reference#model-metadata)）；你打开的目录仍会被读取和保存。没有可用 ID 的模型会被略去，无法读取的字段视为未报告，所以一个异常的模型不会让整个目录读取失败。`doctor --online` 会检查默认 Provider 是否能列出模型，并显示对每个模型所知道的信息。宿主可以在保存 Provider 之前读取它的模型目录，以测试地址、令牌和请求头（`test_provider_draft`，见[嵌入 Agent](/docs/embedding#configuration-in-a-host)）。

## 推理强度与思考过程 [#reasoning]

推理强度在 `providers.toml` 的 `[modelPolicy]` 中设置，命令行上没有对应的选项：

```toml
[modelPolicy]
model = "gpt-5.1"
reasoningEffort = "medium"   # minimal、low、medium、high、xhigh
```

每种协议都会发送推理强度，各用自己的字段：

| 协议               | 请求发送的内容                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Responses          | `reasoning: {effort, summary: "auto"}`                                                                                                                                                                          |
| Chat Completions   | `reasoning_effort`，OpenAI 的字段，DeepSeek 的文档也列出了它，OpenRouter 把它列在参数中（其推理指南对 Anthropic 模型只提到它的 `reasoning` 对象）                                                               |
| Anthropic Messages | Claude 4.6 及以后：自适应思考 `thinking: {type: "adaptive", display: "summarized"}`，加上 `output_config: {effort}`（`minimal` 按 `low` 发送）。Claude 4.5 及以前，以及 ID 不是 Claude 的模型：思考预算，见下文 |

没有设置推理强度时，请求不携带它，由 Provider 的默认值决定。`/status` 会显示当前会话的推理强度；当对模型已知的信息改变了它时，还会显示实际发送的值（`reasoning xhigh, sends high`，或 `not sent: the model takes none`）。

请求实际携带的推理强度还取决于对该模型已知的信息，这些信息来自 Provider 的模型目录或 Provider 的拒绝：

| 已知的信息             | 发送的推理强度                                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一无所知               | 设置的推理强度                                                                                                                                                                                                                                  |
| 会推理，目录列出了档位 | 设置的推理强度在列表中则用它；否则它的别名在列表中则用别名（`minimal` → `low`，`xhigh` → `max`）；否则用 `minimal < low < medium < high < xhigh < max` 上最近的已列出档位，距离相同时取较低者；否则不发送。发生改变时，每个会话记录一次警告日志 |
| 会推理，目录未列出档位 | 设置的推理强度                                                                                                                                                                                                                                  |
| 不接受推理参数         | 不发送，无论设置了什么                                                                                                                                                                                                                          |

目录用 `supported_reasoning_levels`（Codex）、`reasoning.supported_efforts`（OpenRouter）或 `capabilities.effort`（Anthropic）列出档位；`none` 不会作为档位，因为推理强度不接受 `none`：不设置推理强度，或模型不接受推理参数，才是请求不带推理的方式。模型自己的 `reasoningEfforts`（[按模型的设置](#per-model)）会取代目录列出的档位，或声明它不接受推理参数。模型策略中的模型有已知档位时，策略表单会以选项而不是文本框提供它们。

Provider 拒绝推理参数时（状态码 400 或 422，并指名该参数，见[内部实现](/docs/internals#reasoning-refusals)），请求会去掉它重发一次（`exec --json` 报告 `model_retry_scheduled`，阶段为 `reasoning_fallback`），之后 7 天内无论目录怎么说，都认为该模型不接受推理参数，这一点保存在 `model-metadata.json` 中，直到被[遗忘](#forget)。在模型自己的 `reasoningEfforts` 下，请求仍会去掉推理参数重发，但下一次请求会再次携带推理强度。

**Anthropic 的思考预算。** 对于使用预算的模型，推理强度决定 `budget_tokens`：

| 推理强度                     | `budget_tokens` |
| ---------------------------- | --------------- |
| `minimal`                    | 1,024           |
| `low`                        | 4,096           |
| `medium`，或此处未列出的强度 | 8,192           |
| `high`                       | 16,384          |
| `xhigh`                      | 24,576          |
| `max`                        | 32,000          |

`max_tokens` 为预算加上留给回答的 16,384，但不超过模型的最大输出；最大输出未知时，它保持 16,384，并缩减预算，为回答留出其中的 4,096。保不住 1,024 个 token 的预算不会发送。强制调用某个工具的请求，以及回应的工具调用所在消息中没有可回传思考块的请求，也不会带上预算思考。使用自适应思考时，`max_tokens` 为 32,768，且不超过模型的最大输出；最大输出未知时为 16,384。

模型的思考过程会显示出来，在终端界面中每一段思考是一个 `Thinking` 条目，点击或 Ctrl-O 可以展开它的文本（见[终端界面](/docs/terminal-interface#thinking)），在 `exec --json` 中是 `reasoning_*` 事件（见 [exec --json 事件](/docs/json-events#reasoning)）；`exec` 的普通输出和 `sessions show` 只显示思考了多久（`thought for 12s`）。能看到什么取决于 Provider：

| 协议               | 思考内容                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| Responses          | 设置了推理强度时，Agent 会请求思考摘要；兼容服务（例如 vLLM 上的 gpt-oss）也可能发送原始思考文本 |
| Chat Completions   | 服务在 `reasoning_content` 或 `reasoning` 中发送的内容（DeepSeek、Qwen、OpenRouter 等）          |
| Anthropic Messages | 请求的自适应思考摘要，或预算允许的思考内容；服务未经请求发送的 `thinking` 块也会显示出来         |

思考内容保存在会话历史中，每一段最多 256 KiB，超出的部分被截断。这些文本只用于显示，不会再发送给模型。有两种协议要求回传思考，Agent 照做：

- **使用预算的 Anthropic 思考**：本轮的思考块会连同签名原样随它之前的工具调用回传，仅限该轮剩余的请求。它们只保存在内存中，从不写入历史，所以重启后恢复的轮次，下一个请求不带思考。自适应思考不回传任何思考块：Anthropic 允许在此省略它们，而它最新的模型会拒绝前文已改变的思考块，Agent 的请求在步骤之间恰恰会改变前文。
- **Chat Completions 的 `reasoning_content`**（DeepSeek 的思考模式：带工具的请求中，之前的助手消息缺少它就会被拒绝）：以 `reasoning_content` 到达的每一段思考，其完整文本（最多 1 MiB）作为它之前那条助手消息的 `reasoning_content` 回传，来自仍在上下文窗口中的每一轮，压缩的请求也一样，无论是否设置了推理强度。它随消息写入历史，所以恢复的会话也会发送它。以 `reasoning`（OpenRouter 的字段）到达的思考不回传。没有文本可回传的助手消息（Agent 开始回传之前的消息，或思考超过 1 MiB 的消息）不带这个字段发送；只要这样的消息还在上下文窗口中，带工具的 DeepSeek 就可能拒绝该会话的请求，包括压缩的请求：这时请新建会话。

## 上下文窗口与压缩 [#compaction]

模型的上下文窗口依次取自：模型自己的 `contextWindowTokens`（[按模型的设置](#per-model)）、`[modelPolicy]` 中的 `contextWindowTokens`、Agent 从 Provider 的拒绝中学到的窗口（见下文，仅在它更小时）、Provider 模型目录最近一次报告的值、你打开 [models.dev](#models-dev) 时它给出的值、内置的常见模型表（如 GPT-5 系列、Claude、Gemini 2.5）。都没有时不会自动压缩。会话在创建或选择模型时、读取它的 Provider 的模型目录时（在后台，或由 `/model`、`/providers` 或测试读取）、它的每个轮次开始时以及模型每次回答之后取得窗口。所以在读取模型目录之前创建的会话一读到目录就得到窗口，不必等到轮次（此时正在回答的会话在那次回答之后得到），你在 `providers.toml` 中设置或修改的窗口在下一个轮次生效。你设置的窗口优先。当没有任何来源再知道模型的窗口时，会话保留它已有的窗口，除非那是设置的、学到的或来自 models.dev 的、而现在已不存在（被删除、被[遗忘](#forget)，或关闭了 models.dev）：这时它的窗口重新变为未知。`/status` 显示窗口及其来源：`200K (reported)`、`128K (models.dev)`，或 `unknown (compacts on the Provider's error)`。

上下文用到窗口的 `autoCompactThresholdPercent`（默认 80%）时，Agent 会在回合开始前或回合中自动压缩：把较早的对话总结成摘要，保留最近的消息。如果窗口剩下的部分已容不下一次回复，它会更早压缩：为模型的最大输出留出空间（模型目录没有报告时按 32,768 token 计），但最多为窗口的十分之一、至少 4,096 token，且不超过窗口的一半。所以在默认的 80% 下，窗口在 20,480 token 及以上时由阈值决定，而在 10,000 的窗口上 Agent 在 5,904 时压缩。

上下文是 Provider 报告的上一次请求的提示总量：每个输入 token，无论是否从提示缓存读取，以及写入缓存的 token。Responses 和 Chat Completions 协议报告的就是这个总量；Anthropic 把缓存分开报告，Agent 把它加回去。所以在 Anthropic 上，主要由缓存提供的对话与其他协议在同样的大小达到阈值；0.3 之前只计它未缓存的输入，压缩得比应有的晚。`/status`、状态栏、回合的输入 token 预算和[目标](/docs/sessions#goals)的 token 预算计的都是同一个总量。

Provider 以超出模型窗口为由拒绝请求时，Agent 会压缩一次并重试；再次被拒时回合失败（`context_window_exceeded`）。它还会从拒绝中学习：拒绝中写明的窗口（`maximum context length is 131072 tokens`），或在没有写明时，被拒请求的大小（窗口一定比它小）。会话立即采用这个窗口，于是重试和之后的轮次会在窗口填满前压缩，对话中也会提示（`The Provider refused the request as too long; this model's window is taken as 131072 from now on.`）。此后同一 Provider 上同一模型的每个会话都从这个窗口开始，重启后也一样，为期 7 天；在此之前只有更小的窗口才会替换它，[遗忘](#forget)则会丢弃它。即使关闭了自动压缩也会学习，且从不替换你设置的 `contextWindowTokens`。

| 设置                          | 默认值       | 作用                                                                                       |
| ----------------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `autoCompactionEnabled`       | `true`       | 是否自动压缩                                                                               |
| `autoCompactThresholdPercent` | `80`         | 触发自动压缩的比例                                                                         |
| `remoteCompaction`            | `"disabled"` | 设为 `"responses_compact"` 或 `"responses_compact_v2"` 时，在 Responses 协议上由服务端压缩 |
| `contextWindowTokens`         | 未设置       | 指定上下文窗口                                                                             |

已有会话在下一轮次或 `/compact` 时采用修改后的 `remoteCompaction`，在下一轮次采用修改后的 `contextWindowTokens`（策略的或模型自己的）；其他键在会话重新选择模型（`/model`）时才采用，新会话则全部采用。除这种压缩外如何缩减上下文，由 `config.toml` 中的[压缩策略](/docs/config-reference#compaction)决定。

在终端界面中输入 `/compact` 可以立即压缩。`/status` 显示 token 用量和上下文剩余比例。

## 图片 [#images]

`[modelPolicy.inputCapabilities]` 的 `imageInput` 为 `"auto"`（默认）时，Agent 是否向模型发送图片（你的图片，以及 `view_image` 查看的图片），取决于它对这个模型所知道的：

- **它读图**（Provider 的模型目录这样说，或在其他来源都没说时 [models.dev](#models-dev) 这样说），或者**没有任何来源说明**：发送图片，并提供 `view_image`。如果模型仍然拒绝了图片，Agent 会去掉图片重试一次，并从此在 7 天内（重启后也一样）把它当作不读图的模型。
- **它不读图**（模型目录这样说，或从拒绝中学到）：不会有图片发给它，所以不会先有请求被拒绝。对话中已有的图片会被替换成一条说明图片已略去的文字，不提供 `view_image`，带图片的消息会被拒绝（`the configured model does not support image input`）。

拒绝的分量重于目录：目录说读图、却拒绝过图片的模型，在这 7 天内不会收到图片，直到被[遗忘](#forget)。对话在开始、选用模型或恢复时采用已知的信息，并在每次请求前再取一次，所以之后才读到的目录从下一次请求起生效。模型自己的 `imageInput`（[按模型的设置](#per-model)）分量重于这两者：`"supported"` 不论目录怎么说、拒绝教了什么都发送图片，`"unsupported"` 从不发送。策略中的 `"disabled"` 则无论模型及其单独设置如何都从不发送图片。

## 按模型的设置 [#per-model]

目录对模型的报告，或者 Agent 学到的东西，可能是错的；一份策略也无法描述同一 Provider 的两个模型。模型自己的设置写在 `providers.toml` 中它的 Provider 之下，只对这个模型生效，分量重于这两者：

```toml
[[providers]]
id = "provider-1"
# …

[providers.models."qwen3-coder"]
contextWindowTokens = 262144
maxOutputTokens = 65536
imageInput = "unsupported"
reasoningEfforts = []

[providers.models."openai/gpt-4.1"]
imageInput = "supported"
```

| 键                    | 取值                                             | 作用                                                                                                                                                                 |
| --------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contextWindowTokens` | 正整数                                           | 模型的窗口，优先于 `[modelPolicy]` 的 `contextWindowTokens`、学到的窗口和目录报告的窗口                                                                              |
| `maxOutputTokens`     | 正整数                                           | 模型的最大输出，阈值为它留出空间，Anthropic 的思考预算也按它计算（[上下文窗口与压缩](#compaction)、[推理强度与思考过程](#reasoning)）                                |
| `imageInput`          | `"auto"`（默认）、`"supported"`、`"unsupported"` | `"auto"` 按已知的信息（[图片](#images)）；`"supported"` 不论目录怎么说、拒绝教了什么都发送图片：拒绝仍会让那次请求回退，下一次请求再次发送；`"unsupported"` 从不发送 |
| `reasoningEfforts`    | 推理强度的列表，或 `[]`                          | 模型接受的档位，取代目录列出的档位，发送的推理强度按它收窄、策略表单也提供它们；`[]`：不接受推理参数，不发送推理强度                                                 |

每个键都可省略，省略的键交给其他来源。会话在下一个轮次开始时采用它们（新会话、恢复的会话以及已打开的会话都一样），所以退出 Agent、编辑文件，然后继续即可。无法使用的值会被略去，文件会被[修复](/docs/recovery)，Provider 及其其他设置都保留。它们也可以在[设置中心](/docs/terminal-interface#config)的 Model 标签页中的 **Model overrides** 编辑：每个 Provider 和模型一条记录（`a` 添加一条，以 `PROVIDER/MODEL` 命名，第一个 `/` 之后都是模型 ID），每个键改动时即保存，`r` 取消设置它，每次写入都带上设置中心读取时 `providers.toml` 的版本。Provider 自己的保存和 `providers` 命令会原样保留它们。

## 遗忘学到的信息 [#forget]

Agent 从 Provider 的拒绝中学到的信息（更小的窗口、模型不读图、不接受推理参数、不支持结构化输出或强制工具）保持 7 天。要在此之前再试这个模型，就遗忘它：

- 终端界面中的 `/model forget`，针对会话的模型；
- `hanafubuki-agent providers forget ID [--model MODEL]`，针对该 Provider 的一个模型或它的全部模型（[命令行参考](/docs/cli-reference#providers)）。

目录报告的信息、[models.dev](#models-dev) 的副本和按模型的设置都保留。会话在下一个轮次或模型的下一次回答之后采用这一变化：它的窗口变为其他来源所知道的窗口，什么都不知道时则为未知。

标题、回顾、记忆提取和自动权限审查都会向模型要一个小的 JSON 回答。Agent 用协议自己的结构化输出（Responses 和 Chat Completions）或强制调用一个工具（Anthropic）来要它；Provider 或网关以状态码 400 或 422 拒绝时，立即改为强制调用工具再要一次，再不行就以纯文本要，模型记住行得通的方式 7 天，所以一周只有第一个请求会被拒绝（[内部实现](/docs/internals#structured-output-rungs)）。遗忘后会重新尝试协议自己的方式。

## models.dev [#models-dev]

[models.dev](https://models.dev) 是一个按提供商列出模型的公开目录。在 `config.toml` 中设置 `modelMetadata.modelsDev = true`（或在 `/config modelMetadata` 中打开 **Use models.dev**）后，Agent 会下载它（`https://models.dev/api.json`），并从中取得其他更可靠的来源都没说的模型信息：窗口（`limit.context`）、最大输出（`limit.output`）、它会推理（`reasoning`）以及它读图（`modalities.input` 含 `"image"`）。它默认关闭：**打开后，本机会向第三方 models.dev 发送请求**，大约每天一次，经过 `network.proxy`（[网络与日志](/docs/network-logging#proxy-scope)），User-Agent 写明 Agent 及其版本，不带任何凭据或关于你的信息。

- **排在其他来源之后。** 模型自己的设置、策略、从拒绝中学到的信息和 Provider 目录报告的信息都优先；models.dev 只补上它们未知的部分，排在内置表之前。它只做加法：它从不说模型不读图或不推理；它说"会推理"时，你设置的推理强度保持不变（它不列出级别）。它的窗口和最大输出与目录报告的一样决定会话何时压缩，但从不改变请求：只有在 models.dev 之外的来源知道最大输出时，Anthropic 的思考预算才在其之内确定（[推理强度与思考过程](#reasoning)）。
- **用哪一条。** 比较模型 id 时用小写，去掉 `vendor/` 前缀、末尾的 `-latest` 和末尾的 `-YYYYMMDD` 日期（`anthropic/claude-3-5-haiku-20241022` 即 `claude-3-5-haiku`）。优先取 models.dev 中以该 Provider 自己名义列出的条目：键是 Provider 的 id 或其中一个词（`openai`、`my-openai`），或是其端点主机名中的一段（`api.deepseek.com` 即 `deepseek`），或其 API 就在该主机上。没有时，合并所有提供商对该模型的条目，每项限制（窗口、最大输出）取较小者，以及任何一个"是"，因为一个提供商可能发布的是另一个的限制。
- **何时下载。** 在启动时，以及每当会话绑定到某个 Provider 时，与读取模型目录的时机相同（[模型](#model)），不论 `modelMetadata.discovery` 的值：下载成功后每天最多一次，失败后每 15 分钟最多一次。副本保存在 `model-metadata.json` 中，使用一周，所以 models.dev 无法访问或返回无法使用的内容时什么都不变，也不提示。`/model forget` 和 `providers forget` 会保留它；关闭 `modelsDev` 会丢弃它，以及会话从中取得的窗口。

`/status`、`doctor --online` 和策略表单的占位文字把来自它的信息标为 `models.dev`。

## 重试与限制 [#limits]

- 模型请求失败（例如无法连接）时最多尝试 3 次，之后回合以 `model_request_retries_exhausted` 失败。
- 响应流中断时会重试，终端界面的状态行显示 `Reconnecting`。
- 一个回合最多 32 次模型请求，最长 30 分钟（`agent turn stopped at its time limit of 30 minutes; send a message to continue`）。压缩之后对话仍然太长时，回合以 `the conversation is still too long for the model's context window after it was compacted; start a new conversation or attach less context` 结束。其他限制见 [`turnBudget`](/docs/config-reference#model-policy)。
- 访问 Provider 使用 Agent 进程的代理环境变量，而不是 `network.proxy`，见[网络与日志](/docs/network-logging#provider-proxy)。
