**Provider** 是一个模型服务：一个接口地址、一种协议，以及可选的 API 令牌。可以配置多个 Provider，其中一个是**默认 Provider**，新会话在它上面运行。**模型策略**决定新会话使用的模型、推理强度和上下文压缩方式，对所有 Provider 生效。

Provider 和模型策略都保存在配置目录的 `providers.toml` 中，见[配置参考](/docs/config-reference#providers-toml)。

## 协议 [#protocols]

| 协议               | `--protocol`         | 请求路径（追加在接口地址后） | 认证                                                 | 常见服务                                      |
| ------------------ | -------------------- | ---------------------------- | ---------------------------------------------------- | --------------------------------------------- |
| OpenAI Responses   | `responses`（默认）  | `responses`                  | `Authorization: Bearer 令牌`                         | OpenAI、vLLM 等兼容服务                       |
| Chat Completions   | `chat-completions`   | `chat/completions`           | `Authorization: Bearer 令牌`                         | DeepSeek、OpenRouter、Ollama 等大多数兼容服务 |
| Anthropic Messages | `anthropic-messages` | `messages`                   | `x-api-key: 令牌` 和 `anthropic-version: 2023-06-01` | Anthropic                                     |

接口地址末尾的 `/` 可有可无，协议的路径直接追加在它后面：`https://api.openai.com/v1` 加上 `responses` 就是 `https://api.openai.com/v1/responses`。地址中的查询参数会保留。模型列表从同一地址的 `models` 读取。

## 添加 Provider [#add]

<Tabs items={["OpenAI", "Anthropic", "Chat Completions", "本地服务"]}>
  <Tab value="OpenAI">
    ```sh
    hanafubuki-agent providers add OpenAI --base-url https://api.openai.com/v1 --api-key-env OPENAI_API_KEY
    ```
  </Tab>
  <Tab value="Anthropic">
    ```sh
    hanafubuki-agent providers add Anthropic --protocol anthropic-messages \
      --base-url https://api.anthropic.com/v1 --api-key-env ANTHROPIC_API_KEY
    ```
  </Tab>
  <Tab value="Chat Completions">
    ```sh
    hanafubuki-agent providers add DeepSeek --protocol chat-completions \
      --base-url https://api.deepseek.com/v1 --api-key-env DEEPSEEK_API_KEY
    ```

    接口地址填到 `chat/completions` 之前的部分即可。

  </Tab>
  <Tab value="本地服务">
    ```sh
    hanafubuki-agent providers add Ollama --protocol chat-completions --base-url http://127.0.0.1:11434/v1
    ```

    不需要令牌的服务可以省略 `--api-key-env`。

  </Tab>
</Tabs>

- `--api-key-env 变量` 在添加时从环境变量读取令牌，并原样保存在 `providers.toml` 中（仅自己可读）。令牌不能直接写在命令行上，避免留在 Shell 历史里。变量没有设置时，命令以退出码 2 退出。
- `--header 名称=值` 添加一个随该 Provider 的每个请求发送的请求头（可重复），保存在 `providers.toml` 中。与令牌不同，它的值写在命令行上。
- `--disabled` 添加一个禁用的 Provider。
- 命令打印新 Provider 的 ID，例如 `added provider-2`。ID 是最小的空闲 `provider-N`。

## 管理 Provider [#manage]

```sh
hanafubuki-agent providers list
hanafubuki-agent providers default provider-2 --model deepseek-chat
hanafubuki-agent providers remove provider-1
```

```text
model: gpt-5.1
provider-1 OpenAI (default)  Responses  https://api.openai.com/v1  token: set
provider-2 DeepSeek  ChatCompletions  https://api.deepseek.com/v1  token: set
```

- 第一个添加的 Provider 成为默认 Provider。默认 Provider 被删除或禁用时，默认改为列表中第一个启用的 Provider。
- `providers list` 从不打印令牌和请求头的值。
- 更换令牌或请求头（`requestHeaders`）、启用 Provider，可以在终端界面中使用 `/providers`（[见下文](#interface)），也可以编辑 `providers.toml`（编辑前请先退出正在运行的 Agent）。

## 在终端界面中 [#interface]

[终端界面](/docs/terminal-interface#providers)中的 `/providers` 可以完成上面这些命令的工作，并直接编辑 Provider：

- **列表**：★ 标记默认 Provider；每个 Provider 显示协议、基础 URL、`token set` 或 `no token`，以及 `disabled`。Enter 编辑，`a` 添加，`d` 确认后删除，`e` 启用或停用，`*` 把一个已启用的 Provider 设为默认，`p` 编辑模型策略，Esc 关闭。
- **表单**：名称、协议（`responses`、`chat_completions` 或 `anthropic_messages`）、基础 URL、API 令牌、是否启用，以及按行填写的请求头。令牌显示为圆点：保持不动就保留原值，清空就删除它。按键见[表单](/docs/terminal-interface#forms)。
- **Test** 用表单中的内容（包括令牌和请求头）列出模型，不保存任何东西：它显示 Provider 列出的模型数量，或者 Provider 返回的错误。
- **Save** 完整写入这个 Provider。对于已启用的 Provider，接着会打开模型选择：选中的模型（Provider 没有列出时，用 **Enter a model id…** 手动输入）成为新会话使用的模型，这个 Provider 成为默认 Provider。按 Esc 则保持原来的模型。`/model` 仍然只修改当前会话的模型。
- **模型策略**（列表中的 `p`，或 `/providers policy`）：默认 Provider 和模型、推理强度、图片输入、上下文窗口、自动压缩及其阈值、远程压缩，以及 Agent 默认值或全部十一个回合预算字段。它通过同一套修订号保护写入。
- 每次写入都会带上界面读取时 `providers.toml` 的版本。如果期间文件被其他地方修改（例如另一个终端中的 `providers` 命令），写入会被拒绝：界面重新读取 Provider，保留表单中的内容并给出提示，再保存一次即可。
- 没有默认 Provider 或没有模型时，界面启动时会自动打开这个界面，见[首次设置](/docs/terminal-interface#setup)。

## 模型 [#model]

| 方式                           | 作用范围                                                     |
| ------------------------------ | ------------------------------------------------------------ |
| `providers default ID --model` | 模型策略中的模型：之后所有新会话的默认模型                   |
| `-m 模型`                      | 本次运行中的新会话（以及恢复的会话），在默认 Provider 上运行 |
| 终端界面的 `/model`            | 当前会话；从已启用 Provider 的模型目录中选择                 |

`/model` 列出每个已启用 Provider 的模型目录（从 `models` 接口读取）。某个 Provider 的目录无法读取时，列表会显示原因。Agent 从目录中的每个模型读取它报告的上下文窗口（见[上下文窗口与压缩](#compaction)），也读取它的最大输出、是否读图、是否推理，但目前还不据此行事。目录报告的内容保存在数据目录的 `model-metadata.json` 中，重启后依然有效；之后的目录不再列出的模型会再保留 7 天。Agent 也会自己在后台读取目录：启动时读取默认 Provider 的目录；在某个 Provider 上创建会话、选用它的模型或在它上面运行轮次时，读取该 Provider 的目录，每个 Provider 每天最多一次（目录读取失败后每 15 分钟最多一次）。没有什么会等待它，读取失败的目录只是稍后再试。在 `config.toml` 中设置 `modelMetadata.discovery = "off"` 可以关闭它（[配置参考](/docs/config-reference#model-metadata)）；你打开的目录仍会被读取和保存。没有可用 ID 的模型会被略去，无法读取的字段视为未报告，所以一个异常的模型不会让整个目录读取失败。`doctor --online` 会检查默认 Provider 是否能列出模型。宿主可以在保存 Provider 之前读取它的模型目录，以测试地址、令牌和请求头（`test_provider_draft`，见[嵌入 Agent](/docs/embedding#configuration-in-a-host)）。

## 推理强度与思考过程 [#reasoning]

推理强度在 `providers.toml` 的 `[modelPolicy]` 中设置，命令行上没有对应的选项：

```toml
[modelPolicy]
model = "gpt-5.1"
reasoningEffort = "medium"   # minimal、low、medium、high、xhigh
```

推理强度只对 Responses 协议有效；其他协议的会话会忽略它。`/status` 会显示当前会话的推理强度。

模型的思考过程会显示出来，在终端界面中是一行可以用 Ctrl-O 展开的 `Thinking`（见[终端界面](/docs/terminal-interface#thinking)），在 `exec --json` 中是 `reasoning_*` 事件（见 [exec --json 事件](/docs/json-events#reasoning)）；`exec` 的普通输出和 `sessions show` 只显示思考了多久（`thought for 12s`）。能看到什么取决于 Provider：

| 协议               | 思考内容                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| Responses          | 设置了推理强度时，Agent 会请求思考摘要；兼容服务（例如 vLLM 上的 gpt-oss）也可能发送原始思考文本 |
| Chat Completions   | 服务在 `reasoning_content` 或 `reasoning` 中发送的内容（DeepSeek、Qwen、OpenRouter 等）          |
| Anthropic Messages | 目前不会请求思考，因此没有内容；服务仍然发送的 `thinking` 块会显示出来                           |

思考内容保存在会话历史中，每一段最多 256 KiB，超出的部分被截断。它只用于显示，不会再发送给模型。

## 上下文窗口与压缩 [#compaction]

模型的上下文窗口依次取自：`[modelPolicy]` 中的 `contextWindowTokens`、Provider 模型目录最近一次报告的值、内置的常见模型表（如 GPT-5 系列、Claude、Gemini 2.5）。都没有时不会自动压缩。会话在创建或选择模型时取得窗口，并在它的每个轮次开始时再取一次，所以在读取模型目录之前创建的会话会在下一个轮次得到窗口。你设置的窗口从不被替换；当没有任何来源再知道模型的窗口时，会话保留它已有的窗口。

上下文用到窗口的 `autoCompactThresholdPercent`（默认 80%）时，Agent 会在回合开始前或回合中自动压缩：把较早的对话总结成摘要，保留最近的消息。Provider 报告上下文超出窗口时，Agent 会压缩一次并重试；再次超出时回合失败（`context_window_exceeded`）。

| 设置                          | 默认值       | 作用                                                                                       |
| ----------------------------- | ------------ | ------------------------------------------------------------------------------------------ |
| `autoCompactionEnabled`       | `true`       | 是否自动压缩                                                                               |
| `autoCompactThresholdPercent` | `80`         | 触发自动压缩的比例                                                                         |
| `remoteCompaction`            | `"disabled"` | 设为 `"responses_compact"` 或 `"responses_compact_v2"` 时，在 Responses 协议上由服务端压缩 |
| `contextWindowTokens`         | 未设置       | 指定上下文窗口                                                                             |

已有会话在下一轮次或 `/compact` 时采用修改后的 `remoteCompaction`；其他键在会话重新选择模型（`/model`）时才采用，新会话则全部采用。除这种压缩外如何缩减上下文，由 `config.toml` 中的[压缩策略](/docs/config-reference#compaction)决定。

在终端界面中输入 `/compact` 可以立即压缩。`/status` 显示 token 用量和上下文剩余比例。

## 图片 [#images]

`[modelPolicy.inputCapabilities]` 的 `imageInput` 为 `"auto"`（默认）时，Agent 会向接受图片的模型发送图片（例如 `view_image` 工具查看的图片）。模型拒绝图片时，Agent 会去掉图片重试一次，并在 7 天内（重启后也一样）不再向该模型发送图片。设为 `"disabled"` 则从不发送图片。

## 重试与限制 [#limits]

- 模型请求失败（例如无法连接）时最多尝试 3 次，之后回合以 `model_request_retries_exhausted` 失败。
- 响应流中断时会重试，终端界面的状态行显示 `Reconnecting`。
- 一个回合最多 32 次模型请求，最长 30 分钟（`agent turn stopped at its time limit of 30 minutes; send a message to continue`）。压缩之后对话仍然太长时，回合以 `the conversation is still too long for the model's context window after it was compacted; start a new conversation or attach less context` 结束。其他限制见 [`turnBudget`](/docs/config-reference#model-policy)。
- 访问 Provider 使用 Agent 进程的代理环境变量，而不是 `network.proxy`，见[网络与日志](/docs/network-logging#provider-proxy)。
