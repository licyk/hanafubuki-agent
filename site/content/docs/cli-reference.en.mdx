```text
hanafubuki-agent [OPTIONS] [PROMPT]
hanafubuki-agent [OPTIONS] <COMMAND> [ARGS]
```

With no command it opens the [terminal interface](/docs/terminal-interface), `PROMPT` being the first message. `hanafubuki-agent --help` and `hanafubuki-agent <COMMAND> --help` print the same information; `-V` (`--version`) prints the version.

## Global flags [#global-flags]

They go before or after the command, and apply to every command.

| Flag                                                 | Does                                                                                                                                            |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `-c`, `--config KEY=VALUE`                           | Overrides a key of `config.toml` for this run; repeatable, the later wins. The value is TOML, or a string when it is not valid TOML             |
| `-p`, `--profile NAME`                               | Reads the profile `[profiles.NAME]` over the user's settings; a profile the file does not have is an error                                      |
| `-m`, `--model MODEL`                                | The model a new (or resumed) session runs on the default Provider, in place of the model policy's                                               |
| `--role NAME`                                        | The [role](/docs/roles#sessions) a new session of the terminal interface or of `exec` takes, in place of `default`; an unknown role is an error |
| `-C`, `--cd DIR`                                     | The working directory: the first workspace root; its Git root decides which project configuration may be read                                   |
| `--add-dir DIR`                                      | Another workspace root; repeatable                                                                                                              |
| `--permission-mode manual\|auto-review\|full-access` | This run's [permission mode](/docs/permissions), as `-c permissionMode=…`, winning over `-c`                                                    |
| `--log-level off\|error\|warn\|info\|debug\|trace`   | This run's log level, as `-c logLevel=…`, winning over `-c`                                                                                     |
| `--data-dir DIR`                                     | The data directory (history, memory, Skills, logs), in place of the platform's or the one `HANAFUBUKI_AGENT_HOME` names                         |
| `--no-alt-screen`                                    | The [terminal interface](#interface) writes the conversation into the terminal's scrollback; other commands ignore it                           |
| `--safe-mode`                                        | Starts the Agent in safe mode: only its core runs, no plugin row (`disabledPlugins` is unchanged) and no [installed plugin](#plugins)'s content |

<Callout>
  The flag's values have hyphens (`auto-review`, `full-access`); the configuration file and `-c` use
  underscores (`auto_review`, `full_access`).
</Callout>

The layers and their precedence are in [Configuration layers](/docs/config-layers).

## The terminal interface [#interface]

| Command                     | Does                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `hanafubuki-agent [PROMPT]` | Opens the terminal interface in a new session                                                                  |
| `resume [ID] [PROMPT]`      | Resumes session `ID` in the terminal interface; without an id, opens the resume picker                         |
| `resume --last [PROMPT]`    | Resumes the latest session a turn ran in, or starts a new one when there is none. `--last` takes no session id |

`--no-alt-screen` keeps the interface off the terminal's alternate screen for this run: the conversation goes into the terminal's scrollback (Scrollback), whatever `tui.fullscreenTranscript` and `tui.alternateScreen` say. The other commands ignore it.

Without a terminal, both exit with code 2. See [Terminal interface](/docs/terminal-interface#modes).

## exec [#exec]

```text
hanafubuki-agent exec [OPTIONS] [PROMPT|-]
```

| Flag                               | Does                                                                               |
| ---------------------------------- | ---------------------------------------------------------------------------------- |
| `PROMPT`                           | The message; `-`, or none with standard input not a terminal, reads standard input |
| `--json`                           | Prints every event as one JSON line                                                |
| `--approve POLICY`                 | How approvals are answered: `deny` (the default), `ask`, `allow:TOOL[,TOOL…]`      |
| `-o`, `--output-last-message FILE` | Writes the turn's final answer to `FILE`                                           |

See [exec](/docs/exec) and [exec --json events](/docs/json-events).

## config [#config]

| Command                | Does                                                                                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `config path`          | Prints where `config.toml`, `providers.toml`, `mcp.toml`, the data directory and the log file are                                                                                                                              |
| `config get [KEY]`     | Prints a key's value with every layer applied (a string as it is, anything else as TOML); without a key, every setting. A proxy URL's credentials print as `***`                                                               |
| `config set KEY VALUE` | Writes one key into the user's `config.toml`: any setting, `profiles.NAME.KEY`, `projects."PATH".trustLevel`. The value is TOML, or a string when it is not; a setting's value is checked against its type, bounds and choices |
| `config edit`          | Opens the user's `config.toml` in `$VISUAL` or `$EDITOR`                                                                                                                                                                       |

See [Configuration](/docs/configuration).

## providers [#providers]

| Command                                                                                                                                                  | Does                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `providers list`                                                                                                                                         | Prints the model policy's model, and each Provider's id, name, whether it is the default or disabled, protocol, address, whether a token is set, and its headers' names                                                                                      |
| `providers add NAME --base-url URL [--protocol responses\|chat-completions\|anthropic-messages] [--api-key-env VAR] [--header NAME=VALUE]… [--disabled]` | Adds a Provider and prints its id. The protocol defaults to `responses`; the token is read from `VAR`; `--header` adds a request header. The first one becomes the default                                                                                   |
| `providers remove ID`                                                                                                                                    | Removes a Provider; when it was the default, another becomes the default                                                                                                                                                                                     |
| `providers default ID [--model MODEL]`                                                                                                                   | Makes a Provider the default, and optionally sets the model policy's model                                                                                                                                                                                   |
| `providers forget ID [--model MODEL]`                                                                                                                    | Forgets what the Provider's refusals taught of `MODEL`, or of all its models: a smaller window, no images, no reasoning, no structured output ([Forgetting what was learned](/docs/providers-models#forget)); prints how many models had something to forget |

See [Providers and models](/docs/providers-models).

## mcp [#mcp]

| Command                                                                    | Does                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mcp list`                                                                 | Prints each server's id, whether it is disabled, its transport and target, the names (never the values) of its environment variables or headers; then the servers the enabled [installed plugins](#plugins) run, each ending `(plugin ID)` (they are changed with `plugins`, not here); then the credentials that are set |
| `mcp add ID --url URL [--oauth disabled\|optional\|required] [--disabled]` | Adds a Streamable HTTP server; `--oauth` sets whether it takes an OAuth login (`disabled` by default)                                                                                                                                                                                                                     |
| `mcp add ID [--env KEY=VALUE]… [--disabled] -- PROGRAM [ARG]…`             | Adds a stdio server: the program and its arguments follow `--`. An enabled server is connected at once, and how that went is printed                                                                                                                                                                                      |
| `mcp remove ID`                                                            | Disconnects and removes a server                                                                                                                                                                                                                                                                                          |
| `mcp connect ID`                                                           | Connects a server and prints its state and tool count; fails when it does not reach `ready`                                                                                                                                                                                                                               |
| `mcp login ID`                                                             | Logs in to a server with OAuth: prints the URL to open in a browser on this machine, waits up to 5 minutes for the authorization, then prints the servers' states                                                                                                                                                         |

A server id has 1 to 128 letters, digits, `-`, `_` and `.` only. Credentials are edited in `mcp.toml`; see [MCP](/docs/mcp).

## plugins [#plugins]

Installed plugins are packages in Codex's, Claude Code's, Cursor's or the Agent Plugins format: their Skills, MCP servers, hooks and roles join the Agent's once installed and on. They come from a marketplace the user added, or from a directory; a plugin in this project's format can also run code ([Writing plugins](/docs/writing-plugins)). The model sees what each contributes; the store and the settings they live in are described in [Configuration reference](/docs/config-reference#plugins), and what they may do and how they fail in [Plugins](/docs/plugins).

| Command                                                                          | Does                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugins list [--available] [--json]`                                            | Lists the installed plugins: id, `enabled` or `disabled`, version and source. `--available` lists each added marketplace's plugins under it instead (`installed, enabled`, `installed, disabled`, `not installed`, `not installable`), then the installed plugins no marketplace offers. `--json`: `{"installed": [...], "marketplaces": [...]}`                                                                      |
| `plugins add PLUGIN@MARKETPLACE`, `plugins add PLUGIN --marketplace MARKETPLACE` | Installs the marketplace's plugin and turns it on (`[plugins."PLUGIN@MARKETPLACE"] enabled = true`); prints its root, what its reading left out, the Skills its commands became and how many of its hooks wait to be trusted (`/hooks` or `/plugins` trusts them). `--json` prints the whole result                                                                                                                   |
| `plugins add DIR [--marketplace NAME]`                                           | Installs the plugin in the directory `DIR`, filed under the marketplace `NAME` (`local` when not given): its id is `<its manifest's name>@local`                                                                                                                                                                                                                                                                      |
| `plugins remove ID [--purge-data]`                                               | Uninstalls the plugin and removes its `[plugins]` entry; its data directory is kept unless `--purge-data`. A linked plugin is unlinked, and its directory kept                                                                                                                                                                                                                                                        |
| `plugins enable ID`, `plugins disable ID`                                        | Turns an installed plugin on or off; a plugin whose marketplace is turned off cannot be turned on                                                                                                                                                                                                                                                                                                                     |
| `plugins update ID`                                                              | Installs the plugin again from its marketplace, as the marketplace is now (upgrade a git marketplace first), or from the directory it came from; a changed plugin's hooks wait to be trusted again. A linked plugin is refused: it is never updated                                                                                                                                                                   |
| `plugins info ID [--json]`                                                       | Shows the plugin: status, version, format, source, its Skills, MCP servers, hooks and roles, the hooks waiting to be trusted, its code's state once the command's own Agent has started it, or after 30 s (`code: running`, `blocked`, …; at once `stopped` in safe mode or with the `plugins` row off), and its issues                                                                                               |
| `plugins retry ID`                                                               | Loads the installed plugins again, starts its code again if it failed, and shows the plugin once its code has started, as `info` does                                                                                                                                                                                                                                                                                 |
| `plugins grant ID`                                                               | Grants the plugin's code what its manifest asks for (the network, the workspace, environment variables) and prints it; a program guest waits for its grant (`blocked`); a WebAssembly guest needs none, and the command fails for it                                                                                                                                                                                  |
| `plugins settings ID [--get]`, `plugins settings ID --set JSON`                  | Prints the settings of the plugin's code (`[plugins."ID"].settings`) and its `configSchema`; `--set` replaces them with a JSON object checked against the schema, `--set null` removes them; its guest starts again with them                                                                                                                                                                                         |
| `plugins new NAME [--lang rust\|python] [--target process\|wasm] [--dir DIR]`    | Creates a plugin with code in `DIR` (default `./NAME`): the package in `package/` (a manifest declaring a tool and more, permissions and a `configSchema`) and the guest's source with kardia-guest or pykardia; `--target wasm` (Rust only) writes a crate that builds a WebAssembly module ([Writing plugins](/docs/writing-plugins#start))                                                                         |
| `plugins validate DIR [--run] [--json]`                                          | Checks the plugin in `DIR` as an install reads it and its code as the Agent runs it; `--run` also installs it into a throwaway home, grants it and starts its guest. Exit code 1 on any issue or a guest that does not run ([Check it](/docs/writing-plugins#validate))                                                                                                                                               |
| `plugins dev DIR [--grant]`                                                      | Installs the plugin in `DIR` as `NAME@local`, turns it on, asks to grant what its code asks for (`--grant` grants it), then installs it again after each change to its files until Ctrl+C ([Develop it](/docs/writing-plugins#dev))                                                                                                                                                                                   |
| `plugins link DIR [--marketplace NAME] [--json]`                                 | Links the plugin in `DIR` as `NAME@local` (or under the marketplace `NAME`) and turns it on: the directory is the package, never copied nor pinned by a content hash, listed as `linked DIR`; a running Agent reads it again and restarts its code after each change ([Link it](/docs/writing-plugins#link)). An id that is installed is refused, and `plugins add` refuses a linked one; `plugins remove` unlinks it |
| `plugins marketplace add SOURCE [--ref REF] [--sparse PATH]…`                    | Adds a marketplace: a local directory, used where it is, or a git repository (`owner/repo[@ref]`, an HTTPS or SSH URL, `file://`), cloned under the data directory's `plugins/marketplaces/`; `--sparse` checks out only those paths. Adding the same source again changes nothing                                                                                                                                    |
| `plugins marketplace list [--json]`                                              | Lists the added marketplaces: name, `local` or `git`, `on`, `off` or `unreadable`, and root                                                                                                                                                                                                                                                                                                                           |
| `plugins marketplace upgrade [NAME]`                                             | Brings the git marketplace `NAME`, or every added git marketplace, to its remote's revision; its installed plugins stay as they are until `plugins update`                                                                                                                                                                                                                                                            |
| `plugins marketplace remove NAME`                                                | Removes the marketplace (and a git one's checkout); the plugins installed from it stay installed                                                                                                                                                                                                                                                                                                                      |

A plugin's id is `PLUGIN@MARKETPLACE`. The command line has no `-m` for `--marketplace`: `-m` is the global `--model`.

## update [#update]

| Command          | Does                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `update`         | Updates this executable to the latest release, the way it was installed (below): the steps on standard error, the result on standard output                                                |
| `update --check` | Looks the latest release up and reports it: this version, the latest, the executable, how it was installed, the release notes and what `update` would do. It downloads and changes nothing |
| `update --force` | Also reinstalls the latest release when it is this version. Nothing installs an older release: a build newer than the latest release is left as it is                                      |

`--check` and `--force` together are a usage error (exit code 2).

```text
$ hanafubuki-agent update --check
Current version  0.2.0
Latest release   0.3.0
Executable       /home/me/.local/bin/hanafubuki-agent
Installed as     a released binary
Release notes    https://github.com/licyk/hanafubuki-agent/releases/tag/v0.3.0

An update is available: run `hanafubuki-agent update` to install 0.3.0.

$ hanafubuki-agent update
Updating hanafubuki-agent 0.2.0 → 0.3.0 at /home/me/.local/bin/hanafubuki-agent
Downloading hanafubuki-agent-0.3.0-x86_64-unknown-linux-gnu.tar.gz: 18.9 MiB: done
Verifying the SHA-256 digest: ok
Checking the new executable: hanafubuki-agent 0.3.0
Installing: done
Updated to 0.3.0. The next start of hanafubuki-agent runs it; running ones keep 0.2.0 until they restart.
```

On a terminal the download line counts up in place; otherwise only its first state and its end are printed.

What it does depends on how the executable was installed:

- **A released binary**: the latest release's archive for this platform (`hanafubuki-agent-VERSION-TARGET.tar.gz`, `.zip` on Windows) is downloaded into a new hidden directory beside the executable (`.hanafubuki-agent-update-…`) and checked against the size and the SHA-256 digest GitHub gives for it; a release without a digest is refused. Only the executable is taken from it, by its exact path (`hanafubuki-agent-VERSION-TARGET/hanafubuki-agent`), and it must answer `--version` with the new version within 10 seconds, which also catches a build for another architecture or, on Linux, a glibc older than 2.35. Then a rename puts it in place: the installed executable is never written into, and nothing before this last step touches it. Through a symbolic link, the file it points to is replaced and the link stays. On Windows, where a running executable cannot be replaced, it is first renamed to `hanafubuki-agent.exe.NUMBER.outdated` beside it (and put back if the new one cannot be put in place); the next update removes that file once no process runs it.
- **`cargo install`**: on Linux and macOS it runs `cargo install --locked hanafubuki-agent-cli` (with `--root` when the executable is not in cargo's default root) in a temporary directory, so no project's cargo settings apply, showing cargo's own output; then it asks the executable its version, so a cargo that installed it elsewhere (`CARGO_INSTALL_ROOT`, `install.root`) is noticed. On Windows it only names the command.
- **A build from a checkout** (`target/debug`, `target/release`, `cargo install --path`), **a directory you cannot write**, or **a platform no release is built for**: it says what to do instead and exits with 1.

A failure says what was kept, usually "nothing was changed": the executable is then as it was. A stopped or killed update leaves at most its hidden directory, which the next update removes.

One update at a time: while one runs, another of the same executable is refused at once (its lock is the file `.hanafubuki-agent.update.lock` beside the executable, which stays). An update that finds the executable already at the latest version (another process updated it) downloads nothing.

`update` does not start the Agent and does not take the data directory's lock, so it runs while Agents run. They keep their version until they restart, and the next start runs the new one; meanwhile their sandboxed commands start the executable at its path, now the new one ([Internals](/docs/internals#self-update)).

What it sends: `GET https://api.github.com/repos/licyk/hanafubuki-agent/releases/latest` with `Accept: application/vnd.github+json`, `User-Agent: hanafubuki-agent/VERSION` and, when `GITHUB_TOKEN` is set, `Authorization: Bearer` with it ([Environment](/docs/environment#read)); then the archive, from the address GitHub's answer gives (GitHub redirects it to its download host), without the token. Every request and every redirect is HTTPS. Both go through `network.proxy`; a configuration that cannot be read only warns, and the system's proxy is used. A debug build looks up releases only at `HANAFUBUKI_AGENT_TEST_RELEASE_URL`.

It exits with 0 when it updated or there was nothing to install, and with 1 when it could not ([Exit codes](/docs/exit-codes)). See also [Updating](/docs/installation#updating).

## Which commands start the Agent [#agent-start]

`config`, `providers list`, `roles` and `doctor` without `--online` only read and write the configuration (`roles` and `doctor` also read the installed plugins, writing nothing there), and `update` reads it for its proxy: they do not start the Agent, and work while another Agent process runs. The other commands start it, and need the data directory to themselves.

Every command reads the configuration first, then installs the crash handler and the log file, before it starts the Agent or changes anything. A management command that starts the Agent also connects the enabled MCP servers in the background, as every start does.

Ctrl-C ends any command other than `exec` and the terminal interface at once: the operating system releases the data directory's lock, and the next start cleans up the processes the Agent had started.
