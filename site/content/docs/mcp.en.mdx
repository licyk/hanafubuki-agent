An MCP (Model Context Protocol) server gives the model the tools of a local program or a remote service. A server may reach files, the network, databases and third-party accounts: add only servers you trust, and give their tools fitting approval policies.

The servers are kept in `mcp.toml` in the configuration directory; every field is in the [Configuration reference](/docs/config-reference#mcp-toml).

## Adding a server [#add]

<Tabs items={["stdio", "Streamable HTTP"]}>
  <Tab value="stdio">
    A local program the Agent starts. The program and its arguments follow `--`; `--env` sets an environment variable (repeatable):

    ```sh
    hanafubuki-agent mcp add files -- npx -y @modelcontextprotocol/server-filesystem /home/me/notes
    hanafubuki-agent mcp add search --env SEARCH_REGION=eu -- /usr/local/bin/search-mcp --stdio
    ```

    The program is an absolute path, or a name looked up on `PATH`. A stdio server inherits the Agent process's whole environment.

  </Tab>
  <Tab value="Streamable HTTP">
    A local or remote HTTP service that is already running:

    ```sh
    hanafubuki-agent mcp add docs --url https://mcp.example.com/mcp
    ```

    A server that needs an OAuth login takes `--oauth required` (`optional` when it also works without one); see [OAuth login](#oauth).

  </Tab>
</Tabs>

- A server id has 1 to 128 letters, digits, `-`, `_` and `.` only. A server in `mcp.toml` with another id is dropped when the file is read, as a broken server is (see [Configuration recovery](/docs/recovery)), and the other servers stay.
- A new server has the defaults: the approval policy `ask`, the exposure policy `deferred`, a 120-second call timeout, and so on.
- An enabled server is connected as soon as it is added, and the command prints how that went, such as `files: ready`. `--disabled` adds it turned off.

## Plugins' servers [#plugin-servers]

An enabled [installed plugin](/docs/architecture#installed-plugins) runs the MCP servers it declares. They are the plugin's: they are not in `mcp.toml`, cannot be edited there, and come and go with the plugin, connecting when it is turned on and disconnecting when it is turned off, without a restart. They run like the servers you add: the same connection, reconnect and approval rules, with the defaults of a new server (approval `ask`, exposure `deferred`).

- **Codex's, Claude Code's and Cursor's packages** declare them in `.mcp.json` at the package's root, or in the manifest's `mcpServers` (a path to such a file, or the servers themselves), as `{"mcpServers": {"NAME": {...}}}` or as the bare map of servers by name. A server has `command`, `args`, `env` and `cwd` (stdio) or `url` and `headers` (`http_headers`) (Streamable HTTP), and may have `type`, `enabled`, `required`, `startup_timeout_sec`, `tool_timeout_sec`, `enabled_tools`, `disabled_tools` and `oauth` (which allows a login). A relative `cwd` or command path is in the package; `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`, `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` are replaced by the package's directory and its data directory, and a stdio server runs with those four variables set. Other fields are ignored; `bearer_token_env_var` and `env_http_headers` are refused.
- **An Agent Plugins package** declares them in its root's `mcp.json`, read strictly by its 1.0.0 schema: `$schema` and `mcpServers` only; a `stdio` server's `command` is a bare name or a `./` path in the package, its `args` and `env` may use `${PLUGIN_ROOT}` and `${PLUGIN_DATA}` (which `env` may not set), and its `cwd` is `./…`, `${PLUGIN_ROOT}/…` or `${PLUGIN_DATA}/…`, which must exist and stay inside; a `streamable-http` server's URL is HTTPS unless it is on loopback, and the client's own headers (`Authorization`, `Content-Type`, …) are dropped; `sse` is not supported. A field the schema does not define fails its server.
- **One bad server costs only itself**: it is listed among the plugin's issues and its siblings run.
- **A name runs once.** Your server in `mcp.toml` comes first: a plugin's server of the same name gives way, and runs again once yours is deleted. Among plugins, the first in key order (`<plugin>@<marketplace>`) wins. The one that gives way is its plugin's issue.
- **You restrict a plugin's server** in `[plugins."PLUGIN@MARKETPLACE".mcpServers.NAME]`: `enabled`, `enabledTools` and `disabledTools` ([Plugins](/docs/config-reference#plugins)).

The facade's MCP snapshot lists them as `pluginServers`, each with its plugin, its configuration and its status.

## In the terminal interface [#interface]

`/mcp` in the [terminal interface](/docs/terminal-interface#mcp) opens the [settings center](/docs/terminal-interface#config) at the MCP servers, where a server is added and edited field by field and each change applies at once:

- **The servers**: each with its command or URL, its connection phase (`starting`, `ready`, `failed`, …), its number of tools once connected, and its last error. `a` adds one (named by its id; a new server starts from the defaults), `d` deletes one after asking, Enter opens one.
- **A server**: its transport (stdio: the program, the arguments as a list, the working directory and the environment; Streamable HTTP: the URL, OAuth `Off`, `Optional` or `Required`, and the headers), enabled and required, the protocol mode (`legacy` or `v20260728`), the approval and exposure defaults, the tools only allowed or not allowed, a list per tool for the call limit (`TOOL=NUMBER`, 1 to 64), the approval (`TOOL=allow|ask|deny`) and the exposure (`TOOL=direct|direct_model_only|deferred|hidden`), and the timeouts and concurrent calls. The environment and the headers are `NAME=VALUE` items. Below them are **Delete**, **Connect**, **Disconnect**, **Refresh**, **Log out** and **Log in** (the [OAuth login](#oauth)).
- **MCP secrets**: an environment variable or a header whose value is secret is a record of its own, `SERVER/NAME`. Its value is kept as a [credential](#credentials) the server refers to from `credentialEnvironment` or `credentialHeaders`, named after the server and the variable (`github-GITHUB_TOKEN`), and it is never shown: `••••` says it is set, and typing one replaces it. Deleting a secret, a server, or a transport the server leaves removes the credentials no other server uses.
- Each write names the version of `mcp.toml` the center read; a write over settings that changed meanwhile is refused, the servers are read again, and the change stays to be saved again.
- `/mcp verbose` writes the servers and their tools into the conversation, those of the installed plugins included, and `/mcp login ID` opens that server's login over its record in the center.

## Credentials [#credentials]

`mcp add` sets no credentials. For a server that needs a token, add it to the MCP secrets in `/mcp` ([above](#interface)), or edit `mcp.toml`: point an environment variable or a header at a key of `[credentials]`, the only place the value is kept (the file is readable only by you).

<Tabs items={["stdio: an environment variable", "HTTP: a header"]}>
  <Tab value="stdio: an environment variable">
    ```toml
    [[servers]]
    id = "github"
    # …

    [servers.transport]
    type = "stdio"
    program = "github-mcp-server"
    argv = ["stdio"]

    [servers.transport.credentialEnvironment]
    GITHUB_PERSONAL_ACCESS_TOKEN = "github-token"

    [credentials.github-token]
    value = "ghp_..."
    generation = 1
    ```

  </Tab>
  <Tab value="HTTP: a header">
    ```toml
    [[servers]]
    id = "docs"
    # …

    [servers.transport]
    type = "streamable_http"
    url = "https://mcp.example.com/mcp"
    oauth = "disabled"

    [servers.transport.credentialHeaders]
    Authorization = "docs-token"

    [credentials.docs-token]
    value = "Bearer abc123"
    generation = 1
    ```

  </Tab>
</Tabs>

- Variables and headers that are not secret go in `publicEnvironment` and `publicHeaders`.
- When you change a credential's value, raise its `generation` by one.
- A server that refers to a credential key that does not exist cannot connect.
- Quit any running Agent before you edit the file; the change applies at the next start.

`mcp list` prints only the names of the environment variables and headers, and which credentials are set, never their values.

A host sets or removes one credential at a time (`mcp_set_credential`, `mcp_remove_credential`); see [Embedding](/docs/embedding#configuration-in-a-host).

## OAuth login [#oauth]

A Streamable HTTP server whose `oauth` is `"optional"` or `"required"` takes an OAuth login:

```sh
hanafubuki-agent mcp add docs --oauth required --url https://mcp.example.com/mcp
hanafubuki-agent mcp login docs
```

- `mcp login` prints the authorization URL. Open it in a browser on the same machine: after you authorize, the browser is sent back to `http://127.0.0.1:PORT/callback`, a port the command listens on for this login only, and the page says you can close the tab.
- The command waits up to 5 minutes; then it prints `docs: logged in` and the servers' states. Ctrl-C ends it.
- The tokens are kept in the platform's secure store (the keyring), not in `mcp.toml`; without a reachable keyring (`doctor` checks it) the login cannot keep them.
- A server whose `oauth` is `"disabled"` (the default) refuses the login: `OAuth is disabled for this MCP server`.
- In the terminal interface, `/mcp login docs` (or **Log in** on the server in `/mcp`) logs in the same way: the page shows the address to open (`c` copies it; the conversation keeps it too), waits for the browser, and Esc cancels the login.

## Approval and exposure policies [#policies]

A server has default policies, and a tool can have its own:

```toml
[[servers]]
id = "github"
approvalPolicy = "ask"
exposurePolicy = "deferred"
disabledTools = ["delete_repository"]

[servers.toolApprovalPolicies]
get_issue = "allow"
list_issues = "allow"

[servers.toolExposurePolicies]
search_code = "direct"
```

**The approval policy** (`approvalPolicy`, `toolApprovalPolicies`):

| Value             | Does                                                                                                                                            |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `"allow"`         | No approval when the tool says it is not destructive (`destructiveHint: false`); a tool that says nothing counts as destructive, and still asks |
| `"ask"` (default) | The [permission mode](/docs/permissions) decides: manual mode asks you                                                                          |
| `"deny"`          | The call is refused, in every permission mode                                                                                                   |

**The exposure policy** (`exposurePolicy`, `toolExposurePolicies`) decides how the model sees a tool:

| Value                  | Does                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------- |
| `"direct"`             | The tool is given to the model with every request                                               |
| `"deferred"` (default) | Not given directly: the model finds it with `tool_search` when it needs it, which saves context |
| `"hidden"`             | Never offered to the model                                                                      |
| `"direct_model_only"`  | As `direct`, for a tool meant for the model and not an application's interface                  |

A non-empty `enabledTools` opens only the tools it lists; the tools in `disabledTools` are not opened.

The model sees a tool as `mcp__SERVER__TOOL`, with any character outside `[A-Za-z0-9_-]` replaced by `_`.

## Connecting [#connecting]

- When the Agent starts, it connects every enabled server in the background, four at a time.
- A server whose connection drops is reconnected after 2, 10 and 30 seconds, at most three times in ten minutes.
- A server with `required = true` is required: a failed connection at the start is logged as an error, and a step of a turn fails when its tools cannot be used.
- A management command that starts the Agent (`sessions list`, say) connects the servers in the background too.

```sh
hanafubuki-agent mcp connect files    # connects and prints its state and tools: files: ready (11 tools)
hanafubuki-agent mcp list
hanafubuki-agent mcp remove files
hanafubuki-agent doctor --online      # connects each enabled server and reports how it went
```

`mcp connect` fails with exit code 1, printing the error, when the server does not reach `ready`.

`/mcp` in the terminal interface shows each server: its command or URL, its connection state, its tools and its last error; `/mcp verbose` writes the servers, their errors and their tools into the conversation.

## Resources [#resources]

A server's resources are read with `list_mcp_resources`, `list_mcp_resource_templates` and `read_mcp_resource`, which need no approval.

## MCP and memory [#memory]

With `memory.excludeExternalContext` on, a session that has used a web or MCP tool's output no longer contributes to the memory, so unchecked outside content stays out of it. See [Memory](/docs/memory).
