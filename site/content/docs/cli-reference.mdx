```text
hanafubuki-agent [选项] [提示词]
hanafubuki-agent [选项] <命令> [参数]
```

不带命令时打开[终端界面](/docs/terminal-interface)，`提示词`作为第一条消息。`hanafubuki-agent --help` 和 `hanafubuki-agent <命令> --help` 打印同样的信息，`-V`（`--version`）打印版本。

## 全局选项 [#global-flags]

全局选项可以写在命令之前或之后，对所有命令有效。

| 选项                                                 | 作用                                                                                                                   |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `-c`、`--config 键=值`                               | 本次运行覆盖 `config.toml` 的一个键，可重复，后面的优先。值按 TOML 解析，不是合法 TOML 时作为字符串                    |
| `-p`、`--profile 名字`                               | 在用户设置之上读取配置档 `[profiles.名字]`；配置文件中没有这个配置档时报错                                             |
| `-m`、`--model 模型`                                 | 新会话（以及恢复的会话）使用的模型，在默认 Provider 上运行，代替模型策略中的模型                                       |
| `-C`、`--cd 目录`                                    | 工作目录：第一个工作区目录；它所在的 Git 仓库根目录决定读取哪个项目配置                                                |
| `--add-dir 目录`                                     | 再添加一个工作区目录，可重复                                                                                           |
| `--permission-mode manual\|auto-review\|full-access` | 本次运行的[权限模式](/docs/permissions)，相当于 `-c permissionMode=...`，优先于 `-c`                                   |
| `--log-level off\|error\|warn\|info\|debug\|trace`   | 本次运行的日志级别，相当于 `-c logLevel=...`，优先于 `-c`                                                              |
| `--data-dir 目录`                                    | 数据目录（历史、记忆、Skill、日志），代替平台默认位置或 `HANAFUBUKI_AGENT_HOME` 指定的位置                             |
| `--no-alt-screen`                                    | [终端界面](#interface)把对话写入终端的滚动历史；其他命令忽略它                                                         |
| `--safe-mode`                                        | 以安全模式启动 Agent：只运行核心，不运行任何插件行（`disabledPlugins` 不变），也不加载任何[已安装插件](#plugins)的内容 |

<Callout>
  选项中的值使用连字符（`auto-review`、`full-access`），而配置文件和 `-c`
  中使用下划线（`auto_review`、`full_access`）。
</Callout>

配置的分层和优先级见[配置分层](/docs/config-layers)。

## 终端界面 [#interface]

| 命令                        | 作用                                                                            |
| --------------------------- | ------------------------------------------------------------------------------- |
| `hanafubuki-agent [提示词]` | 在新会话中打开终端界面                                                          |
| `resume [ID] [提示词]`      | 在终端界面中恢复会话 `ID`；不给 ID 时打开恢复选择器                             |
| `resume --last [提示词]`    | 恢复最近一个运行过回合的会话；没有时开始新会话。`--last` 不能和会话 ID 一起使用 |

`--no-alt-screen` 让本次运行的界面不使用终端的备用屏幕：对话写入终端的滚动历史（Scrollback），不管 `tui.fullscreenTranscript` 和 `tui.alternateScreen` 如何设置。其他命令忽略它。

没有终端时，两者都以退出码 2 退出。见[终端界面](/docs/terminal-interface#modes)。

## exec [#exec]

```text
hanafubuki-agent exec [选项] [提示词|-]
```

| 选项                               | 作用                                                      |
| ---------------------------------- | --------------------------------------------------------- |
| `提示词`                           | 消息。`-`，或者不给且标准输入不是终端时，从标准输入读取   |
| `--json`                           | 每个事件输出一行 JSON                                     |
| `--approve 策略`                   | 如何回答审批：`deny`（默认）、`ask`、`allow:工具[,工具…]` |
| `-o`、`--output-last-message 文件` | 把回合的最终回答写入文件                                  |

见 [exec](/docs/exec) 和 [exec --json 事件](/docs/json-events)。

## config [#config]

| 命令               | 作用                                                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `config path`      | 打印 `config.toml`、`providers.toml`、`mcp.toml`、数据目录和日志文件的位置                                                   |
| `config get [键]`  | 打印应用所有分层后的值：字符串原样输出，其他值输出为 TOML；不给键时输出全部设置。代理 URL 中的凭据显示为 `***`               |
| `config set 键 值` | 把一个键写入用户的 `config.toml`：任何设置、`profiles.名字.键`、`projects."路径".trustLevel`。值按 TOML 解析，否则作为字符串 |
| `config edit`      | 用 `$VISUAL` 或 `$EDITOR` 打开用户的 `config.toml`                                                                           |

见[配置](/docs/configuration)。

## providers [#providers]

| 命令                                                                                                                                                   | 作用                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| `providers list`                                                                                                                                       | 打印模型策略中的模型，以及每个 Provider 的 ID、名称、是否默认、是否禁用、协议、地址、是否设置了令牌和请求头的名字                 |
| `providers add 名称 --base-url URL [--protocol responses\|chat-completions\|anthropic-messages] [--api-key-env 变量] [--header 名称=值]… [--disabled]` | 添加 Provider 并打印它的 ID。协议默认为 `responses`。令牌从环境变量读取；`--header` 添加一个请求头。第一个添加的成为默认 Provider |
| `providers remove ID`                                                                                                                                  | 删除 Provider；删除的是默认 Provider 时，默认改为另一个                                                                           |
| `providers default ID [--model 模型]`                                                                                                                  | 设为默认 Provider，并可同时设置模型策略中的模型                                                                                   |

见 [Provider 与模型](/docs/providers-models)。

## mcp [#mcp]

| 命令                                                                       | 作用                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mcp list`                                                                 | 打印每个服务器的 ID、是否禁用、传输方式和目标、环境变量或请求头的名字（不打印值）；然后是启用的[已安装插件](#plugins)运行的服务器，每行以 `(plugin ID)` 结尾（它们用 `plugins` 修改，不在这里修改）；最后是已设置的凭据 |
| `mcp add ID --url URL [--oauth disabled\|optional\|required] [--disabled]` | 添加一个 Streamable HTTP 服务器；`--oauth` 设置它是否用 OAuth 登录（默认 `disabled`）                                                                                                                                   |
| `mcp add ID [--env 键=值]… [--disabled] -- 程序 [参数]…`                   | 添加一个 stdio 服务器，`--` 之后是程序和参数。启用的服务器添加后立即连接，并打印连接结果                                                                                                                                |
| `mcp remove ID`                                                            | 断开并删除服务器                                                                                                                                                                                                        |
| `mcp connect ID`                                                           | 连接服务器并打印它的状态和工具数量；没有达到 `ready` 时失败                                                                                                                                                             |
| `mcp login ID`                                                             | 用 OAuth 登录服务器：打印要在本机浏览器中打开的 URL，最多等待 5 分钟完成授权，然后打印服务器的状态                                                                                                                      |

服务器 ID 只能包含 1 到 128 个字母、数字、`-`、`_` 和 `.`。凭据需要编辑 `mcp.toml`，见 [MCP](/docs/mcp)。

## plugins [#plugins]

已安装插件是 Codex、Claude Code、Cursor 或 Agent Plugins 格式的包：安装并启用后，它们的 Skill、MCP 服务器和 hook 加入 Agent。插件来自用户添加的市场（marketplace），或来自一个目录；本项目格式的插件还可以运行代码（[编写插件](/docs/writing-plugins)）。模型能看到每个插件提供的内容；插件存放的位置和相关设置见[配置参考](/docs/config-reference#plugins)，它们能做什么、如何失败见[插件](/docs/plugins)。

| 命令                                                                           | 作用                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugins list [--available] [--json]`                                          | 列出已安装插件：ID、`enabled` 或 `disabled`、版本和来源。`--available` 改为在每个已添加的市场下列出它的插件（`installed, enabled`、`installed, disabled`、`not installed`、`not installable`），然后列出不由任何市场提供的已安装插件。`--json`：`{"installed": [...], "marketplaces": [...]}` |
| `plugins add 插件@市场`、`plugins add 插件 --marketplace 市场`                 | 安装市场中的插件并启用它（`[plugins."插件@市场"] enabled = true`）；打印它的根目录、读取时略过的内容、由命令转换成的 Skill，以及有多少 hook 等待信任（用 `/hooks` 或 `/plugins` 信任）。`--json` 打印完整结果                                                                                 |
| `plugins add 目录 [--marketplace 名字]`                                        | 安装目录中的插件，归入市场 `名字`（不指定时为 `local`）：它的 ID 是 `<清单中的名字>@local`                                                                                                                                                                                                    |
| `plugins remove ID [--purge-data]`                                             | 卸载插件并删除它的 `[plugins]` 条目；除非加 `--purge-data`，它的数据目录会保留                                                                                                                                                                                                                |
| `plugins enable ID`、`plugins disable ID`                                      | 启用或停用一个已安装插件；所属市场被关闭的插件不能启用                                                                                                                                                                                                                                        |
| `plugins update ID`                                                            | 从插件的市场（按市场当前的内容；git 市场先升级）或它原来的目录重新安装；内容变化的插件的 hook 需要重新信任                                                                                                                                                                                    |
| `plugins info ID [--json]`                                                     | 显示插件：状态、版本、格式、来源、它的 Skill、MCP 服务器和 hook、等待信任的 hook、它的代码的状态（等到命令自己的 Agent 启动了它，最多 30 秒；`code: running`、`blocked` 等；安全模式下或 `plugins` 行停用时立即显示 `stopped`）以及问题                                                       |
| `plugins retry ID`                                                             | 重新加载已安装插件，代码失败时重新启动它，并像 `info` 一样，在代码启动后显示该插件                                                                                                                                                                                                            |
| `plugins grant ID`                                                             | 授予插件代码其清单请求的权限（网络、工作区、环境变量）并打印它们；程序访客在获得授权前处于 `blocked` 状态；WebAssembly 访客不需要授权，对它执行此命令会失败                                                                                                                                   |
| `plugins settings ID [--get]`、`plugins settings ID --set JSON`                | 打印插件代码的设置（`[plugins."ID"].settings`）和它的 `configSchema`；`--set` 用一个按 schema 检查的 JSON 对象替换设置，`--set null` 删除它们；访客会带着新设置重新启动                                                                                                                       |
| `plugins new 名字 [--lang rust\|python] [--target process\|wasm] [--dir 目录]` | 在 `目录`（默认 `./名字`）中创建一个带代码的插件：`package/` 中的包（声明一个工具等贡献、权限和 `configSchema` 的清单），以及用 kardia-guest 或 pykardia 编写的访客源码；`--target wasm`（仅 Rust）写出构建 WebAssembly 模块的 crate（[编写插件](/docs/writing-plugins#start)）               |
| `plugins validate 目录 [--run] [--json]`                                       | 像安装那样检查 `目录` 中的插件，并像 Agent 运行它那样检查它的代码；`--run` 还会把它安装到临时主目录、授权并启动它的访客。有任何问题或访客没有运行时退出码为 1（[检查](/docs/writing-plugins#validate)）                                                                                       |
| `plugins dev 目录 [--grant]`                                                   | 把 `目录` 中的插件安装为 `名字@local` 并启用，询问是否授予它的代码请求的权限（`--grant` 直接授予），然后每当它的文件改动就重新安装，直到 Ctrl+C（[开发](/docs/writing-plugins#dev)）                                                                                                          |
| `plugins marketplace add 来源 [--ref 引用] [--sparse 路径]…`                   | 添加一个市场：本地目录（原地使用），或 git 仓库（`owner/repo[@ref]`、HTTPS 或 SSH URL、`file://`），克隆到数据目录的 `plugins/marketplaces/` 下；`--sparse` 只检出这些路径。再次添加相同来源不会有任何变化                                                                                    |
| `plugins marketplace list [--json]`                                            | 列出已添加的市场：名字、`local` 或 `git`、`on`、`off` 或 `unreadable`，以及根目录                                                                                                                                                                                                             |
| `plugins marketplace upgrade [名字]`                                           | 把 git 市场 `名字`（或所有已添加的 git 市场）更新到远程的最新提交；其中已安装的插件保持不变，直到执行 `plugins update`                                                                                                                                                                        |
| `plugins marketplace remove 名字`                                              | 删除市场（以及 git 市场的检出）；从它安装的插件仍然保留                                                                                                                                                                                                                                       |

插件 ID 是 `插件@市场`。命令行中 `--marketplace` 没有简写 `-m`：`-m` 是全局的 `--model`。

## roles [#roles]

| 命令              | 作用                                                                                                                                                       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `roles list`      | 按名字列出每个角色：它的来源和描述的第一行（不可派生时加 `(not spawnable)`），或 `unusable:` 及原因；读取和解析角色时的问题输出到标准错误                  |

## 哪些命令会启动 Agent [#agent-start]

`config`、`providers list`、`roles` 和不带 `--online` 的 `doctor` 只读写配置，不启动 Agent，可以在另一个 Agent 进程运行时使用。其他命令会启动 Agent，需要独占数据目录。

每个命令都会先读取配置，再安装崩溃处理和日志文件，然后才启动 Agent 或修改任何内容。会启动 Agent 的管理命令也会像每次启动一样在后台连接启用的 MCP 服务器。

除 `exec` 和终端界面外，按 Ctrl-C 会立即结束命令：操作系统释放数据目录锁，下次启动时清理 Agent 启动过的进程。
